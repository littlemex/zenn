## はじめに

2026年前半、フロンティア級のオープンな大規模言語モデル (LLM) の技術レポートが相次いで公開された。DeepSeek-V4、Kimi K2.5、GLM-5、Step-3.5、Qwen3.5、Nemotron 3、Gemma 4 などである (Mistral Large 3 は2025年末の公開で、アーキテクチャの詳細は非公開)。これらを横に並べると、設計の骨格が驚くほど似ている。ほぼ全てが疎な Mixture-of-Experts (MoE) を採用し、Attention を疎化ないし圧縮し、Multi-Token Prediction (MTP) や投機デコード (speculative decoding) を組み込み、学習の段階から低ビット量子化を前提にしている。

なぜこの4点に揃うのか。ここで先に一つの誤解を潰しておく。「独立した設計者が偶然に同じ最適解へ達した」という収斂進化的な物語は、この事例では正しくない。むしろ各社は互いのレポートを熱心に読み、技術を輸入し合っている。GLM-5 が採る DSA は名前の通り DeepSeek 発の Sparse Attention であり、Kimi の MLA は DeepSeek-V2 が生んだ手法である。観測された類似の少なくとも一部は、模倣と知識の水平伝播という社会的な過程で説明できてしまう。

だとすれば問いはこう鋭くなる。設計の選択肢は無数にあるのに、模倣する側にとってすら、なぜ他でもないこの4点が繰り返し「採る価値がある」と判断され続けるのか。本稿の主張はこうだ。伝播は収束の速度を与えたが、収束の方向を選別しているのはハードウェア、とりわけ HBM (High Bandwidth Memory) の帯域とインターコネクトの帯域である。4つのトレンドは「1トークンを生成するのに読むバイト数を削る」という一本の目標を、式の別々の因子として分担して攻めている。1つの制約に対する4つの分業なのだ。誰かが公開した工夫を他社が採り入れる伝播の連鎖があってなお、生き残る工夫がこの4点に偏るのは、ハードが淘汰圧をかけているからだ、というのが本稿の見立てである ([仮説])。

![2026年前半の主要モデルの技術採用マトリクス](/images/books/digging-into-machine-learning/llm2026-fig1-matrix.png)

上の図は主要オープンモデルがどの技術を採用しているかを一覧にしたものである。各セルは各モデルの技術レポートまたは config で確認した採否に基づく (根拠は巻末の対照表を参照)。列 (MoE、Attention 疎化・圧縮、MTP・投機、低ビット学習、1M 文脈、Thinking、マルチモーダル) を眺めると、緑 (採用) がほぼ全モデルの左4列に集中しているのが分かる。この左4列は、いずれも後述するハード制約 (自己回帰デコードの帯域律速) と密接に絡む「どう作るか」の軸である。一方で右3列 (1M 文脈、Thinking、マルチモーダル) は採否が割れるが、これらは「どの用途を狙うか」という製品側の設計判断に依るところが大きい。左4列とは軸の性質が異なるので、本稿ではこの右3列を主たる関心の対象からは外し、ハード制約と絡む左4列がなぜ揃うのかに焦点を絞る。まずこの「特定の4点への収束の事実」を出発点に置き、なぜそうなるのかをハードウェアから説明していく。

なお本稿の観察対象は「技術レポートや config でアーキテクチャを確認できる、フロンティア級のオープンウェイトモデル」に限る。クローズドな GPT・Claude・Gemini 本体は設計が非公開で、この収束の輪の中にいるかは直接には確かめられない (価格・速度・文脈長から同じ圧力下にあると推測はできるが、[仮説] の域を出ない)。また標本は中国系ラボに偏っており、この偏りが結論に与える影響は最後に反例として点検する。

本稿は連載の第1章にあたる。第1章では「大きな流れと意思決定」、すなわちなぜ各社が同じ設計に向かうのかを、ハード制約と1本の式で整理する。第2章では要素技術を重要な順 (MTP、Attention、MoE、低ビット) に、それぞれの数理まで掘り下げる。

本稿を通して、主張の根拠の強さを3段階で明示する。読者が「どこまでが証明された事実で、どこからが筆者の解釈か」を常に区別できるようにするためである。

## 4つの収束と、1つの問い

まず収束の中身を、一次ソースで確認できた具体的な数値とともに押さえる。以下はいずれも [報告] レベル、すなわち各モデルの技術レポートや config に原文で確認できた事実である。

MoE の主流化について。フロンティア級のオープンモデルは、2026年に入ってからほぼ全てが MoE になった。特徴的なのはアクティブ比 (総パラメータのうち1トークンあたり実際に活性化するパラメータの割合) が軒並み小さいことである。DeepSeek-V4-Pro は 1.6T のうち 49B しか使わず比率は約 3.1%、Kimi K2.5 は 1T のうち 32B で約 3.2%、GLM-5 は 744B のうち 40B で約 5.4% である。総パラメータは1兆を超えていくのに、1トークンあたりの計算量はその数%に抑えられている。

Attention の疎化・圧縮について。技術詳細が公開されているフロンティア級モデルに限れば、素朴な全結合 Attention をそのまま使うものはほぼ見当たらない。ただし解法は一つに収束しておらず、狙いが3つに分かれている。KV-Cache のバイト数を削る低ランク圧縮 (MLA など)、参照するトークン数を減らす疎選択・局所化 (DSA、SWA など)、状態サイズを固定して系列長依存そのものを消す線形化 (Mamba・DeltaNet など) の3系統である。ここで注意したいのは、MLA が削るのは KV のバイト数であって計算量は $O(L^2)$ のまま残る点である。系列長の2乗で効く計算量まで潰すのは疎選択・局所化・線形化の側で、両者は動機が別物である。DeepSeek 系は MLA からその後継の圧縮 Attention へ、GLM-5 は DeepSeek Sparse Attention (DSA)、Step-3.5 は Sliding Window Attention (SWA) と全結合の 3対1 ハイブリッド、Qwen3.5 は Gated DeltaNet の線形ハイブリッドと、同じ問題を各社が別の数学で攻めている。

MTP・投機デコードについて。まず投機デコード (speculative decoding) とは、小さく速いドラフトが先読みしたトークン列を本体が1回の順伝播でまとめて検証し、当たった分を一括で確定する高速化である。MTP (Multi-Token Prediction) はそのドラフタを、学習の段階から本体モデルに内蔵する手法だと考えればよい。Gemma 4 はドラフタ用のヘッドを持ち、DeepSeek-V4・GLM-5・Step-3.5 は複数トークンを同時に予測する MTP を組み込む。ただし後述の通り、Kimi のように MTP を採らない主要モデルも存在する。

低ビット学習について。後付けの量子化 (Post-Training Quantization, PTQ) から、学習の段階で低ビットを前提にする方向へ移った。Gemma 4 は int2/int4 混在の量子化を意識した学習 (Quantization-Aware Training, QAT)、DeepSeek-V4 は FP4 と FP8 の混在、Nemotron 3 の Super と Ultra は NVFP4 でのネイティブ事前学習を行う (Nano は BF16 基盤である)。

これらを踏まえると、問いは次のようになる。互いに技術を輸入し合える状況で、なぜ淘汰を生き延びる工夫が揃ってこの4点に偏るのか。以下ではまずハードウェアが「何を必要条件として押し付けているか」を見て、次にそれを1本の式に落とす。ここで一点、範囲を正直に断っておく。この後に立てる式は decode (1トークンずつ生成する局面) のコストを表すものである。MoE や低ビット化は学習コストの削減という、おそらくより強い別の圧力にも同時に押されている。4つの技術は「1つの動機の分業」というより、複数の圧力の合力がたまたま同じ方向を向いた結果に近い。本稿はそのうち decode 帯域という一つの軸を式として取り出す、という立場を取る。

## ハードウェアが必要条件を与える

### 自己回帰デコードは帯域の壁に張り付く

LLM の推論は2つの局面に分かれる。入力プロンプトをまとめて処理する prefill と、1トークンずつ順番に吐き出す decode である。ユーザーが体感する生成速度を支配するのは後者の decode であり、この局面がハードウェアのどこにぶつかっているかを理解することが全ての出発点になる。

ここでルーフラインモデル (roofline model) を使う。横軸に演算強度 (arithmetic intensity、メモリから1バイト読むごとに何回浮動小数点演算をするか)、縦軸に到達性能を取り、対数軸でプロットする図である。性能は「帯域 × 演算強度」で頭打ちになる斜めの直線 (帯域律速) と、チップのピーク演算性能で頭打ちになる水平線 (演算律速) の低い方で決まる。両者が交わる折れ点を ridge point と呼び、その値はピーク FLOPs を帯域で割ったものに等しい。

![ルーフラインモデルとridge pointの世代右移動](/images/books/digging-into-machine-learning/llm2026-fig4-roofline.png)

その前に、この後くり返し出てくる KV-Cache という言葉を定義しておく。Attention では過去の全トークンについて計算した Key と Value のベクトルを保存しておき (これを KV-Cache と呼ぶ)、新しいトークンを生成するたびに全て読み直して参照する。したがって KV-Cache のサイズは系列長に比例して膨れ、1M トークンの文脈では毎トークンの読み出し量が重み本体に匹敵しうるほどになる。decode で読み出すバイトは「重み本体」と「この KV-Cache」の2つだと押さえておけばよい。

decode の演算強度を自分で見積もってみる。batch サイズ1で1トークンを生成するとき、必要な演算量はおよそパラメータ数 $N$ の2倍 ($2N$ FLOPs) であり、読み出すバイト数はパラメータ数掛けるパラメータあたりのバイト数 ($N \times \text{bytes/param}$) である (ここでは支配項の重みだけを見て KV を一旦省く)。演算強度はこの比だから $2 / (\text{bytes/param})$ になる。重みを BF16 (2バイト) で持てば演算強度は1、FP8 (1バイト) なら2、FP4 (0.5バイト) でも4にしかならない。この $1/2/4$ という値は筆者による単純な導出である。裏付けとして、NVIDIA 公式の推論最適化ブログも decode を「データの転送速度がレイテンシを支配し、演算速度ではない」行列ベクトル演算だと定性的に明記している ([報告] なのはこの定性的記述の方で、$1/2/4$ の数値自体は自己導出)。

一方で各世代の ridge point は、その世代のデータシートが主打ちにする最低ビットのネイティブ精度 (いわばカタログ表紙の精度) で計算すると、A100 (BF16) で 153、H100 (FP8 dense) で 591、B200・GB200 (FP4 ネイティブ dense) で 1250 である (いずれも NVIDIA 公式データシートの dense ピーク FLOPs を帯域で割った値。H100 のカタログ値 1,979 TFLOPS は 2:4 構造的疎性込みではなく FP8 dense の値であり、疎性込みのマーケティング値とは区別している)。decode の演算強度 $1$〜$4$ は、精度を揃えて比べても各世代の ridge point より2桁前後 (H100・B200 世代では約2.5桁) 左にある。つまり decode はルーフラインの左端、帯域律速の領域に完全に張り付いている。演算ユニットがいくら速くなっても、HBM から重みと KV を読み出す速度が生成レイテンシを決めてしまう。

上の図で、斜めの直線が帯域律速、水平線が演算律速、両者の折れ点が ridge point である。decode の演算強度は図の左端に位置し、3世代分の ridge point が右へ動いていく様子も描いてある (この右移動は次節で扱う)。

batch を積めば演算強度は上がる (batch $B$ で $2B/(\text{bytes/param})$)。ただし精度を揃えて比べる必要がある。FP8 の重みで batch を128積むと演算強度は約256だが、それでも同じ FP8 で計算した H100 の ridge point 591 には届かない。しかも実際には KV-Cache の読み出しがここに乗る。KV はリクエストごとに固有でバッチ間で共有できないため、batch を積んでも演算強度が上がりにくく、長文脈ではむしろ KV 項が支配的になる。サービング側で batch をまとめても、decode が演算律速に移るのは容易ではないという数値的事実がここにある。

### ridge point は世代ごとに右へ動く

さらに厄介なのは、この壁が世代を追うごとに右へ動くことである。ridge point は $153 \to 591 \to 1250$ と、低ビットのネイティブ精度が追加される世代ごとに右へ動く。ただし単調ではない。H200 は H100 と同じダイ (FP8 で 1,979 TFLOPS) のまま帯域だけ 3.35 から 4.8 TB/s へ増強したため、ridge point はむしろ 591 から 412 へ左に戻る。帯域だけを増やせば壁は左に戻る、という事実は「帯域増強に価値がある」という本節の主張をむしろ補強する。主因は「FLOPs が増えたから」だけではなく、毎世代より低ビットのネイティブ精度が追加され、その精度でのピーク FLOPs が跳ね上がる一方、帯域は着実だが緩やかにしか伸びないことにある。

これは孤立した観察ではない。arXiv:2403.14123 "AI and Memory Wall" は、ピーク FLOPs が2年で約3.0倍になるのに対し、DRAM 帯域は1.6倍、インターコネクト帯域は1.4倍にしか伸びないことを指摘した。ここで注意が要る。この経験則は見出し精度 (世代ごとに下がる) での FLOPs 成長を含むが、以下の検算は精度を固定 (BF16) して行っている。固定精度の per-GPU 実値では、A100 から H100 で FLOPs 成長を帯域成長で割った比は約1.93倍 (約2.5年)、A100 から GB200 で約2.04倍 (約4年) である ([報告])。方向としては論文と一致する (FLOPs が帯域より速く伸びる) が、固定精度で測ると乖離のペースは論文の見積もりより緩やかで、期間が延びても比が2倍前後に留まる。低ビット精度の追加まで数えれば乖離はもっと大きい、と理解するのが正確である。

意味するところはこうだ。演算バウンドになるための最小バッチや最小系列長は、世代ごとに大きくなっていく。裏を返せば「1トークンあたりに読むバイト数」を削る技術の価値は、世代を追うごとに上がり続ける。2026年のモデル設計が揃って帯域削減に向かうのは、この構造的な追い風が背景にある ([仮説] としての因果、ただし ridge point の右移動そのものは [報告])。

### HBM 容量とインターコネクトが並列設計を縛る

帯域だけでなく、HBM の容量とネットワークの帯域も設計を直接縛る。

HBM 容量は、GPU 1基あたり A100 で 80GB、H100 で 80GB、H200 で 141GB、B200 で 180GB、GB200 で 186GB である ([報告]、公式データシート)。総パラメータを常駐させられる上限はここで決まる。1兆パラメータを BF16 で持てば2TBを要し、1基には到底載らない。ここで強調しておきたいのは、MoE はこの容量の壁に対しては味方ではなく、むしろ壁を高くする側だという点である。MoE は総パラメータをあえて増やす設計なので、常駐量の上限を圧迫する。その帳尻を低ビット化と多ノード分散で払う。MoE が救うのは容量ではなく、次に述べる帯域と演算のコスト (1トークンで活性化するパラメータ) の方であり、この容量とコストの分離こそが MoE の本質になる。

ネットワークについては、MoE の宿命である all-to-all 通信が律速点になる。エキスパートが複数ノードに分散すると、各トークンを担当エキスパートのあるノードへ送り、結果を集める全対全通信が発生する。DeepSeek-V3 の技術レポート (arXiv:2412.19437) の 3.2.2 節は、この制約を直接述べている。

> NVLink offers a bandwidth of 160 GB/s, roughly 3.2 times that of IB (50 GB/s). To effectively leverage the different bandwidths of IB and NVLink, we limit each token to be dispatched to at most 4 nodes, thereby reducing IB traffic.

ノード内の NVLink がノード間の InfiniBand (IB) の約3.2倍速いという帯域差が、「1トークンを最大4ノードまでにしか送らない」という設計判断を直接生んでいる ([報告])。インターコネクトの帯域が MoE のルーティング設計をそのまま律速するという、一次証拠である。ここで引用文の 160 GB/s は輸出規制仕様の H800 における削減値であって、通常品 H100 の NVLink 900 GB/s とは別物である点に注意したい。この節の後半で挙げる A100 の 600GB/s、H100・H200 の 900GB/s、Blackwell 世代の 1.8TB/s は通常品の per-GPU 帯域であり、規制品ではさらに絞られる。GB200 NVL72 では NVLink ドメインが72基まで拡大し、この「4ノード制約」の前提そのものが世代とともに動いている点も付け加えておく。それでもノード内とノード間の帯域差が MoE の並列度を規定する構図は変わらない。

なお、この dispatch 制限は「規制で削減された帯域に合わせた設計判断」の一次証拠ではある。ただしそれは通信スケジューリングの話であり、後述する MLA など Attention アーキの採用理由が規制にあるという証言とは別物だという点は、次節で切り分ける。

### 低ビットネイティブ学習はハードが可能にした

学習の段階から FP4 を使う流れも、ハードウェアの機能が前提になっている。Blackwell の第2世代 Transformer Engine が microscaling formats (小さなブロックごとにスケールを持つ低ビット形式) をネイティブに扱えるようになったことが起点である ([報告]、Blackwell データシート)。

興味深いのは DeepSeek-V3 レポートの記述である。彼らは自分たちのソフトウェア的な細粒度 FP8 量子化を「microscaling formats の発想と高度に一致する」と位置づけた。その上で、Blackwell が同形式をネイティブサポートすると発表したことに触れ、「我々の設計が参考になることを願う」と結んでいる。ソフトで先行した細粒度量子化が、次世代ハードのネイティブ機能へ連続していく様子が読み取れる。

### 輸出規制との関係は状況証拠にとどめる

ここで一つ、慎重に扱うべき論点がある。中国系ラボ (DeepSeek、Kimi、GLM) が KV 圧縮や線形 Attention に積極的なのは、輸出規制で帯域の制限された GPU (H800 など) しか使えないためだ、という因果がしばしば語られる。

[仮説] としては魅力的だが、直接の一次証言は論文本文に存在しない。DeepSeek-V3 は H800 の NVLink・IB 帯域の低さへの対処として DualPipe や all-to-all カーネルの最適化を挙げているが、これは通信スケジューリングの話であって MLA 採用の理由としては書かれていない。MLA や線形 Attention の主目的は、論文上はあくまで「推論・生成時の KV 削減によるスループットとバッチの向上」である。実際、DeepSeek-V2 (arXiv:2405.04434) は MLA で「KV cache を 93.3% 削減し、最大生成スループットを 5.76倍にした」と報告する。

したがって本稿では、輸出規制とアーキ革新の時期的一致は状況証拠であって因果の直接証言ではない、という立場を明確にする。ハード選択の背景として輸出規制を挙げることはできるが、「規制があったから MLA を採った」と断定する一次ソースはない。

## 背骨の式: 1トークンの時間を分解する

ここまでのハード制約を1本の式にまとめると、4つのトレンドが同じ式の別々の因子を叩いていることが一目で分かる。decode で1トークンを生成するのにかかる時間を、支配項だけ取り出して近似すると次のようになる。

$$
\text{1トークンの時間} \approx \frac{P_{\text{active}} \cdot b_{\text{weight}} + L_{\text{eff}} \cdot d_{\text{KV}} \cdot b_{\text{KV}}}{\text{BW} \cdot \tau}
$$

分子の第1項が重みの読み出しバイト数、第2項が KV-Cache の読み出しバイト数である。各変数と、それを叩くトレンドを並べると次のようになる。

- $P_{\text{active}}$: アクティブパラメータ数 (1トークンで実際に活性化する重み) → **MoE** が下げる
- $b_{\text{weight}}, b_{\text{KV}}$: 重み・KV の1要素あたりバイト数 → **低ビット学習** が下げる
- $L_{\text{eff}} \cdot d_{\text{KV}}$: 実効系列長 × 1トークンあたり KV 要素数 → **Attention 疎化・圧縮** が下げる
- $\tau$: 投機デコードの期待受理長 (1回の順伝播で平均何トークン確定できるか) → **MTP** が大きくする

$L_{\text{eff}}$ は Attention が実際に参照する実効的な系列長で、SWA なら窓幅、疎選択なら選ばれたトークン数に縮む。$d_{\text{KV}}$ は「全層・全 KV ヘッド合計で、K と V の両方を含む1トークンあたりの要素数」であり、MLA のような低ランク圧縮はここを縮める。分母の BW は HBM 帯域である。

この式には2つの但し書きが要る。第一に、これは batch が小さく decode が帯域律速に留まる範囲での近似である。大バッチでは重み項がバッチで償却されて $P_{\text{active}} b_{\text{weight}} / B$ に薄まる一方、KV 項はリクエストごとに固有で償却されないため、大バッチでは KV 項が相対的に支配的になる。第二に、複数 GPU 推論では all-to-all や allreduce の通信時間が別項として効くが、ここでは支配項を取り出すために省いている。前節で「インターコネクトが MoE の並列度を縛る」と述べた通り、通信は実際には無視できない第3の項である。前節までで見た通り、decode が帯域律速である以上、単一 GPU の生成レイテンシは「読むバイト数 ÷ 帯域」でよく近似できる。

![背骨の式: 4トレンドは同じ式の別々の因子を叩く](/images/books/digging-into-machine-learning/llm2026-fig3-backbone.png)

この式に4つのトレンドを重ねると、役割分担が見える。MoE は $P_{\text{active}}$ を下げる。低ビット学習は $b_{\text{weight}}$ と $b_{\text{KV}}$ を下げる。Attention の疎化・圧縮は $L_{\text{eff}} \cdot d_{\text{KV}}$ を下げる。MTP・投機デコードは $\tau$ で割ることで読み出し回数そのものを減らす。4つは互いに独立な因子に効くため、掛け算で効果が積み上がる。

各因子の代表的な削減オーダーを掛け合わせて概念的に試算すると、削減の積が見えてくる。

![バイト/トークン ウォーターフォール](/images/books/digging-into-machine-learning/llm2026-fig5-waterfall.png)

dense な1兆パラメータモデルを FP16 で毎トークン読む状態を基準の 1.0 とし、各段を「係数 × 前段 = 結果」で積み上げる。

- 基準 (dense 1T・FP16・KV 込み): 1.0
- MoE 化 (アクティブ比 1/20): $\times 0.05 \to 0.05$
- 低ビット化 (16ビットを大半 FP4・一部 FP8 に、平均約4.5ビット、$\times 0.28$): $\to 0.014$
- KV 圧縮 (総バイトが $\times 0.55$): $\to 0.0077$
- MTP (期待受理長 $\tau \approx 2.77$ で割る): $\to 0.00278$

積として約 360分の1、およそ2.5桁の削減になる。図5の各段がこの4ステップに対応する。

:::message
この試算は各技術の代表的なオーダーを掛け合わせた概念的なものであり、特定モデルの実測ではない。2つの単純化を含む点に注意してほしい。第一に、背骨の式の分子は「重みバイト + KV バイト」の和であって、本来は重み側 (MoE・低ビット) と KV 側 (KV 圧縮) を別レーンで計算して足すべきものを、ここでは総量への乗法因子として直列に掛けている。KV 圧縮の $\times 0.55$ は「MLA 級の KV 削減を行った結果、重みも含む総バイトが約 0.55 倍になる」という、ある重み対 KV 比率を仮定した値であり、後述の MLA 単体の 93.3%削減とは基準が異なる。第二に、MTP の $\div \tau$ はドラフトの追加読み出しを無視した上界である。あくまで「4因子が独立に効いて積で効く」ことを示すための目安として読んでほしい。
:::

ここで一点だけ注意を促したい。MoE を「メモリ節約技術」と誤解しやすいが、正確ではない。MoE が下げるのは帯域と演算コスト ($P_{\text{active}}$) であって、総パラメータと all-to-all 通信量はむしろ増える。図書館に喩えると分かりやすい。総パラメータは蔵書数、アクティブパラメータは1つの質問に答えるために机に広げる本の冊数である。蔵書は増やしたいが、毎回全冊を机に運ぶ必要はない。MoE は「蔵書を増やしながら、机に運ぶ冊数を減らす」設計であって、書庫 (メモリ) を小さくする技術ではない。MoE の本質は「メモリの節約」ではなく「知識の容量 (総param) と、1トークンあたりのコスト (active param) の分離」である。この分離こそが次節のテーマになる。

## 知識容量は総paramで、演算コストはactive paramで

MoE がもたらした分離を、実データで見る。総パラメータ (横軸) とアクティブパラメータ (縦軸) を両対数でプロットしたのが次の散布図である。

![総params vs activeparams の両対数散布図](/images/books/digging-into-machine-learning/llm2026-fig2-scatter.png)

2023年から2024年の旧世代 (灰色) は、アクティブ比がおおむね10%から28%の帯にいた。Mixtral 8x7B は 47B 中 13B で約28%、Grok-1 は 314B 中 86B で約27%である (これらの旧世代の値は各モデルの公開仕様に基づく概算)。ところが2026年の新世代 (緑) は、総パラメータが右へ伸びる一方で、点は下の 3%から7% の帯へ移動している。とりわけ DeepSeek 系の系譜が象徴的で、V2 の 8.9% から V3 の 5.5%、V4-Pro の 3.1% へと、世代を追うごとにアクティブ比を下げてきた ([報告])。

なぜこの方向へ動くのか。背景には、パラメータが蓄えられる知識の量に関する経験則がある。arXiv:2404.05405 "Physics of Language Models" は、合成タスクの観測として1パラメータあたり約2ビットの知識を蓄えられると報告した ([報告]、ただし合成的な事実想起タスクでの観測)。ここで蓄えられる「知識」は事実想起の類であって、推論や合成の能力が総パラメータに比例するかは別問題である点は注意が要る (それらはむしろ実行時の計算深度・幅、すなわちアクティブパラメータに依存すると考えられるが、この関係は未解明である。[仮説])。それでも、事実想起型の知識の容量が総パラメータにおおむね比例し、演算コストがアクティブパラメータにおおむね比例するなら、両者を分離して「容量は総paramで稼ぎ、コストはactive paramで抑える」設計が合理的になる。散布図の右下への移動は、この分離戦略への各社の収束を示している ([仮説] としての解釈、点の配置そのものは [報告])。

ただし収束は「一点への収束」ではなく「帯への収束」である。同じ新世代でも Nemotron 3 Ultra は 550B 中 55B でアクティブ比 10% と、あえて厚くアクティブを取る設計を選んでいる。「3%から7%への収束」は定数ではなく幅のある帯であり、設計思想によってその中のどこに位置するかは分かれる (Nemotron の10%はこの帯の外にある外れ値である)。

## 意思決定の非対称性: 品質はどこで守られるのか

ここからが本稿の主題である。4つのトレンドは同じ式を削るという意味では横並びだが、「削った結果、出力の品質がなぜ保たれるのか」という保証のあり方で見ると、はっきり非対称になっている。

![品質はどこで守られるか: 保証レベルの対照表](/images/books/digging-into-machine-learning/llm2026-fig6-guarantee.png)

投機デコード (MTP) だけが、出力品質を数学的な定理で守っている。投機デコードは小さなドラフトモデルが先読みしたトークンを、本体モデルが検証して受理・棄却する。ここで使われる修正版の棄却サンプリング (modified rejection sampling) は、受理・棄却の後の出力分布が本体モデル単独の分布と厳密に一致することが証明されている (arXiv:2211.17192、arXiv:2302.01318)。これは [定理] レベルの保証である。

ただし、この定理が守るのは「同一の本体モデルを前提にした、推論時の検証手続きの分布等価性」だけである点は正確に押さえたい。守らないものが2つある。第一に、MTP を学習に組み込むこと自体は本体の重みを変えるので、MTP 込みで学習したモデルは MTP なしのモデルとは別の分布を持つ。定理は「そのモデルを速く走らせても分布を変えない」とは言うが「学習に MTP を足しても品質が同じ」とは言わない。第二に、守られるのは出力分布であって、スループットではない。検証パスには無駄な計算が伴い、GPU が高稼働の大バッチ環境では投機デコードが総スループットをむしろ下げることもある。後で見る Kimi の不採用は、この計算資源のトレードオフで説明できる可能性が高い。要するに「品質 (出力分布) に関するトレードオフがない稀有な技術」であって、「あらゆるトレードオフがない」わけではない。数式による詳細は第2章に譲る。

残りの3つは事情が違う。これらは「推論時のアルゴリズムで正しさを保証する」のではなく、「学習の段階で制約を焼き込むことで品質を保つ」型である。以下は各技術の位置づけの要約に留め、式と補題は第2章で技術ごとに検証する。

量子化 (低ビット学習) について。確率的丸めの不偏性という部分的な支柱はあるが、QAT が int4 でも劣化しない解を見つける仕組みは経験則であり、Straight-Through Estimator の収束理論も限定的である。どの層を FP4 に振りどの層を FP8 に残すかは、感度の高い層に多くのビットを割く配分問題 (通信理論の注水定理と同型) であって、定理ではなく設計者の選択である。

Attention の疎化・圧縮について。「Attention の質量が少数のトークンに集中する」「実効ランクが低い」といった性質は、H2O (arXiv:2306.14048) や Quest (arXiv:2406.10774) による経験的観測であって、事前に保証された性質ではない。SWA と全結合を 3対1 で混ぜる、圧縮率を128倍にするといった具体値も、アブレーションで良かった設定を採っているにすぎない。

MoE について。負荷分散を最適輸送や割当問題として定式化することはできるが、品質を守る強い定理はほとんどない。アクティブ比が 3%から7% に収束するのも、HBM 容量と all-to-all 帯域の交点というコストモデル上の選択であって定理ではない ([仮説]。「4ノード制限」の一次証拠が示すのは all-to-all がルーティングを縛ることまでで、3〜7%という帯を導く証言ではない)。

この非対称性を一言でまとめる。2026年のアーキテクチャで「正しさが定理で守られている」のは投機デコードだけ (それも推論時の分布等価に限る) であり、他の3つは正しさを学習時の共設計と経験則に委ねている。ただしこれは白黒の二分法ではなくグラデーションである。量子化には不偏性や誤差上界という部分定理があり、投機デコードにも学習側では保証が及ばない。「定理が全面的に守る技術」から「経験則に委ねる技術」への濃淡がある、と捉えるのが正確である。それでも重心の偏りははっきりしており、これが本連載を貫く視点になる。

## 収束は普遍ではない: 反例を見ておく

収束の物語は強力だが、鵜呑みにすると事実を見誤る。ここで反例を3つ挙げ、「全社が同じ設計をしているわけではない」ことを確認しておく。いずれも [報告] レベルの事実である。

第一に、MTP は全社のデフォルトではない。Moonshot の Kimi は、K2.5 で config の `num_nextn_predict_layers` を0に設定して MTP を明示的に無効化している。続く K3 は技術レポート・重みとも本稿執筆時点で未公開で、公表情報に MTP への言及がない (K2.5 からの継承の有無は不明)。確定した反例は K2.5 だが、少なくとも「MTP がデフォルト装備化した」という潮流に例外があること、全社が同一の設計に収束したわけではないことの証拠にはなる。定理型で品質を無条件に守れる技術ですら全社が採るわけではない、という点が示唆に富む (前節で述べたスループットのトレードオフが理由の候補である。[仮説])。

第二に、アクティブ比は設計思想で割れる。前述の通り Nemotron 3 Ultra は10%と厚く、DeepSeek-V4 は3.1%と薄い。同じ「MoE 化」というトレンドの中でも、どれだけアクティブを絞るかは3倍以上の開きがある。

第三に、Attention は最も分岐している主戦場である。MLA (Kimi K2.5)、圧縮 Attention の CSA・HCA (DeepSeek-V4)、DSA と IndexShare (GLM-5.2)、SWA と全結合のハイブリッド (Step-3.5、Gemma 4)、Gated DeltaNet の線形 Attention (Qwen3.5)、Kimi Delta Attention と Gated MLA のハイブリッド (Kimi K3)、Mamba-2 と GQA のハイブリッド (Nemotron 3)。同じ「KV 帯域と $O(L^2)$ を潰す」という問題を、各社がまったく別の数学で攻めている。収束と発散が同居しているのがこの領域である。低ビットのフォーマットも同様で、FP4 と FP8 の混在、MXFP4 と MXFP8、NVFP4、INT4 QAT と割れており、ハードが FP4 ネイティブを可能にしたものの、標準フォーマットはまだ一つに定まっていない。

つまり「同じ式を削る」という大目標では収束しているが、「その式のどの因子を、どの数学で、どれだけ削るか」では豊かに発散している。この収束と発散の同居こそ、2026年のモデル設計を読む上で最も面白い構図である。

## まとめ

第1章の要点を整理する。

第一に、2026年前半の主要オープンモデルは、技術を互いに輸入し合える環境にありながら、MoE、Attention 疎化・圧縮、MTP・投機デコード、低ビット学習という4点に偏って収束した。伝播が収束の速度を与え、ハード制約がその方向を選別している。これは4つの流派ではなく、1つのハード制約 (と、同方向に働く学習コスト圧) に対する4つの分業である。

第二に、その制約の正体は、自己回帰デコードが帯域律速に張り付いているという事実である。decode の演算強度は 1 から 4 FLOP/Byte しかなく、精度を揃えても各世代の ridge point より2桁前後 (H100・B200 世代では約2.5桁) 左にある。しかも ridge point は世代ごとに右へ動き (帯域だけ増えた H200 では左に戻る)、「読むバイト数を削る」技術の価値は上がり続ける。HBM 容量は総paramの常駐上限を、インターコネクト帯域は MoE の並列度を直接縛る。

第三に、この制約は「1トークンの時間 ≈ (アクティブ重みバイト + KV バイト) ÷ (帯域 × 期待受理長)」という1本の式 (小バッチ・decode 限定の近似) に落ち、MoE は $P_{\text{active}}$、低ビットは $b_{\text{weight}}, b_{\text{KV}}$、Attention 疎化は $L_{\text{eff}} \cdot d_{\text{KV}}$、MTP は $\tau$ という別々の因子を叩く。

第四に、品質保証の型は非対称である。投機デコードだけが出力分布の厳密保存という定理で守られ (それも推論時の分布等価に限る)、残りの3つは学習時の共設計と経験則に品質を委ねている。ただし濃淡のあるグラデーションである。

第五に、収束は普遍ではない。MTP を避ける Kimi、アクティブ比を厚く取る Nemotron、そして最も分岐している Attention 設計が、「全社同一」という単純な物語を退ける。揃うのはハード制約と密接に絡む4点に限られ、どの用途を狙うか (1M 文脈・Thinking・マルチモーダル) といった製品側の設計判断は各社で割れる。

次章 (第2章) では、この4つの要素技術を重要な順に掘り下げる。まず唯一の定理型であり生成の環を閉じる MTP・投機デコード、次に1M文脈で主戦場となる Attention の疎化・圧縮、続いて容量とコストを分離する MoE、最後に学習時に制約を焼き込む低ビットネイティブ化を扱う。それぞれについて、なぜそうするのかを数理まで踏み込んで整理していく。
