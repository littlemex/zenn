## はじめに

この本は AIM345 という 60 分のハンズオンワークショップの手順書を、改善前 (Original) と改善後 (Modified) の両方の版でそのまま収めたものである。ワークショップの題材は分離推論、つまり LLM 推論の prefill (入力を読んで KV キャッシュを作る工程) と decode (KV キャッシュを使って 1 トークンずつ生成する工程) を別々のエンジンに分ける構成である。参加者は Amazon EKS 上に用意された統合構成 (1 つのエンジンが prefill と decode を両方担当する) と分離構成 (prefill 専用エンジンと decode 専用エンジンに分け、間を KV ハンドオフでつなぐ) の 2 つのスタックを同じ GPU 予算で実際に測り、どちらを残すかを自分の測定結果から決める。

## このワークショップで何をするか

参加者はまず CloudShell から EKS クラスタに接続し、両方のスタックが同じモデル・同じ GPU 枚数・同じキャッシュとルーティング設定で動いていることを確認する。続いてキャッシュが効くエージェント的な短い呼び出し (shape A) と、長い文脈を使う呼び出し (shape B) の 2 種類のトラフィックを両方のスタックに流し、TTFT (最初の 1 文字が出るまでの時間) と TPOT (1 トークンあたりの生成時間) を測る。負荷を段階的に上げていき、どちらのスタックが「TTFT 2000 ms 未満かつ TPOT 100 ms/トークン未満を 90 パーセント以上満たす」という共通の目標 (SLO) を、より高い到着率まで守れるかを記録する。最後にその記録から、どちらのスタックを残すかを決める。

## Original と Modified の違いの要約

Original は、1 つの約束 (TTFT と TPOT の上限の組) を 1 回測って、勝った方をそのまま結論にする構成だった。なぜ勝ったのか、約束を変えたら答えが変わるのか、1 回の測定を信じてよいのかは扱っていなかった。

Modified は同じ測定結果を土台にしながら、次の 3 点を追加している。1 つ目は、保存済みの測定ファイルを測り直さずに別の約束 (TTFT 1000 から 5000 ms、TPOT 10 から 100 ms/トークンの組み合わせ) で採点し直す `rescore.py` という道具である。2 つ目は、統合と分離それぞれが最初に目標を守れなくなる速さ (この本では「壁」と呼ぶ) を、どちらの上限で壊れたかまで含めて図にしたことである。3 つ目は、1 回の測定だけでは分離が勝つように見えるマスが地図上にできても、同じ負荷を乱数の種を変えて 3 回測り直すとそのマスが消えることを、参加者自身の手順の中で確かめさせることである。この深掘りは 60 分という時間の枠に収まらないため、Modified では新しい Optional ページ (065) に移してあり、本線の 040 と 050 は元の分量に近い長さに戻してある。

数値や結論の違いは本線の各章で測定結果として読めるが、2 つの版を通して読んだときにどこが変わったかをまとめて確認したい場合は、最後の「Original と Modified の差分整理」の章を参照する。

## どちらから読むか

実測の手順と結論を素直に追いたい場合は Original から読むとよい。分離推論を測るときに「1 回勝った」をどう疑うかという考え方に興味がある場合は、先に Modified を読み、気になった章だけ Original と読み比べる進め方もできる。どちらの版も単独で最後まで読めるように章を分けてあるので、途中で行き来しても迷わない構成にしている。

## まとめ

この本には Original の 9 章、Modified の 10 章 (Optional の 065 を含む)、そして両版の差分を整理する章が 1 つ入っている。章タイトルの先頭には必ず「Original:」または「Modified:」を付けてあるので、今どちらの版を読んでいるかはタイトルだけで判別できる。次の章から Original の「000 はじめに」を読み進める。
