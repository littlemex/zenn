## はじめに

[XTTS v2](https://huggingface.co/coqui/XTTS-v2) は、Coqui が公開している音声合成（TTS、文字から音声を作ること）のモデルです。AWS Neuron は、AWS の Trainium と Inferentia のチップでモデルを動かすためのソフトウェアで、NeuronCore はチップの中で計算をする単位です。この記事では、XTTS v2 の一部を AWS Neuron でコンパイルし、インストールした Coqui TTS のソースファイルを編集せずに推論します。あわせて、nn.Module、trace、固定の形といった初学者向けの知識を、図でまとめます。どれも、続編の「[NxD Inference にカスタムモデルを統合するための事前知識](https://zenn.dev/tosshi/articles/81840c7c10dddd)」と「[XTTS v2 を NxD Inference で動かす](https://zenn.dev/tosshi/articles/ffc359901ea1cc)」を読むときに前提になる知識です。

## XTTS v2 の全体像

![XTTS v2 は参照音声から話者の特徴を取り出し、GPT の generate() で音声コードを 1 つずつ作り、GPT の forward() でまとめて latents に変え、HifiDecoder が latents と話者の埋め込みから 24 kHz の波形を作る。Neuron に載せるのは forward() だけ](/images/53cc505a8d85e2-xtts-pipeline.png)

XTTS v2 は、主に GPT と HifiDecoder という 2 つの部品を順につないだ音声合成のモデルです。前処理は、参照音声から、GPT に渡す話者の特徴と、HifiDecoder に渡す話者の埋め込みを取り出します。GPT は、話者の特徴と文のトークンから、音声コード（音声を表す番号の列）と latents（音声の特徴を表す数値の列）を作ります。HifiDecoder は、latents と話者の埋め込みから音声の波形を作ります。

![generate() が 1 ステップに 1 つずつ音声コードを足し、forward() が全部の音声コードを一度に latents に変え、HifiDecoder が波形にする](/images/53cc505a8d85e2-xtts-flow.gif)

GPT の仕事は 2 段に分かれます。`generate()` は、文のトークンと話者の特徴から音声コードを 1 つずつ作り、終わりの印が出るまで繰り返します。続けて XTTS v2 は、同じ文と話者の特徴に、できた音声コードを加えて `forward()` を `return_latent=True` で呼びます。この呼び出しは、コード 1 つにつき 1024 個の数値の latents を返します。

| 部品 | 大きさ | すること | この記事で動かす場所 | 実装の場所 |
| --- | --- | --- | --- | --- |
| 前処理 | ― | 参照音声から話者の特徴と埋め込みを作る | CPU | [get_conditioning_latents()](https://github.com/coqui-ai/TTS/blob/eef419b37393b11cc741662d041d8d793e011f2d/TTS/tts/models/xtts.py#L326-L380) |
| GPT の generate() | GPT 全体で約 396M パラメータ | 音声コードを 1 つずつ作る | CPU | [xtts.py の呼び出し](https://github.com/coqui-ai/TTS/blob/eef419b37393b11cc741662d041d8d793e011f2d/TTS/tts/models/xtts.py#L541) |
| GPT の forward(return_latent=True) | 同上 | 音声コードを latents に変える | NeuronCore | [xtts.py の呼び出し](https://github.com/coqui-ai/TTS/blob/eef419b37393b11cc741662d041d8d793e011f2d/TTS/tts/models/xtts.py#L561-L569)、[GPT クラス](https://github.com/coqui-ai/TTS/blob/eef419b37393b11cc741662d041d8d793e011f2d/TTS/tts/layers/xtts/gpt.py#L88) |
| HifiDecoder | 約 12M パラメータ | latents と話者の埋め込みから 24 kHz の波形を作る | CPU | [HifiDecoder クラス](https://github.com/coqui-ai/TTS/blob/eef419b37393b11cc741662d041d8d793e011f2d/TTS/tts/layers/xtts/hifigan_decoder.py#L615) |

HifiDecoder を CPU に残したのは、中で使う [`interpolate(mode="linear")`](https://github.com/coqui-ai/TTS/blob/eef419b37393b11cc741662d041d8d793e011f2d/TTS/tts/layers/xtts/hifigan_decoder.py#L688-L699) がこの検証ではコンパイルを通らなかったからです。`generate()` を CPU に残したのは、終わりの印が出るまで長さが伸びる処理で、形を固める trace と合わないからです。呼び出しの入口は [full_inference()](https://github.com/coqui-ai/TTS/blob/eef419b37393b11cc741662d041d8d793e011f2d/TTS/tts/models/xtts.py#L421-L500) で、前処理の結果を [inference()](https://github.com/coqui-ai/TTS/blob/eef419b37393b11cc741662d041d8d793e011f2d/TTS/tts/models/xtts.py#L503-L583) に渡し、`inference()` が GIF の順に部品を呼びます。

## nn.Module: 重みと forward() を持つ部品

![model は Xtts という nn.Module で、その中に model.gpt と model.hifigan_decoder という nn.Module が入っている。model.gpt(...) と呼ぶと model.gpt.forward(...) が動く](/images/53cc505a8d85e2-nn-module.png)

PyTorch では、モデルの部品を nn.Module というクラスを継承して作ります。nn.Module を継承した部品は、入力から出力を計算する処理を `forward()` に書き、重みや子の部品をまとめて持ちます。`model.gpt(...)` のように部品を関数のように呼ぶと、PyTorch がその部品の `forward` という名前を探して呼びます。そのため、部品の `forward` を置き直すと、クラスのコードを変えずに呼び出しの行き先を変えられます。nn.Module の中には別の nn.Module を入れられるので、XTTS v2 全体の `model` の中に、`model.gpt` と `model.hifigan_decoder` が入っています。この記事でコンパイルするのは `model.gpt` という部品で、XTTS v2 全体ではありません。

## trace: 一度流して形ごと固める

![nn.Module と例の入力を torch_neuronx.trace() に渡すと、実際に動いた計算が記録され、neuronx-cc でコンパイルされる。できたモデルは同じ形の入力だけを受け付ける](/images/53cc505a8d85e2-trace.png)

[`torch_neuronx.trace()`](https://awsdocs-neuron.readthedocs-hosted.com/en/latest/frameworks/torch/torch-neuronx/api-reference-guide/inference/api-torch-neuronx-trace.html) は、nn.Module に例の入力を一度流し、そのとき実際に動いた計算を記録します。この記事では、重みを持つ nn.Module の `model.gpt` をそのまま渡します。この検証では、関数で包んで渡すと `RuntimeError: Expected XLA tensor` で止まりました。記録した計算は、Neuron のコンパイラ neuronx-cc が NeuronCore の命令の集まり（NEFF）に変え、`trace()` はそれを関数のように呼べるモジュールとして返します。**コンパイルの時点で入力の形が決まるので、できたモデルは例と同じ形の入力しか受け付けません**。データ型も、例の入力にそろえます。例と違う長さの文を渡すと、`expected 1 50` のような形のエラーで止まります。`if` の分かれ道や `for` の繰り返しも、例の入力が通った道と回数に固定されます。

## 固定の形に合わせる

![110 個の音声コードを 128 個まで埋めて Neuron で計算し、出てきた 128 フレームの latents から先頭の 110 フレームを残す。trace の例の wav_lengths には、バケットの 128 に 1024 を掛けた値を渡す](/images/53cc505a8d85e2-pad-trim.png)

実際の文の長さは毎回変わるので、この記事では、文を 50 トークン、音声コードを 128 個の固定の形（bucket、バケット）でコンパイルしました。短い入力は足りない分を埋め、長い入力は切り詰めてから Neuron に渡します。出力の latents は 128 フレームで返るので、実際の長さの割合で切り戻してから HifiDecoder に渡します。切り戻しは長さを合わせるだけなので、上限を超えて切り詰めた文や音声コードは戻りません。埋めた分も GPT の中では計算に入るので、結果は固定の形に合わせる前と同じになるとは限りません。

もう 1 つの注意は `wav_lengths` です。`forward()` は `wav_lengths` を波形のサンプル数として受け取り、[GPT の設定の 1024](https://github.com/coqui-ai/TTS/blob/eef419b37393b11cc741662d041d8d793e011f2d/TTS/tts/layers/xtts/gpt.py#L100) で割って[音声コードの長さを決めます](https://github.com/coqui-ai/TTS/blob/eef419b37393b11cc741662d041d8d793e011f2d/TTS/tts/layers/xtts/gpt.py#L402)。そのため、trace の例には 128 × 1024 を渡します。元の検証では、100 個の音声コードに 100 を渡したところ latents が 1 フレームしか返らず、0.46 秒のほぼ無音の音声になりました。trace はこの値も例の入力で固めるので、コンパイル後のモデルは `text_lengths` と `wav_lengths` の値を使いません。「手元で動かす」の Step 1 の出力にも、この 2 つの入力を使わないという警告が出ます。

## forward() の行き先を差し替える

![Coqui の inference() は self.gpt(...) を呼ぶ。差し替えた forward は、forward_neuron があればコンパイル済みの GPT を、なければ元の forward を呼ぶ。trace の前には、return_latent=True を固定した forward に一時的に置き換える](/images/53cc505a8d85e2-forward-override.png)

Coqui TTS のコードを書き換えて Neuron 用にすると、Coqui TTS の版が上がるたびに同じ変更を当て直す手間が生じます。そこでこの記事では、pip で入れた Coqui TTS はそのままにし、`model.gpt.forward` の行き先だけを外から差し替えます。この記事ではこの方法を Forward Override と呼びます。`types.MethodType` で関数と `model.gpt` を結び付けると、その関数が呼ばれるときに `model.gpt` が `self` として渡されます。trace の前には、`return_latent=True` を固定した `forward` に一時的に置き換えます。trace は例の入力が通った道を固めるので、latents を返す道を通した状態でコンパイルする必要があるからです。推論のときに差し替える `forward` は、コンパイル済みの GPT（`forward_neuron`）があればそれを呼び、なければクラスにもともとある `forward` を呼びます。コンパイル済みの GPT を呼ぶ前には、Coqui が渡す int32 の文のトークンを例の入力と同じ int64 に変え、文を 50、音声コードを 128 まで埋め、返ってきた latents を実際の長さに切り戻します。コンパイル済みの GPT は latents を返す専用なので、[inference() の呼び出し](https://github.com/coqui-ai/TTS/blob/eef419b37393b11cc741662d041d8d793e011f2d/TTS/tts/models/xtts.py#L561-L569)のように `return_latent=True` で呼ぶ使い方に限られます。再現手順では、音声の読み込みの問題を避けるため、Coqui の `load_audio` も同じように外から差し替えます。

## 結果

元の検証で、生成した音声を、すべて CPU で動かした場合と比べた記録です。HifiDecoder はどちらも CPU です。「手元で動かす」の出力とは別の実行です。参照音声は乱数のノイズで、生成はサンプリングなので、値は実行ごとに変わります。

| 項目 | GPT の forward() を Neuron で実行 | すべて CPU |
| --- | --- | --- |
| 生成された音声の長さ | 5.52 秒 | 4.17 秒 |
| 振幅の実効値（RMS） | 0.139 | 0.132 |
| 振幅の絶対値の最大（Peak） | 0.712 | 0.786 |
| 振幅の絶対値が 0.01 未満のサンプルの割合 | 8.7% | 10.5% |
| STT 認識率（元の記録で、計算の式は記録にない） | 80.0% | 81.8% |

STT 認識率は、Neuron で 80.0%、CPU だけで 81.8% と記録されています。参照音声と生成が実行ごとに変わるので、この 1 回の比較から音の質が同じとは言えません。この値は Step 4 と同じ式では再現できないので、参考値として扱ってください。元の検証では、すべて CPU で動かす構成の方が速いと記録されていて、処理ごとの時間は測っていません。`generate()` は音声コードを 1 つ作るたびに GPT の計算を繰り返すので、次の段階ではこのループを Neuron に載せることを目指します。

## NxD Inference へつなぐ

![この記事では GPT の forward() だけをコンパイルし、generate() は CPU、形は 1 つのバケットと切り戻し、差し込みは forward の差し替えで行う。NxD Inference の続編では、デコーダを毎ステップ Neuron で動かし、KV キャッシュを使い、3 つのインタフェースで差し込む](/images/53cc505a8d85e2-to-nxd.png)

続編では、CPU に残した `generate()` の各ステップを Neuron で動かす構成を扱います。そこでは、過去のトークンの attention のキーと値を保存して再計算を減らす KV キャッシュと、長さの違う入力を収まる固定の形に入れる仕組みを使います。NxD Inference は、この 2 つを決まったクラスの書き方で受け持つライブラリです。NxD Inference は Neuron SDK 2.30 から maintenance mode なので、続編は NxD Inference の仕組みを知るための記録として読んでください。この記事で見た nn.Module、trace、固定の形の考え方は、NxD Inference でも使います。forward の差し替えは、NxD Inference では 3 つのクラスを書く形に変わります。NxD Inference の 3 つのインタフェースは「[NxD Inference にカスタムモデルを統合するための事前知識](https://zenn.dev/tosshi/articles/81840c7c10dddd)」で、XTTS v2 への当てはめは「[XTTS v2 を NxD Inference で動かす](https://zenn.dev/tosshi/articles/ffc359901ea1cc)」で説明しています。

## 手元で動かす

inf2.xlarge、trn1.2xlarge、trn2.3xlarge のどれかで動かします。インスタンスの立ち上げ方は「[Inf2 や Trn2 の検証環境の作り方](https://zenn.dev/tosshi/articles/a18dce7d66424d)」にあります。

| 項目 | 版 |
| --- | --- |
| Neuron SDK | 2.28 以降 |
| neuronx-cc | 2.22 以降 |
| Python | 3.10〜3.12 |
| coqui-tts | 0.27 以降。Python 3.12 に対応した idiap のフォーク版 |

オリジナルの coqui-ai/TTS は Python 3.12 より前を求めるので、Neuron の環境の Python に合わせて idiap/coqui-tts を使います。Step 3 の `03_inference_with_trim.py` は、torchcodec のライブラリが読み込めずに `RuntimeError: Could not load libtorchcodec` で止まる問題を避けるため、音声の読み込みを soundfile に置き換えています。

### Step 1: GPT モデルのコンパイル

Step 1 で Forward Override パターンを適用した XTTS v2 モデルの GPT コンポーネントを Neuron にコンパイルします。

::::details ステップ 1 のコード
```python
cat > 01_compile_gpt_bucket128.py << 'EOF'
"""
GPT モデルを torch_neuronx.trace() でコンパイルして保存（BUCKET_SIZE=128）
"""
import sys
import os
os.environ['PATH'] = '/opt/aws_neuronx_venv_pytorch_2_9_nxd_inference/bin: ' + os.environ.get('PATH', '')
os.environ['COQUI_TOS_AGREED'] = '1'

import torch
import torch_neuronx
import types
from pathlib import Path

print("=" * 80)
print("Step 1: GPT モデルのコンパイル（BUCKET_SIZE=128）")
print("=" * 80)

# XTTS v2 モデルをロード
print("\n[1/5] XTTS v2 モデルをロード...")
from TTS.api import TTS
tts = TTS("tts_models/multilingual/multi-dataset/xtts_v2").to("cpu")
model = tts.synthesizer.tts_model

print(f"  [OK] XTTS v2 loaded")
print(f"  GPT: {type(model.gpt)}")

# Forward Override パターンを適用
print("\n[2/5] Forward Override パターンを適用...")
model.gpt.forward_original = types.MethodType(type(model.gpt).forward, model.gpt)
print(f"  [OK] forward_original 保存完了")

# ダミー入力を作成
print("\n[3/5] ダミー入力を作成...")

# XTTS v2 GPT の入力形状
batch_size = 1
text_seq_len = 50
audio_seq_len = 128

# GPT.forward() の引数
text_inputs = torch.randint(0, 256, (batch_size, text_seq_len))  # テキストトークン
text_lengths = torch.tensor([text_seq_len])  # テキスト長
audio_codes = torch.randint(0, 1024, (batch_size, audio_seq_len))  # 音声コード
wav_lengths = torch.tensor([audio_seq_len * 1024])  # 音声長（波形サンプル数）
cond_latents = torch.randn(batch_size, 32, 1024)  # conditioning latents (batch, 32, 1024)

# 注意: cond_latents の形状は (batch, 32, 1024)
# これは get_style_emb() の出力 (batch, 1024, 32) を .transpose(1, 2) したもの
# 参考: TTS/tts/layers/xtts/gpt.py の forward() 内の処理

# 重要: wav_lengths は「波形のサンプル数」を表す
# XTTS v2 では hop_length = 1024 なので、audio_seq_len * 1024 が正しい値
# 例: audio_seq_len=100 → wav_lengths=102400 (約 4.27 秒 @ 24kHz)

print(f"  text_inputs: {text_inputs.shape}")
print(f"  text_lengths: {text_lengths.shape}")
print(f"  audio_codes: {audio_codes.shape}")
print(f"  wav_lengths: {wav_lengths.shape}")
print(f"  cond_latents: {cond_latents.shape}  # (batch, 32, 1024)")

# CPU で動作確認
print("\n[4/5] CPU で動作確認...")
model.gpt.eval()
with torch.no_grad():
    try:
        # XTTS v2 GPT の forward メソッドを呼び出し
        output = model.gpt.forward_original(
            text_inputs=text_inputs,
            text_lengths=text_lengths,
            audio_codes=audio_codes,
            wav_lengths=wav_lengths,
            cond_latents=cond_latents,
            return_attentions=False,
            return_latent=True
        )
        print(f"  [OK] CPU inference successful")
        print(f"  Output shape: {output.shape}")
    except Exception as e:
        print(f"  [ERROR] CPU inference failed: {e}")
        import traceback
        traceback.print_exc()
        sys.exit(1)

# Neuron コンパイル
print("\n[5/5] Neuron コンパイル...")
print(f"  [NOTE] これには約 1-2 分かかります...")
print(f"  [NOTE] コンパイラログは /tmp/neuron_cache_gpt_bucket128/ に保存されます")

try:
    # コンパイル用 forward に上書き（kwargs を固定）
    def compile_forward(self, text_inputs, text_lengths, audio_codes, wav_lengths, cond_latents):
        return self.forward_original(
            text_inputs=text_inputs, text_lengths=text_lengths,
            audio_codes=audio_codes, wav_lengths=wav_lengths,
            cond_latents=cond_latents, return_attentions=False, return_latent=True
        )
    model.gpt.forward = types.MethodType(compile_forward, model.gpt)

    # Module を直接渡してコンパイル
    neuron_gpt = torch_neuronx.trace(
        model.gpt,  # torch.nn.Module を直接渡す
        (text_inputs, text_lengths, audio_codes, wav_lengths, cond_latents),
        compiler_workdir='/tmp/neuron_cache_gpt_bucket128',
        compiler_args='--model-type=transformer --auto-cast=all --auto-cast-type=bf16'
    )

    print(f"  [OK] Neuron compilation successful")

    # コンパイル済みモデルを保存
    output_dir = Path("models/compiled_gpt")
    output_dir.mkdir(parents=True, exist_ok=True)
    neuron_gpt.save(str(output_dir / "gpt_neuron_bucket128.pt"))
```

### Step 2: HifiDecoder は CPU で動かす

HifiDecoder は `interpolate(mode="linear")` がコンパイルを通らないので、コンパイルせずに CPU で動かします。このステップでは何もせず、Step 3 に進みます。

### Step 3: 推論実行

Forward Override で、コンパイル済みの GPT の `forward()` を使って音声を合成します。入力を text=50、audio=128 の固定の形に埋めるか切り詰め、出力の latents を実際の長さの割合で切り戻します。

```python
"""
Step 3: XTTS v2 で音声合成を実行（Neuron + trim 戦略）
"""
import sys
import os
os.environ['COQUI_TOS_AGREED'] = '1'
# torchaudio が soundfile バックエンドを使用するように設定（torchcodec 互換性問題を回避）
os.environ['TORCHAUDIO_USE_BACKEND_DISPATCHER'] = '0'

import argparse
import torch
import torch_neuronx  # Neuron クラスの登録のため必要
import types
import soundfile as sf
from pathlib import Path
import torchaudio
import numpy as np

# load_audio 関数を事前に patch（TTS.api の import 前に実行）
import TTS.tts.models.xtts

def load_audio_fixed(audiopath, sampling_rate):
    """soundfile を使用して音声ファイルをロード（torchcodec 互換性問題を回避）"""
    audio_np, sr = sf.read(audiopath)
    # モノラルに変換
    if len(audio_np.shape) > 1:
        audio_np = audio_np.mean(axis=1)
    # torch.Tensor に変換 (1, samples)
    audio = torch.from_numpy(audio_np).float().unsqueeze(0)
    # リサンプリング
    if sr != sampling_rate:
        audio = torchaudio.functional.resample(audio, sr, sampling_rate)
    # clip audio invalid values
    audio.clip_(-1, 1)
    return audio

# XTTS の load_audio 関数を置き換え
TTS.tts.models.xtts.load_audio = load_audio_fixed

args = parser.parse_args()

# GPT Neuron モデルをロード
print("\n[2/6] GPT Neuron モデルをロード（bucket=128）...")

gpt_neuron_path = Path("models/compiled_gpt/gpt_neuron_bucket128.pt")
if gpt_neuron_path.exists():
    neuron_gpt = torch.jit.load(str(gpt_neuron_path))

    # Forward Override パターンを適用
    model.gpt.forward_original = types.MethodType(type(model.gpt).forward, model.gpt)

    # コンパイル時の固定サイズ（Bucket Strategy）
    COMPILED_TEXT_LEN = 50
    COMPILED_AUDIO_LEN = 128  # 100 → 128 に拡大（truncate 頻度を削減）

    def forward_wrapper_with_trim(self, text_inputs, text_lengths, audio_codes, wav_lengths,
                                   cond_latents=None, return_attentions=False, return_latent=False):
        if hasattr(self, 'forward_neuron'):
            # [1] 実際の長さを記録（padding 前）
            actual_text_len = text_inputs.size(1)
            actual_audio_len = audio_codes.size(1)

            # [2] text_inputs を固定長に padding/truncate（データ型も torch.int64 に変換）
            text_inputs = text_inputs.to(torch.int64)
            if actual_text_len < COMPILED_TEXT_LEN:
                pad_size = COMPILED_TEXT_LEN - actual_text_len
                text_inputs_padded = torch.nn.functional.pad(text_inputs, (0, pad_size), value=0)
            elif actual_text_len > COMPILED_TEXT_LEN:
                text_inputs_padded = text_inputs[: , : COMPILED_TEXT_LEN]
                actual_text_len = COMPILED_TEXT_LEN  # truncate した場合は実長を更新
            else:
                text_inputs_padded = text_inputs

            # [3] audio_codes を固定長に padding/truncate（データ型も torch.int64 に変換）
            audio_codes = audio_codes.to(torch.int64)
            if actual_audio_len < COMPILED_AUDIO_LEN:
                pad_size = COMPILED_AUDIO_LEN - actual_audio_len
                audio_codes_padded = torch.nn.functional.pad(audio_codes, (0, pad_size), value=0)
            elif actual_audio_len > COMPILED_AUDIO_LEN:
                audio_codes_padded = audio_codes[: , : COMPILED_AUDIO_LEN]
                actual_audio_len = COMPILED_AUDIO_LEN  # truncate した場合は実長を更新
            else:
                audio_codes_padded = audio_codes

            # [4] lengths を固定値に設定（重要: wav_lengths は サンプル数 = audio_len * 1024）
            text_lengths_fixed = torch.tensor([COMPILED_TEXT_LEN], dtype=text_lengths.dtype, device=text_lengths.device)
            wav_lengths_fixed = torch.tensor([COMPILED_AUDIO_LEN * 1024], dtype=wav_lengths.dtype, device=wav_lengths.device)

            # [5] Neuron モデル実行
            output = self.forward_neuron(text_inputs_padded, text_lengths_fixed, audio_codes_padded, wav_lengths_fixed, cond_latents)

            # [6] 出力をトリミング（Trim Strategy）
            if actual_audio_len < COMPILED_AUDIO_LEN:
                trim_ratio = actual_audio_len / COMPILED_AUDIO_LEN
                expected_output_len = max(1, int(output.size(1) * trim_ratio))
                output_trimmed = output[: , : expected_output_len, : ]
            else:
                # truncate された場合はそのまま（実長 = bucket サイズ）
                output_trimmed = output

            return output_trimmed
        else:
            return self.forward_original(text_inputs, text_lengths, audio_codes, wav_lengths,
                cond_latents=cond_latents, return_attentions=return_attentions, return_latent=return_latent)

    model.gpt.forward = types.MethodType(forward_wrapper_with_trim, model.gpt)
    model.gpt.forward_neuron = neuron_gpt
    print(f"  [OK] GPT Neuron モデルロード完了（bucket=128, trim 戦略）")
else:
    print(f"  [ERROR] GPT Neuron モデルが見つかりません: {gpt_neuron_path}")
    sys.exit(1)

# HifiDecoder Neuron モデルをロード（引数に応じて）
print(f"\n[3/6] HifiDecoder {args.hifidecoder_device.upper()} モード...")

if args.hifidecoder_device == 'neuron':
    hifidecoder_neuron_path = Path("models/compiled_hifidecoder/hifidecoder_neuron.pt")
    if hifidecoder_neuron_path.exists():
        neuron_hifidecoder = torch.jit.load(str(hifidecoder_neuron_path))

        # Forward Override パターンを適用
        model.hifigan_decoder.forward_original = model.hifigan_decoder.forward

        def hifidecoder_forward_wrapper(self, latents, g=None):
            if hasattr(self, 'forward_neuron'):
                return self.forward_neuron(latents, g)
            else:
                return self.forward_original(latents, g=None)

        model.hifigan_decoder.forward = types.MethodType(hifidecoder_forward_wrapper, model.hifigan_decoder)
        model.hifigan_decoder.forward_neuron = neuron_hifidecoder
        print(f"  [OK] HifiDecoder Neuron モデルロード完了")
    else:
        print(f"  [ERROR] HifiDecoder Neuron モデルが見つかりません: {hifidecoder_neuron_path}")
        sys.exit(1)
else:
    print(f"  [OK] HifiDecoder は CPU で実行されます（推奨）")

print(f"  GPT has forward_neuron: {hasattr(model.gpt, 'forward_neuron')}")
print(f"  HifiDecoder has forward_neuron: {hasattr(model.hifigan_decoder, 'forward_neuron')}")

# 参照音声ファイルを準備
print("\n[4/6] 参照音声ファイルを準備...")

sample_rate = 24000
duration = 3  # 3 seconds
reference_wav = torch.randn(1, sample_rate * duration)

outputs_dir = Path("outputs")
outputs_dir.mkdir(exist_ok=True)

reference_path = outputs_dir / "reference_speaker.wav"
sf.write(str(reference_path), reference_wav.squeeze().numpy(), sample_rate)

print(f"  [OK] Reference audio created: {reference_path}")

# TTS 実行
print("\n[5/6] TTS 実行...")

text = "Hello, this is a test of XTTS v2 running on AWS Neuron."
language = "en"

print(f"  Text: {text}")
print(f"  Language: {language}")
print(f"  Reference: {reference_path}")

try:
    wav = tts.tts(

    print(f"  Duration: {len(wav) / sample_rate: .2f} seconds")

    traceback.print_exc()
    sys.exit(1)

print("\n[6/6] 動作確認...")
```

### Step 4: 音声品質の自動検証（STT）

Step 4 では、Whisper tiny の文字起こしに入力文の単語が出るかと、振幅の基本の統計を確かめます。声の自然さを含む音の質の全体を判定するものではありません。

```bash
"""
生成音声の品質を STT で自動検証
"""
import torch
import soundfile as sf
import numpy as np
from transformers import AutoProcessor, WhisperForConditionalGeneration

# 生成された音声ファイルを読み込み
audio_path = "outputs/xtts_neuron_gpt_cpu.wav"
audio_np, sample_rate = sf.read(audio_path)

# モノラルに変換（必要な場合）
if len(audio_np.shape) > 1:
    audio_np = audio_np.mean(axis=1)

waveform = torch.from_numpy(audio_np).float().unsqueeze(0)

# 音声信号の基本統計
rms = torch.sqrt(torch.mean(waveform ** 2)).item()
peak = torch.max(torch.abs(waveform)).item()
zero_ratio = (torch.abs(waveform) < 0.01).float().mean().item() * 100

print(f"音声品質指標: ")
print(f"  RMS: {rms: .6f}")
print(f"  Peak: {peak: .6f}")
print(f"  ゼロサンプル割合: {zero_ratio: .1f}%")
print(f"  判定: {'[OK] 有意な音声信号あり' if rms > 0.05 and zero_ratio < 50 else '[NG] 音声信号が不十分'}")

# Whisper で音声認識
print(f"\nSTT 検証: ")
processor = AutoProcessor.from_pretrained("openai/whisper-tiny")
model = WhisperForConditionalGeneration.from_pretrained("openai/whisper-tiny")
model.eval()

# 24kHz → 16kHz にリサンプリング（Whisper の入力形式）
if sample_rate != 16000:
    import torchaudio
    waveform = torchaudio.functional.resample(waveform, sample_rate, 16000)

# 音声認識実行
input_features = processor(waveform.squeeze().numpy(), sampling_rate=16000, return_tensors="pt").input_features
with torch.no_grad():
    predicted_ids = model.generate(
        input_features,
        language="en",
        task="transcribe"
    )
transcription = processor.batch_decode(predicted_ids, skip_special_tokens=True)[0]

# 入力テキストと比較
input_text = "Hello, this is a test of XTTS v2 running on AWS Neuron."
print(f"  入力テキスト: \"{input_text}\"")
print(f"  認識テキスト: \"{transcription}\"")

# 単語単位での一致率を計算
input_words = set(input_text.lower().replace(".", "").replace(",", "").split())
recognized_words = set(transcription.lower().replace(".", "").replace(",", "").split())
word_accuracy = len(input_words & recognized_words) / len(input_words) * 100

print(f"  単語再現率: {word_accuracy: .1f}%")
print(f"  判定: {'[OK] 音声に有意な音声内容が含まれている' if word_accuracy >= 60 else '[NG] 音声内容が不明瞭'}")
```

## まとめ

XTTS v2 では、GPT の `forward()` だけを固定の形で trace し、`forward` の行き先を差し替えることで、Coqui TTS のソースファイルを編集せずに Neuron で推論できました。この記事の nn.Module、trace、固定の形の考え方は、maintenance mode に入った NxD Inference で `generate()` のループを Neuron に載せる続編を読むときの前提になります。
