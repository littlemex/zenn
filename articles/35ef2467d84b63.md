## はじめに

[Engram](https://arxiv.org/abs/2601.07372) は、今の位置で終わる数個のトークン（文章を区切った単位）の並びを手がかりに大きな表から数を読み出し、LLM の中を流れる数のベクトルに足す部品です。表の中身も、モデルのほかの重み（計算に使う数で、学習で少しずつ直していくもの）と一緒に学習で決まります。[DeepSeek](https://www.deepseek.com/) と北京大学の研究者が論文で提案し、DeepSeek が公開した LLM の [DeepSeek-V4.1-Flash](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash/tree/2cba9e42aa026125f3ed06c6d98c1db82f7ca027) にも入っています。この記事では、小さな [GPT-2](https://github.com/openai/gpt-2) 型のモデルに Engram を組み込んで学習させました。「Only Alexander the」の次の 1 トークンを当てる 1 か所で、表引きの 1 歩ずつと、モデルの計算の 1 ブロックずつを追います。

## Engram が受け持つ仕事

論文がねらう分担は、GPT の本体（図の GPT backbone）が文脈を読んで次のトークンを決め、Engram が今の位置で終わる並びで表を引いて数を足す、という形です。

GPT 型の LLM は、トークンを番号にし、ブロックと呼ぶ計算を順に通して、次のトークンの確率を出します。ブロックは 0 から数え、最初がブロック 0 です。論文の「層」は、この記事のブロックと同じものですが、論文は 1 から数えるので、論文の層 2 はこの記事のブロック 1 です。ブロックとブロックの間を流れる、位置ごとの数のベクトルが隠れ状態です。

![左右とも 6 ブロックの模式図。Engram が無いと、初めのブロックで Alexander the Great という名前を組み立てる。Engram があると、表引きが組み立てを助け、残りのブロックを文脈を読む仕事に回せる、という論文の仮説を描いたもの](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/engram-why.png)

図は、論文の仮説を 6 ブロックで描いた模式図です。「Only Alexander the」の次の「Great」を当てるには、「the」だけでなく、前の「Alexander」と合わせた並びが手がかりになります。論文は[別の研究](https://arxiv.org/abs/2401.06102)の例を引いて、複数のトークンでできた名前の表し方を初めの何層かで組み立てる様子を示し、こうした並びに対応する数を表にも学習させれば、本体の組み立てを助けられると考えました。

## Engram の中身

この記事で作った Engram の 1 層は、読む行を決め、行を読んで key と value に変え、足す量を決めて足します。例えるなら、今の位置で終わる 2〜3 個のトークンから番号を計算して引き出しを 16 個開け、中身をまとめて「文脈と比べるための数」（key）と「足すための数」（value）に作り替え、key で文脈との合い方を見て、value をどれだけ足すかを決める仕組みです。別の並びが同じ引き出しを使うこともあります。

続けて並んだ n 個のトークンを n-gram と呼びます。図の 7 つの手順は、読む行を決める手順 1〜3、行を読んで key と value にする手順 4〜5、足す量を決めて足す手順 6〜7 に分かれます。

### 行の選び方

並びの種類は多すぎて、1 つずつに行を用意できないので、ハッシュ、つまり並びから決まった計算で行番号を選びます。表は 16 個の範囲に区切ってあり、2-gram が 8 個、3-gram が 8 個の範囲を使います。範囲の行数はどれも違う素数で、1 つの範囲で 1 行を選ぶ計算 1 回分を、ここではヘッドと呼びます。この実装と V4.1-Flash は、n-gram から作る 1 つの大きな数をヘッドの間で共有し、ヘッドごとに違う素数で割った余りを行番号にします。

別の並びが、あるヘッドで同じ行に当たることがあり、これを衝突と呼びます。1 つの n-gram に使う 8 個のヘッドは違う素数で割るので、1 つのヘッドで衝突しても、ほかのヘッドでは別の行になりえます。割る前の大きな数がたまたま同じなら、その n-gram の 8 個とも同じ行になります。トークンの番号のそろえ方とハッシュの計算は V4.1-Flash の[参照実装](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash/blob/2cba9e42aa026125f3ed06c6d98c1db82f7ca027/inference/engram.py)と同じで、同じ設定なら同じ行番号が出ることを、筆者の実験の[テストのコード](https://github.com/littlemex/zenmai-lab/blob/7d12d417f789173aa7082d4739c297d08116ad24/experiments/2026-10-21-engram-nanogpt/tests/test_engram_lm.py)で確かめています。

### 足す量の決め方

ゲート $\alpha$ は 0 と 1 の間の数で、value を何倍して隠れ状態に足すかを決めます。0 に近いほど足す量は小さく、1 に近いほど value をほぼそのまま足し、例文の「the」の 0.88 なら value の各数を 0.88 倍して足します。ゲートは、大きさをそろえた隠れ状態と key の同じ番目の数どうしを、学習した重みを付けて掛けて全部足した点数から決まり、点数が高いほど 1 に近づきます。$\alpha$ は足し込みの係数で、次のトークンの確率や、隠れ状態に占める割合ではありません。この記事では、$\alpha$ が 0.5 を超えて value を多く足す状態を「ゲートが開く」と呼びます。

:::details ゲートの計算式と、論文や実装との違い
位置 $t$ の隠れ状態を $\mathbf{h}_t$、key を $\mathbf{k}_t$、value を $\mathbf{v}_t$ とすると、次のとおりです。

$$
s_t = \frac{1}{\sqrt{d}} \sum_{i=1}^{d} w_i \, \hat{h}_{t,i} \, \hat{k}_{t,i},\qquad
\alpha_t = \sigma\!\left(\operatorname{sign}(s_t)\sqrt{|s_t|}\right),\qquad
\mathbf{h}_t \leftarrow \mathbf{h}_t + \alpha_t \mathbf{v}_t
$$

- $\hat{h}_{t,i}$ は $\mathbf{h}_t$ の $i$ 番目の数を、2 乗平均に $\varepsilon = 10^{-6}$ を足した値の平方根で割ったもので、$\hat{k}_{t,i}$ も同じです。$d$ は 1 つのベクトルの数の個数で 512、$\sigma$ はどんな数も 0 から 1 に変えるシグモイド関数です。
- $w_i$ は学習で決まる重みで、実装では [RMSNorm](https://arxiv.org/abs/1910.07467) の学習する 2 つの重みの積です。
- $\operatorname{sign}(s_t)\sqrt{|s_t|}$ は、符号を残したまま大きさの平方根を取る計算です。論文の式 (4) にはこの平方根がありませんが、V4.1-Flash の[参照実装の model.py](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash/blob/2cba9e42aa026125f3ed06c6d98c1db82f7ca027/inference/model.py) に合わせて入れています。式では、$|s_t|$ に付ける小さな下限を省きました。
:::

## 小さな GPT に組み込んで学習させる

Engram を足したときの差を見るため、同じ GPT の本体に Engram を足したモデルと足さないモデルを学習させました。Engram ありは、表の 6,716 万個と、key と value とゲートを作る重みの約 105 万個、合わせて 6,821 万個だけ重みが多くなります。

### 作るモデル

12 ブロックの GPT の、ブロック 0 とブロック 1 の間に [Engram の層](https://github.com/littlemex/zenmai-lab/blob/7d12d417f789173aa7082d4739c297d08116ad24/experiments/2026-10-21-engram-nanogpt/engram_lm/engram.py)を 1 つ入れます。[モデル全体](https://github.com/littlemex/zenmai-lab/blob/7d12d417f789173aa7082d4739c297d08116ad24/experiments/2026-10-21-engram-nanogpt/engram_lm/model.py)は、ブロック 0 を計算する前に全部の位置の行番号を先に計算しておきます。

![12 ブロックの GPT。トークンの番号から、ブロック 0 の前にハッシュで 16 個の行番号を計算しておき、ブロック 0 とブロック 1 の間の Engram に渡す](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/placement.png)

本体は、OpenAI の [GPT-2](https://github.com/openai/gpt-2) 型のブロックを 12 個重ねたもので、隠れ状態は 1 位置 512 個の数、一度に読む文脈は 512 トークンです。Engram を 2 番目のブロック（ブロック 1）の前に置いたのは、[論文の 6.2 節](https://arxiv.org/abs/2601.07372)が、重みの総数 30 億個の 12 層の MoE モデルに 16 億個の Engram を 1 か所だけ置くなら、2 番目の層が最も良かったと報告しているからです。MoE は、ブロックの中に小さな計算（expert）をいくつも持ち、トークンごとにその一部だけを使うモデルです。

| 部品 | この記事のモデル | DeepSeek-V4.1-Flash |
|---|---|---|
| n-gram とヘッド | 2-gram と 3-gram、8 個ずつ、計 16 行 | 2〜4-gram、8 個ずつ、計 24 行 |
| 表 | 1,049,422 行 × 64、6,716 万個の重み | ブロック 1 の前が 384,006,168 行、ブロック 14 の前が 384,016,682 行、1 行 256 個 |
| 置く場所 | ブロック 1 の前の 1 か所 | ブロック 1 と 14 の前の 2 か所 |
| 論文の追加の部品 | 入れていない（ゲートを掛けた value に短い畳み込みの出力を加える仕組みと、隠れ状態と同じ幅の流れを 4 本並べる仕組み） | 短い畳み込みは入れていない。流れを 4 本並べる仕組みは使う |

V4.1-Flash の値は、[設定ファイル](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash/blob/2cba9e42aa026125f3ed06c6d98c1db82f7ca027/inference/config.json)と参照実装から取りました。

### 重みを 1 回直す流れ

学習では、モデルの予想と正解を比べ、外れが小さくなるように重みを少しずつ直します。

![文章から 512 トークンの窓を 128 個取り出し、モデルが次のトークンの確率を出し、正解との外れ具合の損失から勾配を求め、重みを直す。表は読まれた行に勾配が届く。これを 3,600 回繰り返す](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/training-step.png)

モデルは各位置で次のトークンの確率を出し、正解のトークンとの外れ具合が損失です。重みを少し動かすと損失がどう変わるかを表すのが勾配です。重みを 1 回直すたびに、文章から無作為に取り出した 512 トークンの区切り（窓）128 個分の勾配を使い、これを 3,600 回繰り返して 2.36 億トークンを学習しました。表には、その回に読まれた行に勾配が届きます。一度も読まれない行は最初の乱数のままです。一度読まれた行は、表の重みを直す方法（次の節の Adam）が前の回の勾配も覚えているので、読まれない回にも少し動きます。

### 比べ方

2 つのモデルの違いを Engram の有無にするため、同じ本体の重みから始め、同じ文章を同じ順番で読ませました。

![左の Engram なしと右の Engram ありで、学習を始める前の本体の重み、読む文章の順番、2.36 億トークンの学習量と AdamW の設定が同じ。右だけに Engram の 6,821 万個の重みがあり、表は本体の 5 倍の学習率で weight decay なしの Adam で学習する。重みの総数は約 6,377 万と約 1 億 3,198 万](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/comparison.png)

学習に使った文章は、Wikipedia から作られた [WikiText-103](https://huggingface.co/datasets/Salesforce/wikitext) です。重みのはじめの値と窓を取り出す順番を決める seed を、1337、1338、1339 の 3 通りに変え、2 つのモデルを 3 回ずつ学習させました。実装は本体を先に初期化し、Engram を別の乱数の流れで作るので、同じ seed なら本体は同じ重みから始まります。このことは[テスト](https://github.com/littlemex/zenmai-lab/blob/7d12d417f789173aa7082d4739c297d08116ad24/experiments/2026-10-21-engram-nanogpt/tests/test_engram_lm.py#L133-L145)で確かめています。表以外の重み（本体と、Engram の key と value とゲートの重み）は [AdamW](https://arxiv.org/abs/1711.05101) という方法で直し、Engram の表だけは、[論文の 4.1 節](https://arxiv.org/abs/2601.07372)と同じく [Adam](https://arxiv.org/abs/1412.6980) で、1 回に重みを動かす幅（学習率）を本体の 5 倍にし、重みを縮める weight decay を掛けません。

:::details 学習の環境と設定
- GPU: [Amazon EKS](https://aws.amazon.com/eks/) の上の [NVIDIA RTX PRO 4500 Blackwell](https://www.nvidia.com/en-us/products/workstations/professional-desktop-gpus/rtx-pro-4500/) を、1 つの学習に 1 枚
- ソフトウェア: [PyTorch](https://pytorch.org/) 2.9.1、[CUDA](https://developer.nvidia.com/cuda-toolkit) 12.8、bfloat16 の混合精度、[`torch.compile`](https://docs.pytorch.org/docs/stable/generated/torch.compile.html)
- バッチ: 32 窓ずつ 4 回に分けて勾配をため、128 窓 × 512 トークン = 65,536 トークンごとに重みを直す
- 学習率: 最初の 300 回で 6e-4 まで上げ、その後 6e-5 まで下げる。表の学習率はその 5 倍で、3e-3 から 3e-4。weight decay は表以外の行列の形の重みで 0.1
- 勾配のクリップ: 本体、Engram の表以外の重み、表の 3 組に分け、組ごとに勾配の大きさが 1.0 を超えたら 1.0 まで縮める
- 窓の取り出し方: 重なりを許して無作為に取り出す。2.36 億トークンは WikiText-103 の学習用の文章（約 1.18 億トークン）の約 2 倍だが、ちょうど 2 周読むわけではない
:::

## 学習の結果

Engram ありは、学習の序盤に損失を早く下げましたが、学習を終えた後に、学習に使っていない文章で測った性能の差は小さいものでした。

:::details 評価と集計の条件
- 評価は学習の最後の重みで、文章を重ならない 512 トークンの窓に切り、窓ごとに前の文脈を持たずに測った。最後の窓に満たない残りは測っていない
- パープレキシティは GPT-2 のトークン単位で、単語単位で報告される WikiText-103 の値とは比べられない
- ± は 3 つの seed の値の標準偏差（n − 1 で割ったもの）
:::

### 学習中の損失

Engram の効き目が学習のどの段階で出るかを見るため、学習の途中で、学習に使っていない検証用の文章で損失を測りました。この検証の損失は、低いほど予想が良いことを表します。

![上の段は 6 回の学習の検証の損失で、Engram ありは実線と丸、Engram なしは破線と四角。下の段は同じ seed どうしの差で、0 より下なら Engram ありが低い。約 2,600 万トークンで -0.20〜-0.23、8,000 万トークン前後でほぼ 0、1 億トークンから最後まで -0.008〜-0.030](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/val-loss.png)

約 2,600 万トークン（重みを 400 回直した時点）で、Engram ありの損失は、同じ seed の Engram なしより 0.20〜0.23 低くなりました。Engram なしがこの損失に届くのは、評価の点の間を直線でつないで約 485 回目で、学習の量にすると約 85 回分、約 560 万トークンの先行です。差は 8,000 万〜9,000 万トークンでほぼ 0 になり（seed 1337 では一度わずかに逆転）、1 億トークンから最後までは、3 つの seed とも 0.008〜0.030 の差で Engram ありが低い値でした。

### 学習後の性能

性能は、正解のトークンに付けた確率から求めるパープレキシティで比べました。パープレキシティは、実際の次のトークンにどれだけ確率を付けられたかを表す値で、平均の損失 $\overline{L}$ から $\exp(\overline{L})$ で出し、低いほど良い値です。29 なら、どの位置でも正解に 29 分の 1 の確率を付けたときと同じ平均の損失です。

| | Engram あり | Engram なし |
|---|---|---|
| 重みの数 | 1 億 3,198 万（うち表 6,716 万） | 6,377 万 |
| 検証のパープレキシティ | 28.97 ± 0.08 | 29.26 ± 0.01 |
| テストのパープレキシティ | 29.40 ± 0.16 | 29.36 ± 0.13 |
| 学習のスループット（1 秒あたりのトークン） | 149,543 | 155,677 |

検証用とテスト用の文章は、どちらも学習に使っていない、WikiText-103 の別々の部分です。値は 3 つの seed の平均で、± の後は seed によるばらつき（標準偏差）です。検証では Engram ありが Engram なしより平均 1.0% 低く、3 つの seed のどれでも低い値でした。テストではほぼ同じで、同じ seed どうしでは Engram ありが 0.06、0.06、0.00 高い値でした。学習のスループットは、検証と保存の時間を除いて 1 枚の GPU で測った値で、Engram なしより 3.9% 下がりました。

学習を終えたモデルが表引きにどれだけ頼っているかを見るため、評価のときだけ表引きの足し込みを飛ばしました。以下、これを「表引きを外す」と呼びます。

## 1 つの文で中身を追う

例文「Only Alexander the」の「the」の位置で、正解の「Great」に付けた確率を、ブロックを 1 つ通るたびに取り出して 3 通りで比べました。Engram ありのモデル、その重みのまま表引きを外した場合、最初から Engram なしで学習したモデルです。例文は論文の Figure 1 の文で、結果を見る前に選びましたが、表引きに有利な固有名詞を含む、seed 1337 のモデルの 1 か所の観察です。この記録はすべて CPU の float32 で計算しました。

## ほかの文と文章全体で見る

1 つの位置で見えた違いを、ほかの位置と文章全体で、ゲートの値と途中の予想の 2 つから確かめました。

### ゲートは多くの位置で開く

ゲートが位置ごとにどう変わるかを見るため、44 トークンの文で seed 1337 のモデルのゲートを並べました。文は、筆者の実験の[リポジトリに入れた記録](https://github.com/littlemex/zenmai-lab/blob/7d12d417f789173aa7082d4739c297d08116ad24/experiments/2026-10-21-engram-trace-viewer/viewer/traces/nanogpt-hastings.json)にある、ヘイスティングズの戦いの文です。41 か所でゲートが開き、低かったのは 3 か所だけでした。

![The Battle of Hastings で始まる 44 トークンの文で、seed 1337 の Engram ありのモデルの位置ごとのゲート α。多くの位置で 0.5 を超え、William、Normandy の後の読点、Harold の 3 か所だけ 0.19〜0.22。白い太枠と値で示した](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/gate-text.png)

WikiText-103 ではハイフンが「@-@」と書かれ、GPT-2 のトークナイザは「␣Godwinson」を「␣God」「w」「inson」に分けるので、図の横軸にはそうしたトークンが並びます（␣ はトークンの前に付いた空白です）。低かったのは、人名の William と Harold、Normandy の後の読点で、値は 0.19〜0.22 でした。同じ人名でも、Harold Godwinson の最後の「inson」は 0.85、地名の Hastings は 0.78、Normandy は 0.81 です。例文の「the」の 0.88 も、この文の多くの位置と変わらない値です。論文の Figure 7 は、名前を言い終えた位置でゲートが大きく開く例を示しています。論文のモデルは Engram を 2 か所に置き、4 本の流れごとにゲートを持つのでゲートは 8 個あり、図はそのうち意味のある並びと最も強く結びつくものを選んで描いています。ゲートが 1 個のこのモデルのこの文では、そうした傾向ははっきりとは見えませんでした。検証用の文章の最初の 200 窓では、3 つの seed の平均で、ゲートの平均は 0.66、0.5 を超えた位置は 74% でした。

### 途中の予想と最後の予想の近さ

表引きを足すと、早いブロックのうちに予想が最後の形に近づくかを見るため、検証用の文章で、LogitLens で取り出した途中のブロックの予想を、そのモデル自身の最後の予想と比べました。近さは KL ダイバージェンス（KL）で測りました。2 つの確率の並びがどれだけ違うかを表す 0 以上の値で、同じなら 0 です。

![検証用の文章の最初の 200 窓で、ブロックごとの仮の予想と、同じモデルの最後の予想との違いを KL で測った値。Engram ありは実線と丸で、ブロック 0 の後は 5.04、ブロック 1 の後は 2.91 で、ブロック 10 まで Engram なしより低い。Engram なしは破線と四角で、ブロック 0 から 4 までほぼ 4。3 つの seed の平均と標準偏差](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/logit-lens-kl.png)

最後の予想 $p_{\mathrm{final}}$ を基準に、ブロック $l$ の後の予想 $p_l$ を比べた $D_{\mathrm{KL}}(p_{\mathrm{final}} \,\|\, p_l)$ を 10 万 2,400 か所で平均し、3 つの seed で平均しました。点は平均、縦の線は標準偏差で、最後のブロックの後は 0 になるので省いています。Engram ありはブロック 1 の後で 2.91 で、Engram なしの 3.94 より低く、ブロック 10 まで低いままでした。表引きを足す前のブロック 0 の後だけは、Engram ありが 5.04 で、Engram なしの 4.01 より高い値です。この KL は各モデル自身の最後の予想との近さで、どちらが正しく当てるかや、ブロックの仕事の分担を測った値ではありません。論文の「初めのブロックの仕事を表引きが助ける」という読み方とは矛盾しない、という結果です。

### 1 位の候補が固まるブロック

予想の 1 位がどのブロックで決まるかを数で見るため、検証用の文章の 483 窓すべて、seed あたり 247,296 か所で、1 位の候補がどのブロックから最後まで変わらなくなったかを数えました。本体は GPU の bfloat16 の混合精度で、各ブロックの予想の読み出しは float32 で計算しました。[集計のコード](https://github.com/littlemex/zenmai-lab/blob/7d12d417f789173aa7082d4739c297d08116ad24/experiments/2026-10-21-engram-nanogpt/engram_lm/settling.py)は、最後のブロックまで計算した後で振り返って数えるもので、固まった後のブロックも計算され、確率は変わり続けます。

![1 位の候補がそれ以上変わらなくなったブロックの割合。ブロック 1 で固まった位置は、Engram ありが 14.5%、同じ重みで表引きを外すと 8.7%、Engram なしで学習したモデルが 4.8%。斜線、点、× の格子の棒で区別。3 つの seed の平均](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/settling.png)

同じ seed どうしで位置ごとに比べると、Engram ありのほうが早く固まった位置が 46.4%、遅かった位置が 26.1%、同じだった位置が 27.4% でした。固まったブロックの平均は、Engram ありが 6.27、表引きを外すと 6.91、Engram なしが 7.04 です。差が最も大きいのは表引きの直後で、ブロック 1 で固まった位置は Engram ありが 14.5%、Engram なしが 4.8%、ブロック 1 までに固まった位置は同じ順に 23.0% と 13.9% でした。ここでの 1 位はそのモデル自身の最後の 1 位で、それが実際の次のトークンと一致した位置は、Engram ありが 40.2%、Engram なしが 39.8% です。

両方のモデルが最後に正解し、Engram ありのほうが早く固まった位置だけを集めると、固まった時点の 1 位の確率の中央値（seed ごとの値の平均）は、Engram ありが 0.39、Engram なしが 0.48 で、早く固まった側のほうが低い値でした。早く 1 位が決まることは、早く高い確率を付けることとは別です。表引きを外しても、ブロック 1 で固まる位置は 8.7% で Engram なしの 4.8% より多い一方、最後の 1 位が正解の位置は 30.8% に下がります。早く固まる理由が表引きの足し込みにあるのか、一緒に学習した本体の重みにあるのかは、この集計からは分かりません。

## 表を分けて学習し直す

学習の最後の 200 回の更新では、Engram ありの学習用の文章での損失は Engram なしより 0.151 低いのに、検証用の文章では 0.010 しか低くありませんでした。表が、一度読んだ文章の続きを覚えていたためです。そこで、学習用の文章を Wikipedia の記事ごとに順に 3 つに分け、表も 3 つ持たせて、各位置には自分の記事を学習していない 2 つの表の平均だけを読ませて学習し直しました。表全体の大きさは元と同じです。3 つの seed の平均で、テスト用の文章のパープレキシティは 29.40 から 28.50 に下がり、Engram なしの 29.36 も下回りました。

これは、1.18 億トークンの文章を約 2 周するこの規模での結果です。文章を 1 周しかしない大規模な学習では、表が一度読んだ文章をまた読む場面がもともと少ないので、同じように効くかは試していません。それでも、Engram の作りにはまだ改善の余地がありそうです。試した内容と数字は[解説のページ](https://littlemex.github.io/explainers/engram-ideas.html)に、コードは [zenmai-lab](https://github.com/littlemex/zenmai-lab/tree/61a8d823b6c37a268a015ec61806b85ad9d4b219/experiments/2026-11-17-engram-cutoff-train) に置きました。

## 比較の範囲

この記事で比べたのは、同じ GPT の本体に Engram を足した場合と、足さない場合です。違いは Engram の重みだけでなく表の学習の設定にもあるので、差を「表引きという仕組みの効果」と「重みや学習の設定が違う効果」に切り分ける比較ではありません。

|---|---|
| Engram あり と Engram なし の比較 | Engram ありは重みが 6,821 万個多く、表だけ本体の 5 倍の学習率の Adam で学習し、勾配のクリップも別の組にしている |
| 規模 | 12 ブロック、2.36 億トークン、WikiText-103 の 1 通りだけで試した |

| 中身の分析 | 途中の予想、ゲート、固まるブロックは検証用の文章だけで測った。1 つの文の追跡は seed 1337 の 1 か所 |

## 自分で動かす

筆者が公開した学習済みのモデルと、筆者が作った、1 つの文の中身を画面で追う[ページ](https://github.com/littlemex/zenmai-lab/tree/7d12d417f789173aa7082d4739c297d08116ad24/experiments/2026-10-21-engram-trace-viewer)を使うと、ここまでの観察を自分の文で試せます。

![動作確認のページの一部。with Engram の欄に、Alexander the と Only Alexander the をキーに 1,049,422 行の表から 16 行を読み、ブロック 1 の前に足すこと、混ぜる強さ 88%、表引きの有無でブロック 1 の後の Great の確率が 0.1% から 5.3% に変わることが並ぶ。trained without Engram の欄には、表なしで学習したモデルである説明が並ぶ](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/ladder-lookup.png)

図は、ページで「the」を選んだときの表引きの欄です。欄の「top choice same」は、1 位の候補が「␣same」というトークンだという意味です。ページの「How strongly it is mixed in」はゲート $\alpha$ で、88% は value に掛ける 0.88 のことです。モデルは [Hugging Face の littlemex/engram-nanogpt-wikitext103](https://huggingface.co/littlemex/engram-nanogpt-wikitext103) に、6 回の学習の分を置いてあります。

:::details この記事の例文を記録して、画面で開く手順
Git、[Python](https://www.python.org/) 3、[uv](https://docs.astral.sh/uv/) を使います。モデルの取得には [Hugging Face の CLI](https://huggingface.co/docs/huggingface_hub/guides/cli) の `hf download` を使います。モデルのファイルは 2 つで約 785 MB です。記録は CPU で動き、手元の Mac では、依存のパッケージを入れた後の記録のコマンドだけで 17 秒でした（モデルのダウンロードを除く）。記録は、入力の文の後に Engram ありのモデルで 20 トークンを書き足し、その全体を 3 通りで読み直します。書き足した部分の次のトークンは人が用意した正解ではなく、Engram ありのモデルの出力です。例文は、学習の文章と同じく先頭に空白を置いた「␣Only Alexander the Great could tame the horse」です。

```bash
git clone https://github.com/littlemex/zenmai-lab.git
cd zenmai-lab
git checkout 7d12d417f789173aa7082d4739c297d08116ad24
cd experiments/2026-10-21-engram-nanogpt
export SEED=1337
uv run --python 3.11 --with-requirements requirements.txt hf download littlemex/engram-nanogpt-wikitext103 --revision e9758158ad0d180336bc059e20fecf29f67f445b --include "*-seed$SEED/model.safetensors" --local-dir hub
uv run --python 3.11 --with-requirements requirements.txt python -m engram_lm.record_trace --engram hub/engram-seed$SEED/model.safetensors --baseline hub/baseline-seed$SEED/model.safetensors --prompt " Only Alexander the Great could tame the horse" --new-tokens 20 --title "Alexander the Great (seed $SEED)" --out ../2026-10-21-engram-trace-viewer/viewer/traces/alexander.json
cd ../2026-10-21-engram-trace-viewer/viewer
python3 -m http.server 8000 --bind 127.0.0.1
```

記録が終わると、次の 1 行が出ます。

```
wrote ../2026-10-21-engram-trace-viewer/viewer/traces/alexander.json: 28 tokens (20 generated)
```

サーバーを動かしたまま、ブラウザで `http://127.0.0.1:8000/ladder.html?trace=traces/alexander.json` を開いてください。`--prompt` を変えると自分の文で試せます。WikiText-103 の書き方に合わせて、句読点の前後に空白を置き、ハイフンを ` @-@ ` と書くと、学習の文章に近い形になります。
:::

## まとめ

Engram は、トークンの番号だけで読む行を先に決め、読んだ数を、ゲートで決めた量だけ隠れ状態に足す部品です。12 ブロックのこの実験では、Engram なしと比べて序盤の損失を早く下げ、検証用の文章で 1 位の候補が固まるブロックの平均も、Engram なしの 7.04 に対して 6.27 と早くなりましたが、学習を終えた後のテスト用の文章のパープレキシティはほぼ同じでした。学習用の文章と表を 3 つに分け、各位置に自分の部分を学習していない表だけを読ませて学習し直すと、この規模ではテストのパープレキシティが 29.40 から 28.50 に下がりました。

論文の結果の詳しい読み方は「[Engram は何を覚えて、どう引くのか](https://zenn.dev/tosshi/articles/5853108f53bd7f)」に、大きな表を何台かに分けて持つ方法は「[Engram の表を何台かに分けて引く](https://zenn.dev/tosshi/articles/54aced4bdcb137)」に書きました。
