## はじめに

Engram は、今の位置で終わる数個のトークンの並びを手がかりに大きな表から数を読み出し、LLM の中を流れるベクトルに足す部品です。表の中身も、モデルのほかの重みと一緒に学習で決まります。DeepSeek と北京大学の研究者が[論文](https://arxiv.org/abs/2601.07372)で提案し、DeepSeek が公開した LLM の [DeepSeek-V4.1-Flash](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash/blob/2cba9e42aa026125f3ed06c6d98c1db82f7ca027/inference/config.json) にも入っています。仕組みを読むだけでは、表から何が出てきて、モデルの中で何が変わるのかが見えません。この記事では、小さな GPT に Engram を組み込んで学習させ、「Only Alexander the」の次の 1 トークンを当てる 1 か所を、表引きの 1 歩ずつと、モデルの計算の 1 段ずつで追います。

## Engram が受け持つ仕事

Engram は、直前の数個のトークンだけで決まる手がかりを、毎回計算する代わりに表から読み出します。論文が狙う分担は、GPT の本体が文脈を読んで次のトークンを決め、Engram が直前の並びで表を引いて数を足す、という形です。

![左右とも 6 ブロックの模式図。Engram が無いと、初めのブロックで Alexander the Great という名前を組み立てる。Engram があると、表引きが組み立てを助け、残りのブロックを文脈を読む仕事に回せる、という論文の考え方を描いたもの](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/engram-why.png)

GPT 型の LLM は、文章をトークンという単位に分けて番号にし、ブロックと呼ぶ計算を順に通して、次のトークンの確率を出します。ブロックとブロックの間を流れる、位置ごとの数のベクトルが隠れ状態です。「Only Alexander the」まで読んだ位置で次の「Great」を当てるには、「the」だけでなく、前の「Alexander」とひとまとまりで王の名前の書き出しだと捉える必要があります。論文は、こうした名前の組み立てに初めの何ブロックかが使われると説明しています。

直前の並びから分かる手がかりは、並びが同じなら毎回同じです。論文は、これを毎回ブロックで計算し直すのは無駄だと考え、並びごとの手がかりを表に覚えさせました。図は論文の考え方を描いた模式図で、ブロックごとの仕事を測ったものではありません。

## Engram の中身

この記事で作った Engram の 1 層は、トークンの番号だけで読む 16 行を決め、その行を読み、今の隠れ状態に合わせて足す量を決めて足します。図では、行番号を決める計算、表を読んで足す Engram の計算、文脈を読む GPT の本体を分けて描きます。

| 部品 | 受け持ち | 使うもの |
|---|---|---|
| 手順 1〜3（方眼の模様の箱） | 読む行の番号を決める | トークンの番号だけ。学習する重みは無い |
| 手順 4〜7（斜線の箱） | 行を読み、足す量を決めて足す | 表と、読んだ数を変換して足す量を決める重み |
| ブロック 0 とブロック 1（× の格子の箱） | 文脈を読む GPT の本体 | 本体の重み |

例えるなら、直前の 2〜3 個のトークンから番号を計算して引き出しを 16 個開け、16 個の中身をまとめた 1 つの束を、今の文脈に合うかを見て何割足すかを決める仕組みです。引き出しに言葉が書いてあるわけではなく、中身は最初は乱数で、学習で決まる数です。別の並びが同じ引き出しを使うこともあります。図の上の段は左から右へ、下の段は右から左へ進みます。

![この記事のモデルの Engram の 1 層。手順 1 でトークンの番号をそろえ直し、手順 2 で n-gram を作り、手順 3 でハッシュから 16 個の行番号を出し、手順 4 で 1,049,422 行 × 64 の表から 16 行を読み、手順 5 で key と value を作り、手順 6 でブロック 0 の後の隠れ状態 h と key からゲート α を出し、手順 7 で h に α を掛けた value を足してブロック 1 に渡す。手順 1〜3 はトークンの番号だけを使う](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/engram-overview.png)

手順 1〜3 がトークンの番号だけで決まることが、Engram の大事な性質です。**読む行の番号は、GPT のブロックを 1 つも計算しないうちに分かります**。そのため、表が大きすぎて GPU のメモリに入らないときも、表を外のメモリに置き、前のブロックを計算している間に必要な行を取り寄せる設計にできると、[論文](https://arxiv.org/abs/2601.07372)の 2.5 節は述べています。行番号のそろえ方とハッシュの計算は V4.1-Flash の[参照実装](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash/blob/2cba9e42aa026125f3ed06c6d98c1db82f7ca027/inference/engram.py)と同じで、同じ設定なら同じ行番号が出ることを、この実験の[テストのコード](https://github.com/littlemex/zenmai-lab/blob/7d12d417f789173aa7082d4739c297d08116ad24/experiments/2026-10-21-engram-nanogpt/tests/test_engram_lm.py)で確かめています。以下、例文「Only Alexander the」の最後の「the」の位置で、7 つの手順を順に見ます。この位置の正解の次のトークンは「Great」です。

### 手順 1: トークンの番号をそろえる

Engram は、大文字と小文字や前の空白などだけが違うトークンを、1 つの番号にまとめてから並びを作ります。

![前に空白のある The の 383、前に空白のある the の 262、空白の無い The の 464、空白の無い the の 1169 が、どれもそろえ直した番号 231 になる。GPT-2 の 50,257 個のトークンが 32,962 個の番号にまとまる](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/compress.png)

GPT-2 のトークナイザでは、「 the」のように前の空白を含めて 1 トークンになるので、文頭の「The」と文中の「 the」は別の番号です。別の番号のままだと、同じ並びの知識が表の別々の行に分かれます。まとめた番号は行を選ぶためだけに使い、GPT の本体が読むトークンと当てるトークンは、GPT-2 の 50,257 個のままです。

### 手順 2〜4: 並びから 16 行を選んで読む

続けて並んだ N 個のトークンの組を N-gram と呼びます。今の位置で終わる 2-gram から 8 個、3-gram から 8 個、計 16 個の行番号を計算し、16 行すべてを読みます。

![例文 Only Alexander the で、位置 t を the に置く。3-gram は Only Alexander the、2-gram は Alexander the。それぞれから 1 つの数を計算し、8 個のヘッドで 8 行ずつ選ぶ。表は 65,537〜65,651 行の 16 個の範囲に分かれ、選んだ 16 行をつないで 1,024 個の数の e_t にする。行番号は公開したモデルで記録した、範囲の中での番号](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/hash.png)

並びの種類は多すぎて、1 つずつに行を用意できません。そこで、並びから決まった計算で 1 つの大きな数を作ります。この計算をハッシュと呼び、同じ並びからはいつも同じ数が出ます。この記事のモデルでは、そろえた番号に、何個前のトークンかごとに違う奇数を掛け、XOR というビットの計算で重ねます。1,049,422 行の表は 16 個の範囲に区切ってあり、範囲の行数は 65,537〜65,651 の、どれも違う素数です。大きな数をその範囲の素数で割った余りが、範囲の中の行番号になります。1 つの範囲で 1 行を選ぶこの割り算 1 回分を、ここではヘッドと呼びます。論文はヘッドを別々のハッシュ関数として書いていて、この実装と V4.1-Flash は、同じ数を違う素数で割ることでそれを作っています。

別の並びが、あるヘッドで同じ行に当たることがあり、これを衝突と呼びます。8 個のヘッドは違う素数で割るので、1 つのヘッドで衝突しても、ほかのヘッドでは別の行になりえます。ただし、割る前の大きな数がたまたま同じなら、8 個とも同じ行になります。読んだ 16 行は 64 個ずつの数なので、順に並べてつなぐと 1,024 個の数のベクトル $\mathbf{e}_t$ になります。

### 手順 5〜7: 足す量を決めて足す

読んだ 16 行は、今の文脈に合うとは限らないので、ゲートという 0 から 1 の数で足す量を決めます。

![16 行をつないだ e_t を、重み W_K と W_V で 512 個ずつの value と key に変える。key とブロック 0 の後の隠れ状態 h_t からスコア s_t を出し、0 から 1 のゲート α_t にする。h_t に α_t を掛けた value を足してブロック 1 に渡す。例文の the の位置では α は 0.88](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/gate.png)

$\mathbf{e}_t$ に学習で決まる重みを掛けて、隠れ状態と同じ 512 個の数のベクトルを 2 本作ります。key の $\mathbf{k}_t$ は今の文脈と比べるためのもので、value の $\mathbf{v}_t$ は隠れ状態に足す中身です。ゲートは、今の文脈を表す隠れ状態 $\mathbf{h}_t$ と key を比べた点数が高いほど 1 に近づき、value を多く足します。

$$
s_t = \frac{1}{\sqrt{d}} \sum_{i=1}^{d} w_i \, \hat{h}_{t,i} \, \hat{k}_{t,i},\qquad
\alpha_t = \sigma\!\left(\operatorname{sign}(s_t)\sqrt{|s_t|}\right),\qquad
\mathbf{h}_t \leftarrow \mathbf{h}_t + \alpha_t \mathbf{v}_t
$$

$\hat{\mathbf{h}}_t$ と $\hat{\mathbf{k}}_t$ は、ベクトルの大きさをそろえる RMSNorm という計算を通した $\mathbf{h}_t$ と $\mathbf{k}_t$ で、$d$ は 512 です。$\hat{h}_{t,i}$ はベクトルの $i$ 番目の数で、$w_i$ は学習で決まる重みです（実装では、別々に学習する 2 つの重みの積）。$\operatorname{sign}(s_t)\sqrt{|s_t|}$ は、符号を残したまま大きさの平方根を取る計算です。$\sigma$ はどんな数も 0 から 1 に変えるシグモイド関数です。ゲートは 16 行のどれが衝突したかを見分けるのではなく、16 行から作った value 全体をどれだけ足すかを決めます。例文の「the」の位置では、$\alpha_t$ は 0.88 でした。論文の式 (4) には平方根がありませんが、V4.1-Flash の[参照実装の model.py](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash/blob/2cba9e42aa026125f3ed06c6d98c1db82f7ca027/inference/model.py) に合わせて入れています。式では、$|s_t|$ が 0 に近すぎるときに付ける小さな下限を省きました。

## 小さな GPT に組み込んで学習させる

Engram の効き目を見るため、同じ GPT の本体に Engram を足したモデルと足さないモデルを、ほかの条件をそろえて学習させました。

### 作るモデル

12 ブロックの GPT の、ブロック 0 とブロック 1 の間に Engram を 1 つ入れます。行番号は、ブロック 0 を計算する前に全部の位置の分を先に計算しておきます。

![12 ブロックの GPT。トークンの番号から、ブロック 0 の前にハッシュで 16 個の行番号を計算しておき、ブロック 0 とブロック 1 の間の Engram に渡す](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/placement.png)

本体は、OpenAI の GPT-2 型のブロックを 12 個重ねたもので、隠れ状態は 1 位置 512 個の数、一度に読む文脈は 512 トークンです。ブロックの番号は 0 から数えます。Engram を 2 番目のブロック（ブロック 1）の前に置いたのは、論文の 6.2 節が、12 層のモデルで 1 か所だけ置くなら 2 番目の層が最も良かったと報告しているからです。論文の Engram にある、ゲートを掛けた value を隠れ状態に足す前に通す短い畳み込みと、隠れ状態の流れを 4 本に分けてそれぞれにゲートを持つ仕組みは入れていません。V4.1-Flash も短い畳み込みは入れていません。[Engram の層](https://github.com/littlemex/zenmai-lab/blob/7d12d417f789173aa7082d4739c297d08116ad24/experiments/2026-10-21-engram-nanogpt/engram_lm/engram.py)と[モデル全体](https://github.com/littlemex/zenmai-lab/blob/7d12d417f789173aa7082d4739c297d08116ad24/experiments/2026-10-21-engram-nanogpt/engram_lm/model.py)のコードは公開しています。

| 部品 | この記事のモデル | DeepSeek-V4.1-Flash |
|---|---|---|
| N-gram とヘッド | 2-gram と 3-gram、8 個ずつ、計 16 行 | 2〜4-gram、8 個ずつ、計 24 行 |
| 表 | 1,049,422 行 × 64、6,716 万個の重み | 1 層あたり 384,006,168 行 × 256 |
| 置く場所 | ブロック 1 の前の 1 か所 | ブロック 1 と 14 の前の 2 か所 |

### 学習の 1 歩

学習では、モデルの予想と正解を比べ、外れが小さくなるように、Engram の表も含むすべての重みを少しずつ直します。

![文章から 512 トークンの窓を 128 個取り出し、モデルが次のトークンの確率を出し、正解との外れ具合の損失から勾配を求め、すべての重みを直す。これを 3,600 回繰り返す](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/training-step.png)

文章から 512 トークンの区切り（窓）を、重なりを許して無作為に取り出し、32 窓ずつ 4 回に分けて読み、計 128 窓分の勾配をためてから重みを 1 回直します。モデルは各位置で次のトークンの確率を出し、正解のトークンとの外れ具合が損失です。重みを少し動かすと損失がどう変わるかを表すのが勾配で、勾配を使って重みを直すことを 3,600 回繰り返し、2.36 億トークンを学習しました。表の行は最初は乱数で、その回に読まれた行に勾配が届きます。一度も読まれない行は、最初の乱数のままです。

### 比べ方

2 つの学習は、GPT の本体のはじめの重み、読む文章とその順番、学習量をそろえ、違いを Engram の有無にしました。Engram の分だけ、重みの総数は多くなります。

![左の Engram なしと右の Engram ありで、学習を始める前の本体の重み、読む文章の順番、2.36 億トークンの学習量と AdamW の設定が同じ。右だけに Engram の 6,821 万個の重みがあり、表は本体の 5 倍の学習率で weight decay なしの Adam で学習する。重みの総数は約 6,380 万と約 1 億 3,200 万](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/comparison.png)

重みのはじめの値を決める乱数の seed を 2 つの学習で同じにしたので、本体は同じ重みから始まり、読む文章の順番も同じです。本体と、Engram の key と value とゲートの重みは、AdamW という方法で、1 回に重みを動かす幅（学習率）を 6e-4 まで上げてから 6e-5 まで下げて直します。Engram の表だけは、論文の 4.1 節と同じく Adam で、その時点の本体の学習率の 5 倍にし、重みを縮める weight decay を掛けません。Engram ありは重みが 6,821 万個多いので、同じ大きさのモデルどうしの比較ではありません。

学習には、Amazon EKS の上の NVIDIA RTX PRO 4500 Blackwell を 1 つの学習に 1 枚使い、16 ビットの数を混ぜて計算を軽くする bfloat16 の混合精度で、PyTorch 2.9.1 と CUDA 12.8 の環境でモデルをコンパイルして学習しました。学習の速さは、検証と保存の時間を除いた値です。文章は Wikipedia から作られた WikiText-103 で、seed を 1337、1338、1339 の 3 通りに変えて、2 つのモデルを 3 回ずつ学習させました。

## 学習の結果

Engram ありは、学習の序盤に損失を早く下げましたが、学習を終えた後の性能の差は小さく、テストではほぼ同じでした。

### 学習中の損失

![上の段は 6 回の学習の検証の損失で、Engram ありは実線と丸、Engram なしは破線と四角。下の段は同じ seed どうしの差で、0 より下なら Engram ありが低い。約 2,600 万トークンで -0.20〜-0.23、8,000 万トークン前後でほぼ 0、1 億トークンから最後まで -0.008〜-0.030](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/val-loss.png)

検証の損失は、学習に使っていない検証用の文章で測った損失で、低いほど予想が良いことを表します。約 2,600 万トークンを学習した時点では、Engram ありの損失が、同じ seed の Engram なしより 0.20〜0.23 低くなりました。差は 8,000 万トークン前後でほぼ 0 になり、1 億トークンから最後までは、3 つの seed とも 0.008〜0.030 の差で Engram ありが低いままでした。

### 学習後の性能

学習を終えたモデルでは、検証用の文章で Engram ありがわずかに良く、テスト用の文章ではほぼ同じでした。

| | Engram あり | Engram なし |
|---|---|---|
| 重みの数 | 1 億 3,198 万（うち表 6,716 万） | 6,377 万 |
| 検証のパープレキシティ | 28.97 ± 0.08 | 29.26 ± 0.01 |
| テストのパープレキシティ | 29.40 ± 0.16 | 29.36 ± 0.13 |
| 学習の速さ（1 秒あたりのトークン） | 149,543 | 155,677 |

パープレキシティは、正解のトークンにどれだけ高い確率を付けられたかを表す値で、低いほど良く、平均の損失 $\overline{L}$ から $\exp(\overline{L})$ で出します。検証用とテスト用の文章は、どちらも学習に使っていない、WikiText-103 の別々の部分です。値は 3 つの seed の平均で、± の後は seed によるばらつき（標準偏差）です。評価は学習の最後の重みで、文章を重ならない 512 トークンの窓に切り、窓ごとに前の文脈を持たずに測りました。検証では Engram ありが Engram なしより平均 1.0% 低く、3 つの seed のどれでも低い値でした。テストではほぼ同じで、同じ seed どうしでは Engram ありが 0.06、0.06、0.00 高い値でした。1 秒に学習できるトークンは、Engram なしより 3.9% 減りました。

### Engram を外すと

学習を終えた Engram ありのモデルで、評価のときだけ表引きの足し算（隠れ状態に α と value の積を足す部分）を飛ばして測りました。

![検証のパープレキシティの 3 つの seed の平均。Engram ありのモデルが 28.97、同じ重みで評価のときだけ表引きを外すと 59.54、Engram なしで学習したモデルが 29.26。斜線、点、× の格子の棒](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/engram-off.png)

検証のパープレキシティは、3 つの seed の平均で 28.97 から 59.54 になり、外す前の約 2.1 倍になりました。最初から Engram なしで学習したモデルは 29.26 です。学習を終えたモデルは、表引きの出力を使う前提で組み上がっていると読めます。学習に使った条件を後から変える操作なので、この値から、表が何を覚えているかまでは分かりません。

## 1 つの文で中身を追う

学習済みのモデルに 1 つの文を読ませ、ブロックごとの予想を取り出して、3 通りを比べました。Engram ありのモデル、その重みのまま表引きだけ外した場合、最初から Engram なしで学習したモデルです。

![例文 Only Alexander the の the の位置で、ブロックごとの次のトークン Great の確率。Engram ありは実線と丸で、最後は 0.971。同じ重みで表引きを外すと点線と三角で、最後まで 0.033 以下。Engram なしで学習したモデルは破線と四角で、最後は 0.158。seed 1337 のモデルの 1 か所の値](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/alexander-blocks.png)

ふつう、次のトークンの確率を出す計算は、最後のブロックの後にしか付いていません。これを途中のブロックの後にも付けると、そこで止めたら何を予想したかが分かります。論文も 6.1 節で使った LogitLens という方法です。値は seed 1337 のモデルのものです。候補は 5 万個あって確率が広く散らばるので、確率が数 % でも 1 位になることがあります。

| 比べたモデル | 「Great」が 1 位になったブロック | 最後の「Great」の確率 |
|---|---|---|
| Engram あり | ブロック 3 の後から最後まで | 0.971 |
| Engram ありの重みで、表引きだけ外す | ブロック 10 の後だけ | 0.018（最後の 1 位は「King」） |
| Engram なしで学習したモデル | ブロック 8 の後から最後まで | 0.158 |

表引きを足した直後のブロック 1 の後では、「Great」の確率はまだ 0.053 で、同じ重みで表引きを外した場合の 0.001 より高いものの、1 位ではありません。その後のブロックで確率が上がりました。表引きがどの情報を渡し、どのブロックがそれをどう使ったかは、この記録だけでは分かりません。

## ほかの文と文章全体で見る

1 つの位置で見えた違いが、ほかの位置や文章全体でもあるかを、ゲートの値と、途中の予想の 2 つで確かめました。

### ゲートは位置ごとに違う

ゲートは、表引きの結果をどれだけ足すかを、位置ごとにモデル自身が決めた値です。ここだけ、実験の[リポジトリに入れた記録](https://github.com/littlemex/zenmai-lab/blob/7d12d417f789173aa7082d4739c297d08116ad24/experiments/2026-10-21-engram-trace-viewer/viewer/traces/nanogpt-hastings.json)の、ヘイスティングズの戦いの文を使います。

![The Battle of Hastings で始まる 44 トークンの文で、seed 1337 の Engram ありのモデルの位置ごとのゲート α。多くの位置で 0.5 を超え、William、Normandy の後の読点、Harold の 3 か所だけ 0.19〜0.22。白い太枠と値で示した](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/gate-text.png)

WikiText-103 はハイフンを「@-@」と書き、長い名前は「God」「w」「inson」のように何トークンかに分かれるので、図の横軸にはそうしたトークンが並びます。44 か所のうち 41 か所でゲートが 0.5 を超え、人名の William と Harold、Normandy の後の読点の 3 か所だけが 0.19〜0.22 でした。検証用の文章の最初の 200 窓では、3 つの seed の平均で、ゲートの平均は 0.66、0.5 を超えた位置は 74% でした。

### 途中の予想が最後に近づく速さ

検証用の文章の最初の 200 窓で、途中のブロックの予想が、そのモデル自身の最後の予想にどれだけ近いかを測りました。

![検証用の文章の最初の 200 窓で、ブロックごとの仮の予想と、同じモデルの最後の予想との違いを KL で測った値。Engram ありは実線と丸で、ブロック 0 の後は 5.04、ブロック 1 の後は 2.91 で、ブロック 10 まで Engram なしより低い。Engram なしは破線と四角で、ブロック 0 から 4 までほぼ 4。3 つの seed の平均と標準偏差](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/logit-lens-kl.png)

KL ダイバージェンス（KL）は、2 つの確率の並びがどれだけ違うかを表す 0 以上の値で、同じなら 0 です。ここでは最後の予想 $p_{\mathrm{final}}$ を基準に、ブロック $l$ の後の予想 $p_l$ を比べた値 $D_{\mathrm{KL}}(p_{\mathrm{final}} \,\|\, p_l)$ を、10 万 2,400 か所で平均し、3 つの seed で平均しました。最後のブロックの後は最後の予想そのもので 0 になるので、図から省いています。Engram ありは、表引きを足した後のブロック 1 の後で 2.91 になり、同じブロックの Engram なしの 3.94 より低く、ブロック 10 まで低いままでした。表引きを足す前のブロック 0 の後だけは、Engram ありが 5.04 で、Engram なしの 4.01 より高い値です。KL が小さいことは、予想が正しいことと同じではありません。

### 1 位の候補が固まるブロック

各位置で、1 位の候補がどのブロックから最後まで変わらなくなったかを、検証用の文章の 483 窓すべて、seed あたり 247,296 か所で数えました。

![1 位の候補がそれ以上変わらなくなったブロックの割合。ブロック 1 で固まった位置は、Engram ありが 14.5%、同じ重みで表引きを外すと 8.7%、Engram なしで学習したモデルが 4.8%。斜線、点、× の格子の棒で区別。3 つの seed の平均](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/settling.png)

ブロック 1 で固まった位置は、Engram ありが 14.5% で、Engram なしで学習したモデルの 4.8% のおよそ 3 倍でした。固まったブロックの平均は、Engram ありが 6.27、Engram なしが 7.04 です。[集計のコード](https://github.com/littlemex/zenmai-lab/blob/7d12d417f789173aa7082d4739c297d08116ad24/experiments/2026-10-21-engram-nanogpt/engram_lm/settling.py)は、最後のブロックまで見た後で、1 位が変わらなくなったブロックを数えます。固まった後のブロックも計算され、確率は変わり続けるので、そこで計算を止められるという意味ではありません。この集計は GPU の上の bfloat16 の混合精度で、1 つの文の記録は CPU の float32 で計算したので、同じ位置でも値がわずかに違うことがあります。

早く固まることは、自信があることとも違います。両方のモデルが最後に正解し、Engram ありのほうが早く固まった位置だけを集めました。固まった時点の 1 位の確率は、Engram ありが 0.39、Engram なしが 0.48 で、早く固まった側のほうが低い値でした。どちらも seed ごとの中央値の平均です。また、同じ重みで表引きを外しても、ブロック 1 で固まる位置は 8.7% あり、Engram なしの 4.8% より多くなります。早く固まる理由が表引きだけにあるとは、この数からは言えません。

## 自分で動かす

公開した学習済みのモデルと、1 つの文の中身を画面で追うページを使うと、ここまでの観察を自分の文で試せます。

![動作確認のページの日本語表示の一部。左に文と、トークンごとに 1 位の候補が固まったブロックを 2 つのモデルで並べた図、右に選んだ the の位置での表引き（Alexander the と Only Alexander the で 1,049,422 行から 16 行を読み、混ぜる強さ 88%）が並ぶ](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/ladder-ja.png)

ページは英語と日本語を切り替えられ、図は日本語の表示です。画面の「段」はこの記事のブロックで、「混ぜる強さ」はゲート α です。左は、トークンごとに 1 位の候補が固まったブロックを 2 つのモデルで並べた図で、右は、選んだ位置での表引きの中身と、表引きの有無で変わる 1 位の候補です。ページでは、その下にブロックごとの上位 5 候補も並びます。モデルは [Hugging Face の littlemex/engram-nanogpt-wikitext103](https://huggingface.co/littlemex/engram-nanogpt-wikitext103) に、6 回の学習の分を置いてあります。

:::details この記事の例文を記録して、画面で開く手順
Python 3 と [uv](https://docs.astral.sh/uv/) を使います。モデルのファイルは 2 つで約 785 MB です。記録は CPU で動き、手元の Mac では記録のコマンドだけで 17 秒でした（ダウンロードを除く）。

```bash
git clone https://github.com/littlemex/zenmai-lab.git
cd zenmai-lab
git checkout 7d12d417f789173aa7082d4739c297d08116ad24
cd experiments/2026-10-21-engram-nanogpt
export SEED=1337
uv run --python 3.11 --with-requirements requirements.txt hf download littlemex/engram-nanogpt-wikitext103 --revision e9758158ad0d180336bc059e20fecf29f67f445b --include "*-seed$SEED/model.safetensors" --local-dir hub
uv run --python 3.11 --with-requirements requirements.txt python -m engram_lm.record_trace --engram hub/engram-seed$SEED/model.safetensors --baseline hub/baseline-seed$SEED/model.safetensors --prompt " Only Alexander the Great could tame the horse" --new-tokens 20 --title "Alexander the Great (seed $SEED)" --out ../2026-10-21-engram-trace-viewer/viewer/traces/alexander.json
cd ../2026-10-21-engram-trace-viewer/viewer
python3 -m http.server 8000 --bind 127.0.0.1
```

記録が終わると、次の 1 行が出ます。

```
wrote ../2026-10-21-engram-trace-viewer/viewer/traces/alexander.json: 28 tokens (20 generated)
```

サーバーを動かしたまま、ブラウザで `http://127.0.0.1:8000/ladder.html?trace=traces/alexander.json&lang=ja` を開きます。`--prompt` を変えると自分の文で試せます。WikiText-103 の書き方に合わせて、句読点の前後に空白を置き、ハイフンを ` @-@ ` と書くと、学習の文章に近い形になります。止めるときは、サーバーを動かしている端末で Ctrl+C を押します。
:::

## まとめ

Engram は、トークンの番号だけで読む行を先に決め、読んだ数をゲートで量を決めて隠れ状態に足す部品です。12 ブロック、2.36 億トークンのこの実験では、Engram ありのモデルは序盤の損失を早く下げ、1 位の候補がブロック 1 で固まる位置も多くなりました。一方、学習を終えた後のテストのパープレキシティは、Engram なしとほぼ同じでした。次の点は、この実験ではまだ確かめていません。

| 確かめていないこと | 理由 |
|---|---|
| 表を GPU の外に置き、計算と重ねて取り寄せられるか | この記事の実装は表を GPU に置き、取り寄せの仕組みを作っていない |
| この記事の小さな GPT で、ブロック 1 の前が最も良い置き場所か | 置く場所を変えた学習をしていない |
| 表の行が具体的に何を覚えているか | 行の中身を言葉に戻す方法をまだ試していない |
| ゲートが低い位置に共通点があるか | 1 つの文の 3 か所しか見ていない |
| 重みの総数をそろえた比較で Engram が勝つか | この記事の比較は Engram の分だけ重みが多い |
| もっと大きなモデルや長い学習で結果が変わるか | 12 ブロック、2.36 億トークンの 1 通りだけ |

論文の結果の詳しい読み方は「[Engram は何を覚えて、どう引くのか](https://zenn.dev/tosshi/articles/5853108f53bd7f)」に、大きな表を何台かに分けて持つ方法は「[Engram の表を何台かに分けて引く](https://zenn.dev/tosshi/articles/54aced4bdcb137)」に書きました。
