## はじめに

「[Engram は何を覚えて、どう引くのか](https://zenn.dev/tosshi/articles/5853108f53bd7f)」では、DeepSeek の Engram の仕組みを、論文と DeepSeek-V4.1-Flash から読み解きました。読むだけでは、Engram があると何が変わるのかを確かめられません。この記事では、小さな GPT に Engram を組み込み、Engram があるモデルと無いモデルを、ほかの条件をそろえて学習させて比べます。

トークン、層、隠れ状態、損失といった言葉は、前の記事の「LLM は次のトークンを当てる」の節で説明しました。この記事では、学習の進め方から説明します。

## 作る順番

![WikiText-103 の文章を GPT-2 のトークナイザでトークンの番号にする。12 層の GPT の本体を作り、層 0 と層 1 の間に Engram を入れる。本体だけのモデルと、本体に Engram を足したモデルの 2 つを同じ条件で学習させ、学習に使っていない文章で評価する](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/build-steps.png)

作業は 4 つあります。1 つ目は、文章を用意して、トークンの番号に変えることです。2 つ目は、モデルを作ることです。12 層の GPT を作り、Engram を 1 か所に差し込みます。3 つ目は、Engram ありと無しの 2 つを、同じ条件で学習させることです。4 つ目は、学習に使っていない文章で、2 つの予想の良さを比べることです。

コード、設定、結果は、[この実験のディレクトリ](https://github.com/littlemex/zenmai-lab/tree/a191b5759329986decf9ebdfa28a6669ff34e36f/experiments/2026-10-21-engram-nanogpt)にまとめてあります。

## 学習の 1 歩

![文章から 512 トークンの窓を 128 個取り出し、モデルが各位置で次のトークンの確率を出す。正解のトークンとの外れ具合を損失にし、重みを変えると損失がどう変わるかを勾配として求め、勾配と学習率を使って重みを直す。これを 1 ステップとして繰り返す](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/training-step.png)

学習は、同じ手順の繰り返しです。文章から 512 トークンの区切り（窓）を取り出し、モデルに読ませます。モデルは、窓の各位置で、次のトークンの確率を出します。本当の次のトークンとの外れ具合が、損失です。この実験では、32 個の窓ずつ 4 回計算した勾配をためて、128 個の窓の分で重みを 1 回直します。1 回で 65,536 トークンを学習することになります。

次に、それぞれの重みを少し動かすと損失がどう変わるかを計算します。これを勾配と呼びます。勾配は損失が増える向きを指すので、いちばん簡単な直し方では、その逆向きに重みを少し動かします。直す量の大きさを調整する係数が、学習率です。重みを 1 回直すことを学習の 1 ステップと呼び、この実験では 3,600 回繰り返します。

重みの直し方の決まりを、最適化手法と呼びます。この記事では Adam と AdamW という手法を使います。どちらも、最近の勾配ほど重く見た勾配の平均と、勾配を 2 乗した値の平均を覚えておき、それを使って重みごとに直す向きと量を調整します。AdamW は、そのほかに重みを少し縮める処理（weight decay）を、勾配による直しとは別に加えます。

## 作るもの

![12 層の GPT の層 0 と層 1 の間に Engram を 1 つ入れる。Engram は、そろえ直したトークン番号から 2-gram と 3-gram を 8 通りずつハッシュして 16 個の行番号を作り、1,049,422 行 × 64 の表から読み、重み W_K と W_V で key と value に変え、層 0 の後の隠れ状態 h と key からゲート α を求め、α を掛けた value を h に足す。最後の層の後で次のトークンの確率を出す](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/model.png)

作るのは、12 層の GPT-2 型のモデルです。GPT-2 型は、OpenAI の GPT-2 と同じ並びの層でできたモデルという意味です。層の番号は 0 から数えるので、層 0 が 1 番目、層 11 が 12 番目の層です。1 つの位置の隠れ状態は 512 個の数で、一度に読む文脈は 512 トークンです。重みは全部で 6,377 万個です。

Engram は 1 つだけ、2 番目の層（層 1）の入口に入れます。層 0 の計算が終わった後、層 1 の Attention の前です。[論文](https://arxiv.org/abs/2601.07372)の 6.2 節は、Engram を 1 か所だけ置くなら 2 番目の層が最も良かったと報告しており、それに合わせました。図では、層を block と書いています。

Engram の表引きとゲートの部分は、DeepSeek-V4.1-Flash の参照実装にそろえました。表の大きさ、N-gram の長さ、Engram を置く数は小さくし、取り入れていない部品もあります。トークンの番号のそろえ直しは、Engram の行番号を決めるためだけに使います。モデル本体が読むトークンと、当てるトークンの種類は、GPT-2 の 50,257 個のままです。実装は [Engram の部分](https://github.com/littlemex/zenmai-lab/blob/a191b5759329986decf9ebdfa28a6669ff34e36f/experiments/2026-10-21-engram-nanogpt/engram_lm/engram.py)と[モデル全体](https://github.com/littlemex/zenmai-lab/blob/a191b5759329986decf9ebdfa28a6669ff34e36f/experiments/2026-10-21-engram-nanogpt/engram_lm/model.py)にあります。

| 部品 | この記事のモデル | DeepSeek-V4.1-Flash |
|---|---|---|
| トークンの番号のそろえ直し | GPT-2 の 50,257 個のトークンを、大文字小文字や空白の違いをまとめて 32,962 個にします | 同じ手順です。V4.1-Flash の参照実装の手順を GPT-2 のトークナイザに当てた出力と一致することを、[テスト](https://github.com/littlemex/zenmai-lab/blob/a191b5759329986decf9ebdfa28a6669ff34e36f/experiments/2026-10-21-engram-nanogpt/tests/test_engram_lm.py)で確かめました |
| N-gram とハッシュ | 2-gram と 3-gram を 8 通りずつハッシュして、計 16 個の行番号にします | 同じ式です。同じ設定なら行番号が一致することをテストで確かめました |
| 表 | 1,049,422 行 × 64、6,716 万個の重み | 層ごとに約 3 億 8,400 万行 × 256 |
| ゲートと足し込み | 読んだ 16 行をつなぎ、重み $W_K$ と $W_V$ を掛けて key と value に変えます（前の記事と同じ式）。key と隠れ状態の近さでゲート α を決め、α を掛けた value を隠れ状態に足します | 同じ式です |
| 入れない部品 | 残差の流れを 4 本に分ける hyper-connections と、短い畳み込み | 短い畳み込みは V4.1-Flash も入れていません。hyper-connections の有無は、ここでは比べていません |

## 比べ方

![2 つの学習は、学習を始める前の本体の重み、学習データの順番、2.36 億トークンの学習量、本体の最適化の設定が同じ。Engram ありだけに 6,821 万個の重みの Engram があり、表は 5 倍の学習率で weight decay なしの Adam で学習する。重みの総数は Engram ありが約 1 億 3,200 万、なしが約 6,380 万で、そろえていない](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/comparison.png)

比べたいのは、同じモデルに Engram を足すと何が変わるかです。**Engram を足したことによる違いを見るために、本体の条件を 2 つの学習でそろえました**。学習の始めの重みは、乱数の種という数から作ります。この実装では、本体の重みを作ったあとに、Engram の重みを別の乱数の流れで作ります。そのため、同じ種なら、2 つのモデルの本体は同じ重みから始まります。このことは[テスト](https://github.com/littlemex/zenmai-lab/blob/a191b5759329986decf9ebdfa28a6669ff34e36f/experiments/2026-10-21-engram-nanogpt/tests/test_engram_lm.py#L133-L145)で確かめています。読む文章の順番も、同じ種で決めるのでそろいます。そろえたのは本体の構成と初期の重み、読む文章の順番、学習するトークンの数、本体の学習の設定です。

本体と、Engram の key と value とゲートの計算の重みは、AdamW で学習します。学習率は、最初の 300 ステップで 0 に近い値から 6e-4（0.0006）まで上げ、その後は なめらかな曲線（cosine）で 6e-5 まで下げます。weight decay は、重みが大きくなりすぎないように少しずつ縮める設定です。縮める強さの係数は、行列の形の重みでは 0.1 です。1 ステップで縮む割合は、その時点の学習率に 0.1 を掛けた値で、最大でも 0.00006 です。正規化の係数など、数が 1 列に並ぶ 1 次元の重みは縮めません。Engram の表だけは、[論文](https://arxiv.org/abs/2601.07372)の 4.1 節と同じく Adam で、その時点の学習率の 5 倍で、weight decay なしで学習させます。

勾配が大きすぎると、1 回で重みが大きく動きすぎます。そこで、重みを本体、Engram の key と value とゲートの計算、表の 3 つの組に分け、組ごとに勾配の大きさ（ノルム）が 1.0 を超えたら 1.0 まで縮めます。これをクリップと呼びます。こうすると、本体の縮め方が、Engram の勾配の大きさに左右されません。

Engram ありのほうが、重みが 6,821 万個多くなります。表の 6,716 万個と、key と value とゲートの計算の 105 万個の合計です。重みの総数をそろえた比較ではないので、「同じ大きさのモデルで Engram が勝った」とは言えません。増えた重みの大部分は表で、1 トークンあたりに使うのは、そのうち 16 行（$16 \times 64 = 1{,}024$ 個の数）だけです。乱数の種を 3 つ変えて学習させ、差が種による揺れより大きいかを確かめます。

学習には、Amazon EKS（AWS でコンテナを動かすサービス）の上の NVIDIA RTX PRO 4500 Blackwell という GPU を 2 枚使い、1 枚に 1 つのモデルを載せました。文章は、Wikipedia の記事から作られた WikiText-103 で、GPT-2 のトークナイザ（文章をトークンに分けて番号を付ける道具）で 1 億 1,795 万トークンになります。学習させるのは 2.36 億トークンで、文章全体のおよそ 2 倍です。窓は文章から無作為に取り出すので、ちょうど 2 周するわけではありません。

## 学習中と学習後の結果

![上の段は 6 つの学習の検証の損失で、低いほど良い。種ごとに線の形を変えている。下の段は同じ種どうしの差で、Engram ありから Engram なしを引いた値。0 より下なら Engram ありの損失が低い。約 2,600 万トークンの時点で -0.20 から -0.23、8,000 万トークン前後でほぼ 0、1 億トークン以降は -0.008 から -0.030。図は、最初の 1 回の更新の直後に行った評価を省いている](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/val-loss.png)

検証の損失は、学習に使っていない文章で測った損失です。低いほど、次のトークンの予想が良いことを表します。図の下の段は、同じ種どうしの差で、0 より下なら Engram ありのほうが良い値です。

同じ種どうしの検証の損失の差は、学習の序盤で大きくつきました。記録の番号で 400 ステップ目（番号は 0 から始まるので、401 回の更新を終えた時点）、約 2,600 万トークンを学習した時点で、Engram ありは Engram なしより 0.20〜0.23 低くなりました。評価は 200 ステップおきです。Engram ありが 400 ステップ目に出した損失に、Engram なしが届く時点を、評価の点の間を直線でつないで推定しました。答えは記録の番号で 480〜490 ステップ目で、Engram ありは 2 割弱少ないステップで同じところまで来たことになります。ただし、400 と 600 の間は測っていないので、実際に届く時点は、この推定から前後するかもしれません。

差はいったん縮み、8,000 万トークン前後でほぼ 0 になりました。種 1337 では、この辺りでわずかに Engram ありのほうが高い値でした。その後は再び Engram ありが低くなり、1 億トークンから最後まで、3 つの種とも -0.008〜-0.030 の差でした。最後の差は -0.008〜-0.013 です。評価ごとの損失は、[summary.json](https://github.com/littlemex/zenmai-lab/blob/a191b5759329986decf9ebdfa28a6669ff34e36f/experiments/2026-10-21-engram-nanogpt/results/summary.json) に入っています。

学習を終えた後の結果は次のとおりです。この実験の損失は、正解のトークンに付けた確率の自然対数の符号を変えた値です。正解に付けた確率が 1 なら損失は 0 で、確率が小さいほど損失は大きくなります。パープレキシティは、評価したトークンの平均の損失 $\overline{L}$ から、次の式で出します。

$$
\mathrm{PPL} = \exp(\overline{L})
$$

たとえば、どの位置でも正解に 10 分の 1 の確率を付けていれば、パープレキシティは 10 になります。低いほど、正解のトークンに高い確率を付けられたことを表します。実際に候補をその数まで絞っているという意味ではなく、予想の外れ具合の目安です。検証データは、学習の途中で進み具合を見るための文章で、テストデータは、最後の性能を確かめるために分けておいた文章です。どちらも重みを直すのには使っていません。評価には、学習を終えた最後のステップの重みを使いました。パープレキシティは、文章を重ならない 512 トークンの窓に切り、窓ごとに前の文脈を持たずに測った値です。別の窓の切り方で報告された WikiText-103 の値とは、そのまま比べられません。パープレキシティは 3 つの種の平均で、「±」の後の数は種によるばらつき（3 つの値から求めた標準偏差）です。学習の速さは、1 秒に学習したトークンの数の 3 つの種の平均です。

| | Engram あり | Engram なし |
|---|---|---|
| 重みの数 | 1 億 3,198 万（うち表 6,716 万） | 6,377 万 |
| 検証のパープレキシティ | 28.97 ± 0.08 | 29.26 ± 0.01 |
| テストのパープレキシティ | 29.40 ± 0.16 | 29.36 ± 0.13 |
| 学習の速さ | 毎秒 14.954 万トークン | 毎秒 15.568 万トークン |

検証では、3 つの種のどれでも Engram ありのほうが低く、平均で 1.0% 低くなりました。テストでは、平均がほぼ同じでした。この結果から、学習を終えた後の性能が安定して上がるとは言えません。2 つのモデルは、重みの総数も違います。同じ種どうしで比べると、Engram ありが 0.06、0.06、0.00 高い値です（小数第 2 位に丸めた値）。この規模では、学習を終えた後の性能がはっきり上がるとは言えません。1 秒に学習できるトークンの数は、Engram を足した分だけ 3.9% 減りました。検証や途中の保存の時間は含みません。

## Engram を外すと

![学習を終えた Engram ありのモデル、同じモデルで評価のときだけ Engram を外した場合、Engram なしで学習したモデルの検証のパープレキシティ。28.97、59.54、29.26](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/engram-off.png)

学習を終えた Engram ありのモデルから、評価のときだけ Engram の足し込みを外してみました。この操作で分かるのは、学習を終えたモデルが Engram の出力を使う前提になっているかどうかで、Engram が何を受け持っていたかまでは分かりません。結果は、検証のパープレキシティが 28.97 から 59.54 へ、約 2 倍になりました（[値](https://github.com/littlemex/zenmai-lab/blob/a191b5759329986decf9ebdfa28a6669ff34e36f/experiments/2026-10-21-engram-nanogpt/results/summary.json)）。Engram なしで学習したモデルは 29.26 なので、外したモデルは、最初から Engram なしで学習したモデルよりずっと悪くなります。

次に、Engram を付けたままのモデルで、検証の文章の最初の 200 窓、10 万 2,400 か所のゲートを数えました。3 つの種の平均で、ゲートの平均は 0.66、ゲートが 0.5 を超えた位置は 74% でした。多くの位置で、表から読んだ行で作った value に、0.5 を超える係数を掛けて足していたことになります。ゲートが大きいことだけでは、読んだ行の中身までは分かりません。

## 途中の層の予想

![検証の文章の最初の 200 窓で、層ごとに、その層の時点の予想と、同じモデルの最後の予想との違いを KL で比べた図。点は 3 つの種の平均、縦の線は標準偏差。Engram なしは層 0 から層 4 までほぼ 4 のまま。Engram ありは層 0 の後では 5.04 と高いが、層 1 の後では 2.91 で、層 10 まで Engram なしより低い。最後の層 11 は定義上 0 なので省いた](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/logit-lens-kl.png)

途中の層の隠れ状態を、最後の層の後と同じ計算に通すと、その層の時点での仮の予想が出せます。[論文](https://arxiv.org/abs/2601.07372)も 6.1 節で使った LogitLens という方法です。仮の予想と、同じモデルの最後の予想が、どれだけ違うかを KL で測りました。測ったのは、検証の文章の最初の 200 窓、10 万 2,400 か所です（[値](https://github.com/littlemex/zenmai-lab/blob/a191b5759329986decf9ebdfa28a6669ff34e36f/experiments/2026-10-21-engram-nanogpt/results/summary.json)）。

KL（KL ダイバージェンス）は、2 つの確率分布（次のトークンの候補ごとの確率の並び）の違いを表す値です。必ず 0 以上で、2 つが同じときだけ 0 になります。比べる向きを入れ替えると値は変わるので、ここでは最後の予想 $p_{\mathrm{final}}$ を基準に、層 $l$ の仮の予想 $p_l$ を比べます。

$$
D_{\mathrm{KL}}\left(p_{\mathrm{final}} \,\|\, p_l\right)
$$
図の点は 3 つの種の平均で、縦の線は種によるばらつき（標準偏差）です。最後の層 11 は、最後の予想そのものなので 0 になり、図から省きました。

Engram なしでは、層 0 から層 4 までの値が 3.9〜4.1 で、層 5 から下がります。Engram ありでは、層 0 の後の 5.04 から、層 1 の後で 2.91 へ大きく下がりました。層 1 の点は、Engram の足し込みと層 1 の計算の両方を終えた後の値です。同じ層 1 の後の Engram なしは 3.94 で、Engram ありは層 10 まで Engram なしより低いままでした。Engram を足す前の層 0 の後だけは、Engram ありのほうが高く、5.04 対 4.01 です。この差が層 0 の役割の違いを表すのかは、この KL だけでは分かりません。

層 1 から層 10 で Engram ありのほうが小さいことは、Engram が初めの層の組み立てを助け、本体が少ない層で最後の予想の形に近づく、という論文の見方と矛盾しません。ただし層 0 の後では逆で、論文の Figure 4 のように、どの層でも小さいわけではありません。また、この比較だけでは、層の役割の分け方や、必要な層の数までは判断できません。KL が小さいことは、予想が正しいことと同じでもありません。分かるのは、各層の予想が、それぞれのモデル自身の最後の予想にどれだけ近いかです。Engram が何を渡しているかは、この測り方からは分かりません。それを調べるには、具体的な文章ごとに、選んだ行、ゲートの値、予想の変化を記録する必要があります。

## まとめ

この規模では、Engram は、同じトークン数で比べた序盤の損失を早く下げましたが、学習を終えた後のテストのパープレキシティは Engram なしとほぼ同じでした（29.40 と 29.36）。その代わり、重みは約 2 倍になり、1 秒に学習するトークンは 3.9% 少なくなりました。
