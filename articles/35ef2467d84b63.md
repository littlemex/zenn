## はじめに

LLM は、文章をトークンという単位に区切って読み、次のトークンを 1 つずつ当てて文章を書きます。[Engram の論文](https://arxiv.org/abs/2601.07372)は、この仕事を性質の違う 2 種類に分けて考えます。1 つは、文脈を読んで筋道を組み立てる仕事で、深い計算が要ります。もう 1 つは、決まった知識を思い出す仕事です。童話の主人公の呼び名「Little Red Riding Hood」のような名前や地名、決まった言い回しは、短い範囲にまとまっていて、繰り返し同じ形で現れます。

困りごとは、今の LLM の土台である [Transformer](https://arxiv.org/abs/1706.03762) という仕組みに、決まった知識を引いてくる専用の部品が無いことです。LLM は、層と呼ぶ計算を何段も重ねてできています。論文は[ほかの研究](https://arxiv.org/abs/2401.06102)を引いて、よくある名前 1 つを表すのにも、LLM は初めの何層かの計算を使って組み立てていると指摘しています。層の数には限りがあるので、論文は、思い出すだけの仕事に文脈を読むための層を使うのはもったいない、と考えました。

Engram は、この思い出す仕事を、学習した大きな表を引くことで助ける部品です。表を引く手がかりにするのが n-gram です。n-gram は、文章の中で続けて並んだ n 個のトークンのことです。LLM は文章のトークンを 1 つ読むたびに次のトークンを予想するので、予想するときに最後に読んだトークンの場所を、この記事では Current Position、略して **CP**（現在地）と呼びます。図では current position と書いています。

![「The girl was called Little Red Riding」の次の Hood を当てる場面で、 CP  Riding で終わる 1-gram、2-gram、3-gram を並べた図。WikiText-103 の学習用の文章で、Riding の次が Hood だったのは 404 回中 41 回で 10%、Red Riding なら 45 回中 40 回で 89%、Little Red Riding なら 24 回中 24 回で 100%。Engram が引くのは 2-gram と 3-gram](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/engram-ngram.png)

図は、「The girl was called Little Red Riding」の次を当てる場面で、**CP** の「Riding」で終わる n-gram を並べたものです。この記事で学習に使う WikiText-103 の学習用の文章で数えると、「Riding」の 1 個だけだと、次が「Hood」だったのは 404 回中 41 回で、「of」のほうが多く出ます。「Red Riding」の 2 個なら 45 回中 40 回、「Little Red Riding」の 3 個なら 24 回中 24 回が「Hood」でした。並びを 2〜3 個に伸ばすと続きがほぼ決まるので、Engram はこの 2-gram と 3-gram を手がかりに表を引きます。ただし Engram は回数を数えるのではなく、並びごとに学習した数を表から読みます。

論文が挙げる、Engram を使うとうれしいことは 2 つです。

- 初めの層を、文脈を読む仕事に回せると論文は考えています。全体の大きさと計算量をそろえたモデルどうしで比べると、Engram を入れたほうが、知識を問うテストだけでなく、考える力やコードを書く力を問うテストでも点が上がりました。たとえば[論文の要旨](https://arxiv.org/abs/2601.07372)によると、筋道を立てて考える力を問う [BBH](https://arxiv.org/abs/2210.09261) では、100 点満点で 5.0 ポイント高くなっています。論文は中身の分析から、初めの層が決まった並びの組み立てから解放され、層を増やしたような効果が出たと説明しています。
- 表を GPU の外に置けます。GPU は LLM の計算を受け持つ部品で、そのメモリには限りがあります。Engram が表のどこを引くかはトークンの並びだけで決まるので、GPU の外にあるもっと大きなメモリに表を置いても、計算を待たずに先に読み込めます。[論文の 6.4 節](https://arxiv.org/abs/2601.07372)では、40 億個と 80 億個の大きさの 2 つのモデルに、それより大きな 1,000 億個の数を持つ表を付けて GPU の外に置き、文章を処理するときのスループット、つまり 1 秒に処理できるトークン数を測りました。Engram を持たない同じモデルと比べた低下は、大きいほうのモデルでも 2.8% でした。

![左は Engram なしの 6 ブロックで、すべて GPU のメモリにあり、初めの 3 ブロックが名前を組み立て、考えに使えるのは 3 ブロック。右は Engram ありで、トークンの番号だけから 16 個の行番号を決め、CPU 側のメモリに置いたモデルより大きな表から、ブロック 0 を計算している間にその 16 行を取ってきてブロック 1 の前に足す。名前の組み立てはブロック 0 だけで済み、5 ブロックを考えに使える、という論文の見立てを描いた模式図](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/engram-benefits.png)

図は、論文の見立てを、説明のために置いた 6 ブロックで描いた模式図です。ブロックの数と、名前の組み立てに使うブロックの数は、論文の値ではありません。16 個の行番号は、この記事のモデルの数です。表を引く行はトークンの番号だけで決まるので、ブロックの計算を待たずに分かり、表を GPU の外に置いても先に取ってこられます。

Engram は [DeepSeek](https://www.deepseek.com/) と北京大学の研究者が提案し、DeepSeek が公開した LLM の [DeepSeek-V4.1-Flash](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash/tree/2cba9e42aa026125f3ed06c6d98c1db82f7ca027) にも入っています。この記事では、小さな [GPT-2](https://github.com/openai/gpt-2) 型のモデルに Engram を組み込んで学習させ、Engram なしのモデルと比べます。論文と違って全体の大きさをそろえていないことなど、この比べ方で言えないことは「[比較の範囲](#比較の範囲)」の節にまとめました。表引きの中で何が起きているかは、後の節で 1 つの文を使って 1 歩ずつ追います。

## Engram の中身

この節の数は、特に断らない限り、この記事で作ったモデルの値です。

### 課題: 並びが多すぎて、1 つずつに行を持てない

大文字と小文字などの違いをまとめたトークンの番号は 32,962 種類あるので、**CP** で終わる 3-gram は約 36 兆通りありえます。WikiText-103 の学習用の文章に実際に出た 3-gram だけでも 38,249,328 種類ありますが、表は 1,049,422 行しかありません。並び 1 種類ごとに専用の行は持てないので、Engram は並びを決まった計算で行に割り当て、1 つの行を多くの並びで共有させます。

1 行は多くの並びで共有されるので、1 行を見ただけでは、どの並びの行かは分かりません。そこで 2-gram では、8 個の範囲から 1 行ずつ、合わせて 8 行を取ってきて、その 8 行の組み合わせで並びを見分ける、というアプローチを取ります。8 行の組み合わせは 36 兆通りよりはるかに多くあるので、1 行は共有でも、組み合わせなら並びごとにほぼ別々になります。3-gram も同じ作りです。

取ってきた合計 16 行の中身を範囲の順につなぐと、16 × 64 = 1,024 個の数になり、これを学習した行列で作り直して、key と value に分けます。それでも読んだ中身が今の文脈に合うとは限らないので、最後に隠れ状態と 1 回だけ比べて、足す量を決めます。

:::message
**コラム: なぜこの数なのか**

この記事のモデルでは、設定の 65,536 行より大きい素数を小さい順に選んで各範囲の行数にしているので、1 つの範囲は 65,537〜65,651 行、約 6.6 万行あります。8 個の範囲から 1 行ずつ選ぶ組み合わせは約 6.6 万の 8 乗、およそ $3.4 \times 10^{38}$ 通りあります。3-gram のありうる並びの約 $3.6 \times 10^{13}$ 通り、つまり 36 兆通りよりはるかに多い数です。正確には、組み合わせは途中で作る 1 つの大きな数から決まり、その数が取れる値は約 $9.2 \times 10^{18}$ 通りですが、それでも 36 兆通りより十分に多い数です。ただし、組み合わせの数をまかなうだけなら、約 6.6 万の 3 乗で約 $2.8 \times 10^{14}$ 通りになるので、3 個の範囲で足ります。8 個は、組み合わせの数から逆算した値ではありません。[論文の 2.2 節](https://arxiv.org/abs/2601.07372)は、[Hash Embeddings](https://arxiv.org/abs/1709.03933) にならって衝突を減らすために範囲を複数にする、とだけ書き、8 という値は設定として示しています。決め方や、ほかの個数との比較は載せていません。1 行の中身はその行を共有する多くの並びの学習が混ざった数なので、読む行を増やすほど、ほかの並びの影響が行ごとにばらばらに散り、その並び自身の分が残りやすくなると考えられます。その代わり、1 トークンで読む行が増えて表から運ぶ量が増え、表全体の大きさが同じなら 1 範囲あたりの行数は減ります。8 はこの兼ね合いで選ばれた設定の値で、この記事のモデルも V4.1-Flash に合わせて 8 にしています。
:::

図は、例文「The girl was called Little Red Riding」の **CP** である「Riding」で、実際の値を追ったものです。真ん中の柱が表で、16 個の範囲に分かれています。

1. 番号をそろえる: 大文字と小文字などだけが違うトークンを 1 つの番号にまとめ、同じ並びとして扱えるようにします。「␣Riding」は 36032 から 7780 になります。
2. n-gram を作る: **CP** で終わる 2-gram は (356, 7780)、3-gram は (1067, 356, 7780) です。次の「Hood」はまだ読んでいないので入りません。
3. 大きな数にする: 2-gram と 3-gram のそれぞれについて、番号に位置ごとに違う固定の奇数を掛け、ビットごとに混ぜる XOR という計算で合わせて、1 つの大きな数にします。掛けることで順番が区別され、1 語だけ違う並びもまったく違う数になります。
4. 素数で割る: 大きな数を 8 個の範囲ごとに違う素数で割り、余りをその範囲の中の行番号にします。素数で割ると余りが偏りません。3-gram の 1 範囲は約 6.6 万行なので、学習の文章に出た 3-gram だけでも 1 行を平均 583 種類が共有します。それでも割る前の大きな数が違えば、8 範囲すべてで同じ行になることはないので、8 行の組み合わせはその並び専用の目印になります。
5. 16 行を読む: 番号の行をそのまま読みます。表の中を探しも、照合もしません。行番号はトークンの番号だけで決まるので、ブロックの計算を待たずに分かり、表を GPU の外に置いても先に取ってこられます。
6. つなぐ: 16 行 × 64 個 = 1,024 個の数にします。
7. key と value にする: 学習した行列 W_kv で 1,024 個を作り直し、前半の 512 個を key、後半の 512 個を value にします。
8. ゲートを決める: ブロック 0 の後の隠れ状態と key を 1 回だけ比べて、0 と 1 の間の数にします。この位置では 0.887 です。
9. 足す: value を 0.887 倍して隠れ状態に足し、ブロック 1 に渡します。

表の中身は出現回数ではなく、最初は乱数で、学習で書き換わる数です。学習で変わるのは行の中身、W_kv、ゲートの重みで、同じ並びが読む行は変わりません。

手順 1〜4 の、トークンの番号のそろえ方と行番号を出す計算は V4.1-Flash の[参照実装](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash/blob/2cba9e42aa026125f3ed06c6d98c1db82f7ca027/inference/engram.py)と同じで、同じ設定なら同じ行番号が出ることを、筆者の実験の[テストのコード](https://github.com/littlemex/zenmai-lab/blob/7d12d417f789173aa7082d4739c297d08116ad24/experiments/2026-10-21-engram-nanogpt/tests/test_engram_lm.py)で確かめています。

:::details ゲートの計算式と、論文や実装との違い
位置 $t$ の隠れ状態を $\mathbf{h}_t$、key を $\mathbf{k}_t$、value を $\mathbf{v}_t$ とすると、次のとおりです。

$$
s_t = \frac{1}{\sqrt{d}} \sum_{i=1}^{d} w_i \, \hat{h}_{t,i} \, \hat{k}_{t,i},\qquad
\alpha_t = \sigma\!\left(\operatorname{sign}(s_t)\sqrt{|s_t|}\right),\qquad
\mathbf{h}_t \leftarrow \mathbf{h}_t + \alpha_t \mathbf{v}_t
$$

- $\hat{h}_{t,i}$ は $\mathbf{h}_t$ の $i$ 番目の数を、2 乗平均に、この記事の実装では $\varepsilon = 10^{-6}$ を足した値の平方根で割ったもので、$\hat{k}_{t,i}$ も同じです。$d$ は 1 つのベクトルの数の個数で、この記事のモデルでは 512、$\sigma$ はどんな数も 0 と 1 の間の数に変えるシグモイド関数です。
- $w_i$ は学習で決まる重みで、実装では [RMSNorm](https://arxiv.org/abs/1910.07467) の学習する 2 つの重みの積です。
- $\operatorname{sign}(s_t)\sqrt{|s_t|}$ は、符号を残したまま大きさの平方根を取る計算です。論文の式 (4) にはこの平方根がありませんが、V4.1-Flash の[参照実装の model.py](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash/blob/2cba9e42aa026125f3ed06c6d98c1db82f7ca027/inference/model.py) に合わせて入れています。式では、$|s_t|$ に付ける小さな下限を省きました。
:::

### Attention との違い

図の左が Attention、右が Engram です。key と value という名前は、GPT の各ブロックにある Attention で使う名前と同じです。Attention は、**CP** から作った query を、それまでの全位置の key と比べ、合っている位置の value ほど多く混ぜて足します。Engram も比べて、掛けて、足す形は同じですが、候補は番号で決めた 1 組だけで、比べた結果は value を足す量を決める 1 つの数にしか使いません。

![左は Attention で、それまでの全位置から key と value を t 組作り、 CP の query と全部比べて softmax で重みを分け、多くの value を混ぜて足す。右は Engram で、Red Riding と Little Red Riding のトークンの番号だけから 16 個の行番号を決めて表の行を読み、学習する行列で key と value を 1 組作り、隠れ状態と key を比べて sigmoid で 1 つのゲート 0.887 を決め、value に掛けて足す。比べる段、掛ける段、足す段は同じ形で、候補の作り方と重みの付け方が違う](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/engram-vs-attention.png)

### 学習でも推論でも、位置ごとに 1 回

Engram は、モデルが位置を 1 つ計算するたびに、その位置について 1 回動きます。学習と、入力の文をまとめて読む推論の prefill では全位置をまとめて、1 トークンずつ書き足す decode では新しい 1 位置だけ、同じ計算をします。decode でも行を選ぶのに要るのは直前の 2 トークンの番号だけで、次のトークンが決まった瞬間に取ってくる行も決まります。この記事の測定はどれも prefill と同じ形です。

## 小さな GPT に組み込んで学習させる

Engram を足したときの差を見るため、同じ GPT の本体に Engram を足したモデルと足さないモデルを学習させました。Engram ありは、表の 6,716 万個と、key と value とゲートを作る重みの約 105 万個、合わせて 6,821 万個だけ重みが多くなります。

### 作るモデル

12 ブロックの GPT の、ブロック 0 とブロック 1 の間に [Engram の層](https://github.com/littlemex/zenmai-lab/blob/7d12d417f789173aa7082d4739c297d08116ad24/experiments/2026-10-21-engram-nanogpt/engram_lm/engram.py)を 1 つ入れます。[モデル全体](https://github.com/littlemex/zenmai-lab/blob/7d12d417f789173aa7082d4739c297d08116ad24/experiments/2026-10-21-engram-nanogpt/engram_lm/model.py)は、ブロック 0 を計算する前に全部の位置の行番号を先に計算しておきます。

![12 ブロックの GPT。トークンの番号から、ブロック 0 の前にハッシュで 16 個の行番号を計算しておき、ブロック 0 とブロック 1 の間の Engram に渡す](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/placement.png)

本体は、OpenAI の [GPT-2](https://github.com/openai/gpt-2) 型のブロックを 12 個重ねたもので、隠れ状態は 1 位置 512 個の数、一度に読む文脈は 512 トークンです。Engram を 2 番目のブロック、つまりブロック 1 の前に置いたのは、[論文の 6.2 節](https://arxiv.org/abs/2601.07372)が、重みの総数 30 億個の 12 層の MoE モデルに 16 億個の Engram を 1 か所だけ置くなら、2 番目の層が最も良かったと報告しているからです。MoE は、ブロックの中に expert と呼ぶ小さな計算をいくつも持ち、トークンごとにその一部だけを使うモデルです。

| 部品 | この記事のモデル | DeepSeek-V4.1-Flash |
|---|---|---|
| n-gram とヘッド | 2-gram と 3-gram、8 個ずつ、計 16 行 | 2〜4-gram、8 個ずつ、計 24 行 |
| 表 | 1,049,422 行 × 64、6,716 万個の重み | ブロック 1 の前が 384,006,168 行、ブロック 14 の前が 384,016,682 行、1 行 256 個 |
| 置く場所 | ブロック 1 の前の 1 か所 | ブロック 1 と 14 の前の 2 か所 |
| 論文の追加の部品 | ゲートを掛けた value に短い畳み込みの出力を加える仕組みも、隠れ状態と同じ幅の流れを 4 本並べる仕組みも入れていない | 短い畳み込みは入れていない。流れを 4 本並べる仕組みは使う |

V4.1-Flash の値は、[設定ファイル](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash/blob/2cba9e42aa026125f3ed06c6d98c1db82f7ca027/inference/config.json)と参照実装から取りました。

### 重みを 1 回直す流れ

学習では、モデルの予想と正解を比べ、外れが小さくなるように重みを少しずつ直します。

![文章から 512 トークンの窓を 128 個取り出し、モデルが次のトークンの確率を出し、正解との外れ具合の損失から勾配を求め、重みを直す。表は読まれた行に勾配が届く。これを 3,600 回繰り返す](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/training-step.png)

モデルは各位置で次のトークンの確率を出し、正解のトークンとの外れ具合が損失です。重みを少し動かすと損失がどう変わるかを表すのが勾配です。512 トークン分のひと続きを窓と呼びます。重みを 1 回直すたびに、文章から無作為に取り出した窓 128 個分の勾配を使い、これを 3,600 回繰り返して 2.36 億トークンを学習しました。表には、その回に読まれた行に勾配が届きます。一度も読まれない行は最初の乱数のままです。一度読まれた行は、表の重みを直すのに使う [Adam](https://arxiv.org/abs/1412.6980) という方法が前の回の勾配も覚えているので、読まれない回にも少し動きます。

### 比べ方

2 つのモデルの違いを Engram の有無にするため、同じ本体の重みから始め、同じ文章を同じ順番で読ませました。

![左の Engram なしと右の Engram ありで、学習を始める前の本体の重み、読む文章の順番、2.36 億トークンの学習量と AdamW の設定が同じ。右だけに Engram の 6,821 万個の重みがあり、表は本体の 5 倍の学習率で weight decay なしの Adam で学習する。重みの総数は約 6,377 万と約 1 億 3,198 万](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/comparison.png)

学習に使った文章は、Wikipedia から作られた [WikiText-103](https://huggingface.co/datasets/Salesforce/wikitext) です。重みのはじめの値と窓を取り出す順番を決める seed を、1337、1338、1339 の 3 通りに変え、2 つのモデルを 3 回ずつ学習させました。実装は本体を先に初期化し、Engram を別の乱数の流れで作るので、同じ seed なら本体は同じ重みから始まります。このことは[テスト](https://github.com/littlemex/zenmai-lab/blob/7d12d417f789173aa7082d4739c297d08116ad24/experiments/2026-10-21-engram-nanogpt/tests/test_engram_lm.py#L133-L145)で確かめています。表以外の重みは [AdamW](https://arxiv.org/abs/1711.05101) という方法で直します。本体の重みと、Engram の中で key、value、ゲートを計算する重みがこれに当たります。Engram の表だけは、[論文の 4.1 節](https://arxiv.org/abs/2601.07372)と同じく Adam で直します。1 回に重みを動かす幅を学習率と呼びます。表の学習率は本体の 5 倍にし、重みを縮める weight decay は掛けません。

:::details 学習の環境と設定
- GPU: [Amazon EKS](https://aws.amazon.com/eks/) の上の [NVIDIA RTX PRO 4500 Blackwell](https://www.nvidia.com/en-us/products/workstations/professional-desktop-gpus/rtx-pro-4500/) を、1 つの学習に 1 枚
- ソフトウェア: [PyTorch](https://pytorch.org/) 2.9.1、[CUDA](https://developer.nvidia.com/cuda-toolkit) 12.8、bfloat16 の混合精度、[`torch.compile`](https://docs.pytorch.org/docs/stable/generated/torch.compile.html)
- バッチ: 32 窓ずつ 4 回に分けて勾配をため、128 窓 × 512 トークン = 65,536 トークンごとに重みを直す
- 学習率: 最初の 300 回で 6e-4 まで上げ、その後 6e-5 まで下げる。表の学習率はその 5 倍で、3e-3 から 3e-4。weight decay は表以外の行列の形の重みで 0.1
- 勾配のクリップ: 本体、Engram の表以外の重み、表の 3 組に分け、組ごとに勾配の大きさが 1.0 を超えたら 1.0 まで縮める
- 窓の取り出し方: 重なりを許して無作為に取り出す。WikiText-103 の学習用の文章は約 1.18 億トークンで、2.36 億トークンはその約 2 倍だが、ちょうど 2 周読むわけではない
:::

## 学習の結果

Engram ありは、学習の序盤に損失を早く下げましたが、学習を終えた後に、学習に使っていない文章で測った性能の差は小さいものでした。

:::details 評価と集計の条件
- 評価は学習の最後の重みで、文章を重ならない 512 トークンの窓に切り、窓ごとに前の文脈を持たずに測った。最後の窓に満たない残りは測っていない
- パープレキシティは GPT-2 のトークン単位で、単語単位で報告される WikiText-103 の値とは比べられない
- ± は 3 つの seed の値の標本標準偏差で、平均との差の 2 乗の和を 3 − 1 = 2 で割り、平方根を取って求めた
:::

### 学習中の損失

Engram の効き目が学習のどの段階で出るかを見るため、学習の途中で、学習に使っていない検証用の文章で損失を測りました。この検証の損失は、低いほど予想が良いことを表します。

![上の段は 6 回の学習の検証の損失で、Engram ありは実線と丸、Engram なしは破線と四角。下の段は同じ seed どうしの差で、0 より下なら Engram ありが低い。約 2,600 万トークンで -0.20〜-0.23、8,000 万トークン前後でほぼ 0、1 億トークンから最後まで -0.008〜-0.030](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/val-loss.png)

約 2,600 万トークンを学習し、重みを 400 回直した時点で、Engram ありの損失は、同じ seed の Engram なしより 0.20〜0.23 低くなりました。Engram なしがこの損失に届くのは、評価の点の間を直線でつないで約 485 回目で、学習の量にすると約 85 回分、約 560 万トークンの先行です。差は 8,000 万〜9,000 万トークンでほぼ 0 になり、seed 1337 では、約 7,800 万と約 9,100 万トークンの 2 回の評価で、Engram なしのほうがわずかに低くなりました。1 億トークンから最後までは、3 つの seed とも 0.008〜0.030 の差で Engram ありが低い値でした。

### 学習後の性能

性能は、正解のトークンに付けた確率から求めるパープレキシティで比べました。パープレキシティは、実際の次のトークンにどれだけ確率を付けられたかを表す値で、平均の損失 $\overline{L}$ から $\exp(\overline{L})$ で出し、低いほど良い値です。29 なら、どの位置でも正解に 29 分の 1 の確率を付けたときと同じ平均の損失です。

| | Engram あり | Engram なし |
|---|---|---|
| 重みの数 | 1 億 3,198 万、うち表 6,716 万 | 6,377 万 |
| 検証のパープレキシティ | 28.97 ± 0.08 | 29.26 ± 0.01 |
| テストのパープレキシティ | 29.40 ± 0.16 | 29.36 ± 0.13 |
| 学習のスループット、1 秒あたりのトークン数 | 149,543 | 155,677 |

検証用とテスト用の文章は、どちらも学習に使っていない、WikiText-103 の別々の部分です。値は 3 つの seed の平均で、± の後は seed によるばらつきです。検証では Engram ありが Engram なしより平均 1.0% 低く、3 つの seed のどれでも低い値でした。テストではほぼ同じで、同じ seed どうしでは Engram ありが 0.06、0.06、0.00 高い値でした。学習のスループットは、検証と保存の時間を除いて 1 枚の GPU で測った値で、Engram なしより 3.9% 下がりました。これは学習のときの値で、表は GPU のメモリに置いたままです。はじめにの 2.8% は、論文が別の GPU と別の大きさのモデルで、表を GPU の外に置いて文章を処理するときに測った値なので、この 3.9% とは比べられません。

### 表引きを外すと

学習を終えたモデルが表引きにどれだけ頼っているかを見るため、評価のときだけ表引きの足し込みを飛ばしました。以下、これを「表引きを外す」と呼びます。

![検証のパープレキシティの 3 つの seed の平均。Engram ありのモデルが 28.97、同じ重みで表引きを外すと 59.54、Engram なしで学習したモデルが 29.26。斜線、点、× の格子の棒](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/engram-off.png)

評価のときだけ外した検証のパープレキシティは、3 つの seed の平均で 28.97 から 59.54 になり、外す前の約 2.1 倍になりました。最初から Engram なしで学習したモデルの 29.26 より悪く、学習を終えたモデルは表引きの出力を使う前提で組み上がっていると読めます。学習中に一度もなかった条件で動かした値なので、表引きが運ぶ情報の量そのものではないと、[論文の 6.3 節](https://arxiv.org/abs/2601.07372)も同じ操作について書いています。

## 1 つの文で中身を追う

例文「The girl was called Little Red Riding」の「Riding」の位置で、正解の「Hood」に付けた確率を、ブロックを 1 つ通るたびに取り出して 3 通りで比べました。Engram ありのモデル、その重みのまま表引きを外した場合、最初から Engram なしで学習したモデルです。例文は、童話や小説の題名、人名、科学の言葉など 108 通りの文を 3 つの seed で測り、Engram ありのモデルだけが当てる差がはっきり出るものを選びました。「Little Red Riding」は学習の文章に 24 回現れ、次は 24 回とも「Hood」で、表に覚えやすい並びです。3 つの seed の平均でも、前に付く文を 6 通りに変えて、Engram ありは 0.77〜0.89、表引きを外すと 0.000、Engram なしは 0.05〜0.28 でした。表引きが効きやすい位置を選んでいるので、典型的な位置ではありません。以下は seed 1337 のモデルの 1 か所の観察で、文章全体での傾向は次の節で見ます。この記録はすべて CPU の float32 で計算しました。

途中のブロックの予想は、論文も 6.1 節で使った [LogitLens](https://www.lesswrong.com/posts/AcKRB8wDpdaN6v6ru/interpreting-gpt-the-logit-lens) で取り出しました。LogitLens は、途中のブロックの後の隠れ状態を、ふつうは最後のブロックの後にだけ使う出力の計算に通し、12 ブロックをすべて計算するモデルの途中の仮の予想を読み出す方法です。

![seed 1337 のモデルで、例文の CP の Riding の位置で、次のトークン Hood の確率をブロックごとに取り出した折れ線。横は 0 から 11 のブロック、縦は確率で、ブロック 1 の前に Engram を足す位置を縦の破線で示す。Engram ありは丸と実線で、ブロック 6 で大きく上がり、最後は 0.723。Engram なしで学習したモデルは四角と破線で最後は 0.082、表引きを外した場合は三角と点線で最後は 0.000](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/hood-chart.png)

この記事のモデルの語彙は GPT-2 と同じ約 5 万個のトークンで、確率が広く散らばるので、確率が 2 割ほどでも 1 位になります。

| 比べたモデル | 「Hood」が 1 位になったブロック | 最後の「Hood」の確率 |
|---|---|---|
| Engram あり | ブロック 6 の後から最後まで | 0.723 |
| Engram ありの重みで、表引きを外す | 1 位にならない | 0.00006 |
| Engram なしで学習したモデル | 1 位にならない | 0.082 |

表引きを外した場合も Engram なしのモデルも、最後の 1 位はカンマ「,」でした。

表引きを足してブロック 1 を計算した後の「Hood」の確率は 0.012 で、表引きを外した場合の 0.00013 より高いものの、まだ 1 位ではありません。Engram ありのモデルでは、ブロック 6 で 0.069 から 0.223 に大きく上がり、その後もおおむね上がって最後は 0.723 になりました。この差から分かるのは、この位置で表引きの足し込みが予想を変えたことまでで、表の特定の行がこの名前を覚えたかは分かりません。

## ほかの文と文章全体で見る

1 つの位置で見えた違いを、ほかの位置と文章全体で、ゲートの値と途中の予想の 2 つから確かめました。

### ゲートは多くの位置で開く

ゲートが位置ごとにどう変わるかを見るため、2 文、合わせて 34 トークンの英文で seed 1337 のモデルのゲートを並べました。文は、赤ずきんが森を通っておばあさんの家へ向かい、途中でおおかみに会う、という筆者が作った英文で、[記録](https://github.com/littlemex/figures/blob/45d3390271f62f381240aa8d75fdbb7af0c22094/zenn/articles/35ef2467d84b63/source/redhood-forest.json)を図のリポジトリに置いています。28 か所でゲートが 0.5 を超えて開きました。0.5 以下は 6 か所で、うち 4 か所は 0.3 より低い値でした。

![Little Red Riding Hood で始まる 2 文、34 トークンの英文で、seed 1337 の Engram ありのモデルの位置ごとのゲート α を示した図です。多くの位置で 0.5 を超えています。0.3 を下回ったのは、文頭の Little、walked、2 つの文末のピリオドの 4 か所で、値は 0.09 から 0.24 です。この 4 か所を白い太枠と値で示しています。](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/gate-text.png)

WikiText-103 は句読点の前後に空白を置くので、この英文も「grandmother ,」のように書きました。低かったのは、文頭の「Little」の 0.14、「walked」の 0.24、2 つの文末のピリオドの 0.09 と 0.19 です。ほかに「lived」の 0.35 と「river」の 0.33 も、0.5 に届きませんでした。文頭の「Little」は前のトークンが無く、2-gram と 3-gram の足りない分を `<|endoftext|>` の番号で埋めた位置です。同じ名前の続きの「Red」「Riding」「Hood」は 0.77〜0.87 で、前の節の例文の「Riding」の 0.89 も、この英文の「the」の 0.91 や「forest」の 0.89 と同じくらいで、名前だから特に高いとは言えません。論文の Figure 7 は、名前を言い終えた位置でゲートが大きく開く例を示しています。論文のモデルは Engram を 2 か所に置き、4 本の流れごとにゲートを持つのでゲートは 8 個あり、図はそのうち意味のある並びと最も強く結びつくものを選んで描いています。この記事のモデルでは、名前を言い終える「Hood」のゲートは 0.78 で前後と変わらず、名前の終わりでだけ大きく開く傾向は、ゲートが 1 個のこのモデルのこの英文でははっきりとは見えませんでした。検証用の文章の最初の 200 窓では、3 つの seed の平均で、この記事のモデルのゲートの平均は 0.66、0.5 を超えた位置は 74% でした。

### 途中の予想と最後の予想の近さ

表引きを足すと、早いブロックのうちに予想が最後の形に近づくかを見るため、検証用の文章で、LogitLens で取り出した途中のブロックの予想を、そのモデル自身の最後の予想と比べました。近さは KL ダイバージェンスで測りました。2 つの確率の並びがどれだけ違うかを表す 0 以上の値で、同じなら 0 です。以下では KL と書きます。

![検証用の文章の最初の 200 窓で、ブロックごとの仮の予想と、同じモデルの最後の予想との違いを KL で測った値。Engram ありは実線と丸で、ブロック 0 の後は 5.04、ブロック 1 の後は 2.91 で、ブロック 10 まで Engram なしより低い。Engram なしは破線と四角で、ブロック 0 から 4 までほぼ 4。3 つの seed の平均と標準偏差](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/logit-lens-kl.png)

最後の予想 $p_{\mathrm{final}}$ を基準に、ブロック $l$ の後の予想 $p_l$ を比べた $D_{\mathrm{KL}}(p_{\mathrm{final}} \,\|\, p_l)$ を 10 万 2,400 か所で平均し、3 つの seed で平均しました。点は平均、縦の線は標準偏差で、最後のブロックの後は 0 になるので省いています。Engram ありはブロック 1 の後で 2.91 で、Engram なしの 3.94 より低く、ブロック 10 まで低いままでした。表引きを足す前のブロック 0 の後だけは、Engram ありが 5.04 で、Engram なしの 4.01 より高い値です。この KL は各モデル自身の最後の予想との近さで、どちらが正しく当てるかや、ブロックの仕事の分担を測った値ではありません。論文の「初めのブロックの仕事を表引きが助ける」という読み方とは矛盾しない、という結果です。

### 1 位の候補が固まるブロック

予想の 1 位がどのブロックで決まるかを数で見るため、検証用の文章の 483 窓すべて、seed あたり 247,296 か所で、1 位の候補がどのブロックから最後まで変わらなくなったかを数えました。本体は GPU の bfloat16 の混合精度で、各ブロックの予想の読み出しは float32 で計算しました。[集計のコード](https://github.com/littlemex/zenmai-lab/blob/7d12d417f789173aa7082d4739c297d08116ad24/experiments/2026-10-21-engram-nanogpt/engram_lm/settling.py)は、最後のブロックまで計算した後で振り返って数えるもので、固まった後のブロックも計算され、確率は変わり続けます。

![1 位の候補がそれ以上変わらなくなったブロックの割合。ブロック 1 で固まった位置は、Engram ありが 14.5%、同じ重みで表引きを外すと 8.7%、Engram なしで学習したモデルが 4.8%。斜線、点、× の格子の棒で区別。3 つの seed の平均](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/settling.png)

同じ seed どうしで位置ごとに比べると、Engram ありのほうが早く固まった位置が 46.4%、遅かった位置が 26.1%、同じだった位置が 27.4% でした。固まったブロックの平均は、Engram ありが 6.27、表引きを外すと 6.91、Engram なしが 7.04 です。差が最も大きいのは表引きの直後で、ブロック 1 で固まった位置は Engram ありが 14.5%、Engram なしが 4.8%、ブロック 1 までに固まった位置は同じ順に 23.0% と 13.9% でした。ここでの 1 位はそのモデル自身の最後の 1 位で、それが実際の次のトークンと一致した位置は、Engram ありが 40.2%、Engram なしが 39.8% です。

両方のモデルが最後に正解し、Engram ありのほうが早く固まった位置だけを集め、固まった時点の 1 位の確率の中央値を seed ごとに求めて平均すると、Engram ありが 0.39、Engram なしが 0.48 で、早く固まった側のほうが低い値でした。早く 1 位が決まることは、早く高い確率を付けることとは別です。表引きを外しても、ブロック 1 で固まる位置は 8.7% で Engram なしの 4.8% より多い一方、最後の 1 位が正解の位置は 30.8% に下がります。早く固まる理由が表引きの足し込みにあるのか、一緒に学習した本体の重みにあるのかは、この集計からは分かりません。

## 表を分けて学習し直す

学習の最後の 200 回の更新では、Engram ありの学習用の文章での損失は Engram なしより 0.151 低いのに、検証用の文章では 0.010 しか低くありませんでした。表が、一度読んだ文章の続きを覚えていたためです。そこで、学習用の文章を Wikipedia の記事ごとに順に 3 つに分け、表も 3 つ持たせて、各位置には自分の記事を学習していない 2 つの表の平均だけを読ませて学習し直しました。表全体の大きさは元と同じです。3 つの seed の平均で、テスト用の文章のパープレキシティは 29.40 から 28.50 に下がり、Engram なしの 29.36 も下回りました。

これは、WikiText-103 の学習用の 1.18 億トークンを約 2 周する、この規模での結果です。文章を 1 周しかしない大規模な学習では、表が一度読んだ文章をまた読む場面がもともと少ないので、同じように効くかは試していません。それでも、Engram の作りにはまだ改善の余地がありそうです。試した内容と数字は[解説のページ](https://littlemex.github.io/explainers/engram-ideas.html)に、コードは [zenmai-lab](https://github.com/littlemex/zenmai-lab/tree/61a8d823b6c37a268a015ec61806b85ad9d4b219/experiments/2026-11-17-engram-cutoff-train) に置きました。

## 自分で動かす

筆者が公開した学習済みのモデルと、筆者が作った、1 つの文の中身を画面で追う[ページ](https://github.com/littlemex/zenmai-lab/tree/7d12d417f789173aa7082d4739c297d08116ad24/experiments/2026-10-21-engram-trace-viewer)を使うと、ここまでの観察を自分の文で試せます。

![動作確認のページの一部。with Engram の欄に、Red Riding と Little Red Riding をキーに 1,049,422 行の表から 16 行を読み、ブロック 1 の前に足すこと、混ぜる強さ 89%、表引きの有無でブロック 1 の後の Hood の確率が 0.0% から 1.2% に変わることが並ぶ。trained without Engram の欄には、表なしで学習したモデルである説明が並ぶ](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/ladder-lookup.png)

図は、ページで「Riding」を選んだときの表引きの欄です。欄の「top choice -ster」は、1 位の候補が、前に空白の無い「ster」というトークンだという意味です。ページの「How strongly it is mixed in」はゲートで、89% は value に掛ける 0.89 のことです。モデルは [Hugging Face の littlemex/engram-nanogpt-wikitext103](https://huggingface.co/littlemex/engram-nanogpt-wikitext103) に、6 回の学習の分を置いてあります。

:::details この記事の例文を記録して、画面で開く手順
Git、[Python](https://www.python.org/) 3、[uv](https://docs.astral.sh/uv/) を使います。モデルの取得には [Hugging Face の CLI](https://huggingface.co/docs/huggingface_hub/guides/cli) の `hf download` を使います。モデルのファイルは 2 つで約 785 MB です。記録は CPU で動き、筆者の 16 コアの CPU のマシンでは、記録のコマンドだけにかかった時間は約 5 秒でした。パッケージを入れる時間とモデルのダウンロードの時間は含みません。記録は、入力の文の後に Engram ありのモデルで 20 トークンを書き足し、その全体を 3 通りで読み直します。書き足した部分の次のトークンは人が用意した正解ではなく、Engram ありのモデルの出力です。例文は、学習の文章と同じく先頭に空白を置いた「␣The girl was called Little Red Riding Hood because she always wore a red hood」です。␣ は、トークンの前に付いた空白を表す記号です。

```bash
git clone https://github.com/littlemex/zenmai-lab.git
cd zenmai-lab
git checkout 7d12d417f789173aa7082d4739c297d08116ad24
cd experiments/2026-10-21-engram-nanogpt
export SEED=1337
uv run --python 3.11 --with-requirements requirements.txt hf download littlemex/engram-nanogpt-wikitext103 --revision e9758158ad0d180336bc059e20fecf29f67f445b --include "*-seed$SEED/model.safetensors" --local-dir hub
uv run --python 3.11 --with-requirements requirements.txt python -m engram_lm.record_trace --engram hub/engram-seed$SEED/model.safetensors --baseline hub/baseline-seed$SEED/model.safetensors --prompt " The girl was called Little Red Riding Hood because she always wore a red hood" --new-tokens 20 --title "Little Red Riding Hood (seed $SEED)" --out ../2026-10-21-engram-trace-viewer/viewer/traces/redhood.json
cd ../2026-10-21-engram-trace-viewer/viewer
python3 -m http.server 8000 --bind 127.0.0.1
```

記録が終わると、次の 1 行が出ます。

```
wrote ../2026-10-21-engram-trace-viewer/viewer/traces/redhood.json: 35 tokens (20 generated)
```

サーバーを動かしたまま、ブラウザで `http://127.0.0.1:8000/ladder.html?trace=traces/redhood.json` を開いてください。`--prompt` を変えると自分の文で試せます。WikiText-103 の書き方に合わせて、句読点の前後に空白を置き、ハイフンを ` @-@ ` と書くと、学習の文章に近い形になります。
:::

## まとめ

Engram は、トークンの番号だけで読む行を先に決め、読んだ数を、ゲートで決めた量だけ隠れ状態に足す部品です。12 ブロックのこの実験では、Engram なしと比べて序盤の損失を早く下げ、検証用の文章で 1 位の候補が固まるブロックの平均も、Engram なしの 7.04 に対して 6.27 と早くなりましたが、学習を終えた後のテスト用の文章のパープレキシティはほぼ同じでした。学習用の文章と表を 3 つに分け、各位置に自分の部分を学習していない表だけを読ませて学習し直すと、この規模ではテストのパープレキシティが 29.40 から 28.50 に下がりました。

論文の結果の詳しい読み方は「[Engram は何を覚えて、どう引くのか](https://zenn.dev/tosshi/articles/5853108f53bd7f)」に、大きな表を何台かに分けて持つ方法は「[Engram の表を何台かに分けて引く](https://zenn.dev/tosshi/articles/54aced4bdcb137)」に書きました。
