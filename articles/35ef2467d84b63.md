## はじめに

「[Engram は何を覚えて、どう引くのか](https://zenn.dev/tosshi/articles/5853108f53bd7f)」では、DeepSeek の Engram を論文と公開された DeepSeek-V4.1-Flash から読み解きました。読むだけでは、Engram があると何が変わるのかを手で触って確かめられません。そこでこの記事では、小さな GPT に Engram を自分で組み込み、Engram があるモデルと無いモデルを、Engram 以外の条件をそろえて学習させて比べます。次の記事では、ここで作ったモデルを使って、Engram の動きを画面で確かめながら整理します。

## Engram が減らしたいもの

[Engram の論文](https://arxiv.org/abs/2601.07372)によると、LLM は「Alexander the Great」のような決まった名前でも、初めの何層かの計算をかけて組み立てています。層の数は決まっているので、その分だけ文脈を読む仕事や推論に使える深さが減ります。Engram は、直前の数個のトークンの組で引ける学習済みの表をモデルに足し、この組み立てを表からの読み出しで助けます。仕組みの詳しい説明は前の記事に書きました。この記事では、Engram を足すと、学習の進み方、学習を終えた後の性能、途中の層の予想の 3 つが変わるかを確かめます。

## 作るもの

![12 層の GPT の 0 層目と 1 層目の間に Engram を 1 つ入れる。Engram は正規化したトークン番号から 2-gram と 3-gram を 8 通りずつハッシュして 16 個の行番号を作り、1,049,422 行 × 64 の表から読み、wkv で key と value に変え、0 層目の後の隠れ状態 h と key からゲート α を求め、α を掛けた value を h に足す](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/model.png)

作るのは、12 層の GPT-2 型のモデルです。層の番号は 0 から数えます。隠れ状態の次元は 512、Attention のヘッドは 8、文脈は 512 トークンで、パラメータは 6,377 万です。Engram は 1 つだけ、2 番目の層にあたる 1 層目の Attention の前に入れます。[論文](https://arxiv.org/abs/2601.07372)の 6.2 節は、Engram を 1 か所だけ置くなら 2 番目の層が最も良かったと報告しており、それに合わせました。

Engram の作りは、DeepSeek-V4.1-Flash の参照実装にそろえました。実装は [engram.py](https://github.com/littlemex/zenmai-lab/blob/a191b5759329986decf9ebdfa28a6669ff34e36f/experiments/2026-10-21-engram-nanogpt/engram_lm/engram.py) と [model.py](https://github.com/littlemex/zenmai-lab/blob/a191b5759329986decf9ebdfa28a6669ff34e36f/experiments/2026-10-21-engram-nanogpt/engram_lm/model.py) にあります。

| 部品 | この記事のモデル | DeepSeek-V4.1-Flash |
|---|---|---|
| トークンの正規化 | GPT-2 の 50,257 トークンを、大文字小文字や空白の違いをそろえて 32,962 個にまとめます | 同じ手順です。出力が一致することを[テスト](https://github.com/littlemex/zenmai-lab/blob/a191b5759329986decf9ebdfa28a6669ff34e36f/experiments/2026-10-21-engram-nanogpt/tests/test_engram_lm.py)で確かめました |
| N-gram とハッシュ | 2-gram と 3-gram を 8 通りずつハッシュして、計 16 個の行番号にします | 同じ式です。同じ設定なら行番号が一致することをテストで確かめました |
| 表 | 1,049,422 行 × 64、6,716 万パラメータ | 層ごとに約 3 億 8,400 万行 × 256 |
| ゲートと足し込み | 読んだ 16 行をつなぎ、wkv という線形層で key と value に変えます。key と隠れ状態の近さでゲート α を決め、α を掛けた value を隠れ状態に足します | 同じ式です |
| 入れない部品 | 残差の流れを 4 つに分ける hyper-connections と、短い畳み込み | 短い畳み込みは V4.1-Flash も入れていません |

## 比べ方

![2 つの学習は、0 ステップ目の本体の重み、学習データの順番、2.36 億トークンの学習量、本体の最適化の設定が同じ。Engram ありだけに 6,821 万パラメータの Engram があり、表は 5 倍の学習率で weight decay なしの Adam で学習する。総パラメータは Engram ありが 1 億 3,200 万、なしが 6,380 万](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/comparison.png)

比べたいのは、同じモデルに Engram を足すと何が変わるかです。そのために、違いが Engram だけになるように 2 つの学習をそろえました。同じ乱数の種なら、2 つのモデルの本体は同じ重みから始まり、同じ順番で同じデータを読みます。本体はどちらも AdamW で、最大の学習率 6e-4、cosine で減らす学習率、weight decay 0.1 にそろえます。Engram の表は、[論文](https://arxiv.org/abs/2601.07372)の 4.1 節と同じく Adam を使い、5 倍の学習率で、weight decay を掛けずに学習させます。勾配の大きさを上限 1.0 に抑えるクリップは、本体、Engram の射影とゲート、表の 3 つに分けて行います。こうすると、本体のクリップのされ方が、Engram の勾配の大きさに左右されません。

Engram ありのほうが、表の 6,716 万と射影とゲートの 105 万を合わせて、パラメータが 6,821 万多くなります。パラメータの総数をそろえた比較ではありません。1 トークンあたりに表から読むのは 16 行だけで、学習の速さの違いは後で示すとおり 3.9 % でした。乱数の種を 3 つ変えて学習させ、差が種による揺れより大きいかを確かめます。

学習には、Amazon EKS の上の NVIDIA RTX PRO 4500 Blackwell を 2 枚使い、1 枚に 1 つのモデルを載せました。データは WikiText-103 で、GPT-2 のトークナイザで 1 億 1,795 万トークンになります。学習させるのは 2.36 億トークンで、データのおよそ 2 倍です。学習の窓はデータから無作為に取り出すので、きっちり 2 周するわけではありません。

## 結果: 序盤は速く、最後はほぼ同じ

![上の段は 6 つの学習の検証の損失で、種ごとに線の形を変えている。下の段は同じ種どうしの差で、Engram ありから Engram なしを引いた値。約 2,600 万トークンの時点で -0.20 から -0.23、8,000 万トークンでほぼ 0、1 億トークン以降は -0.008 から -0.030。図は最初の評価の 0 ステップ目を省いている](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/val-loss.png)

損失は、次のトークンをどれだけ外したかを表す値で、低いほど良い予想です。検証の損失は、学習の序盤で大きく差がつきました。400 ステップ目、2,600 万トークンを学習した時点で、Engram ありは同じ種の Engram なしより 0.20〜0.23 低くなりました。評価は 200 ステップおきなので、その間を直線でつないで推定すると、Engram なしが同じ損失に届くのは 480〜490 ステップ目です。評価ごとの損失は、後で示す summary.json に入っています。Engram ありは、2 割弱少ないステップで同じところまで来たことになります。差はいったん縮み、8,000 万トークン前後でほぼ 0 になりました。その後は再び Engram ありが低くなり、1 億トークンから最後まで -0.008〜-0.030 の差で 3 つの種がそろっています。最後の差は -0.008〜-0.013 で、これが次に示す検証のパープレキシティの 1.0 % の差にあたります。

学習を終えた後の結果は次のとおりです。パープレキシティは、損失の平均を指数にした値で、低いほど、評価データの正解のトークンに高い確率を付けられていることを表します。検証データとテストデータは、どちらも学習には使っていない別々の文章です。パープレキシティは 3 つの種の平均 ± 標準偏差、学習の速さは 3 つの種の平均で、元の値は [summary.json](https://github.com/littlemex/zenmai-lab/blob/a191b5759329986decf9ebdfa28a6669ff34e36f/experiments/2026-10-21-engram-nanogpt/results/summary.json) にあります。

| | Engram あり | Engram なし |
|---|---|---|
| パラメータ | 1 億 3,198 万（うち表 6,716 万） | 6,377 万 |
| 検証のパープレキシティ | 28.97 ± 0.08 | 29.26 ± 0.01 |
| テストのパープレキシティ | 29.40 ± 0.16 | 29.36 ± 0.13 |
| 学習の速さ | 毎秒 14.95 万トークン | 毎秒 15.57 万トークン |

検証では、3 つの種のどれでも Engram ありのほうが低く、平均で 1.0 % 低くなりました。テストでは平均がほぼ同じで、同じ種どうしで比べると、小数第 2 位に丸めて Engram ありが 0.06、0.06、0.00 高い値でした。この規模では、Engram を足しても、学習を終えた後の性能がはっきり上がるとは言えません。学習の速さは、Engram を足した分だけ 3.9 % 落ちました。

## Engram を外すと

**Engram を外すと検証のパープレキシティが 2 倍になる**ほど、学習を終えたモデルは Engram に頼っていました。値は 28.97 から 59.54 です。最終の性能の差は小さくても、学習を終えたモデルは Engram の出力を使う前提になっています。ただし、外したときに悪くなることからは、Engram が何を受け持っていたかまでは分かりません。ゲートの平均は 0.66 でした。検証データの最初の 200 窓、10 万 2,400 か所で数えると、ゲートが 0.5 を超えた位置は 74 % でした。多くの位置で、表から読んだ行で作った value に 0.5 を超える係数を掛けて足していたことになります。

## 途中の層の予想

![層ごとに、その層の時点の予想と最終の予想の違いを KL で比べた図。点は 3 つの種の平均、縦の線は標準偏差、縦軸は対数目盛。Engram なしは 0 層目から 4 層目までほぼ 4 のまま。Engram ありは 0 層目の後では 5.04 と高いが、1 層目の後では 2.91 で、10 層目まで Engram なしより低い。最後の層である 11 層目は定義上 0 なので省いた](https://raw.githubusercontent.com/littlemex/figures/refs/heads/zenn/articles/35ef2467d84b63/zenn/articles/35ef2467d84b63/logit-lens-kl.png)

各層の後の隠れ状態を、最後の層と同じ出口に通して、その層の時点で次のトークンをどう予想しているかを出しました。[論文](https://arxiv.org/abs/2601.07372)も 6.1 節で使った LogitLens という方法です。図の縦軸は、その予想がモデル自身の最終の予想とどれだけ違うかを、KL(最終の予想 ‖ その層の予想) で表したものです。KL は 2 つの確率の分かれ方の違いを測る値で、低いほど最終の予想に近いことを表します。点は 3 つの種の平均、縦の線は標準偏差で、縦軸は対数目盛です。最後の層である 11 層目は、最終の予想そのものなので 0 になり、図から省きました。

Engram なしでは、0 層目から 4 層目まで違いがほとんど縮みません。Engram ありでは、0 層目の後の 5.04 から、Engram を足した 1 層目の後で 2.91 へ大きく下がりました。同じ 1 層目の後の Engram なしは 3.94 で、Engram ありは 10 層目まで Engram なしより低いままでした。Engram を足す前の 0 層目の後だけは Engram ありのほうが高く、5.04 対 4.01 です。この差が 0 層目の役割の違いを表すのかは、この KL だけでは分かりません。

これは、Engram が初めの層の組み立てを肩代わりし、本体が少ない層で予想の形に近づく、という論文の見方と合っています。ただ、この比較だけでは、役割の分け方や必要な層の数までは判断できません。分かるのは、各層の予想がそれぞれのモデルの最終の予想にどれだけ近いかです。Engram が何を渡しているかや、どちらの予想が正しいかは、ここからは分かりません。それを確かめるのが次の記事です。

## まとめ

Engram を足した小さな GPT は、パラメータが約 2 倍になり学習が 3.9 % 遅くなる代わりに序盤の学習が速くなりましたが、テストのパープレキシティは Engram なしと変わりませんでした。学習を終えたモデルは Engram に強く頼っていて、1 層目の後から 10 層目まで、Engram なしより最終の予想に近い状態でした。
