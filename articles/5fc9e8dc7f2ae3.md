# はじめに

本記事は、RL ポストトレーニング、つまり学習済みモデルを強化学習でさらに調整する工程で、学習を静かに崩壊させる数値ミスマッチを扱います。応答を生成する推論エンジンと、重みを更新する学習エンジンは、同じ重みを持っていても同じトークンにわずかに違う数値を出すことがあります。同じ重みなら同じ確率を出すはず、という前提が崩れるこのズレを mis_kl と呼びます。条件がそろうと mis_kl は積み上がり、学習を崩壊させます。

以下では GRPO(Group Relative Policy Optimization)を例に、mis_kl がどこで生まれ、何が増幅し、どう抑えるのかを実測とともに整理します。図が説明の中心なので本文は短くします。実測は miles で行いました。miles は GRPO のポストトレーニングを回すためのフレームワークで、そのテストケースを [awsome-distributed-ai の PR #1225](https://github.com/awslabs/awsome-distributed-ai/pull/1225) として追加中です。執筆時点では未マージです。

# GRPO の基本ループ

まず土台の GRPO を確認します。学習対象のモデルをポリシーと呼び、プロンプトから行動を生成します。生成された行動は環境で評価され、1 回の試行ごとに 1 つの報酬が返ります。たとえば囲碁 AI を思い浮かべてください。盤面がプロンプト、指し手が行動で、対局を最後まで打って勝てば良い報酬、負ければ悪い報酬を受け取ります。これを何局も繰り返し、良い手を選びやすくなるよう自分を更新していくのが強化学習の基本です。

![GRPO の基本ループ](/images/5fc9e8dc7f2ae3-fig1-grpo-loop.png)

GRPO の特徴は、PPO などが必要とする価値推定用の補助モデル、いわゆる critic を使わない点です。同じプロンプトから複数の試行を走らせ、各報酬をグループの平均と比べ、平均より良ければ強化し悪ければ抑制して、重みを更新します。タスクがツール利用でもコーディングでも数学でも構造は同じで、モデルが応答を生成し、その応答を評価して報酬を作ります。評価は CPU でも GPU でも実行でき、構成次第です。

# GRPO で起こりうる崩壊

ここでいう崩壊とは、報酬や生成品質が悪化し、勾配や KL が発散的に増えて学習が不安定になり、元に戻りにくくなる状態を指します。たとえば生成が同じ表現の繰り返しに陥る、といった形で現れます。GRPO のような RL は、更新のたびに生成と評価を繰り返します。そのため一度でも悪い方向へずれ始めると、その偏りが次の生成に乗り、さらにずれる、という悪循環に陥ることがあります。細部に立ち入らずに言えば、生成と学習をつなぐループのどこかに小さな偏りが入り続けると、それが増幅して学習全体を壊しうる、ということです。

なお、生成と学習を別々の GPU で動かす分離構成や、その通信の詳細は別記事の [分散 RL の通信](https://zenn.dev/tosshi/articles/1f6589ff93dca7) にまとめています。本記事はその偏りの発生源のひとつである数値ミスマッチだけに絞ります。

# mis_kl とは何か

RL ポストトレーニングでは、応答を生成する推論エンジンと、重みを更新する学習エンジンの 2 つが動きます。miles では生成に SGLang、学習に Megatron を使います。この 2 つのエンジンがやり取りをする境界に、mis_kl は現れます。

![training と rollout の 2 つのエンジンと境界](/images/5fc9e8dc7f2ae3-fig2-engines-boundary.png)

用語を定義します。KL divergence は 2 つの確率分布がどれだけ違うかを測る尺度です。log_probs は、モデルにトークン列を通して各トークンの確率を計算する順伝播、つまり forward の際に、各トークンへ付けられる対数確率が並んだ列です。

![ppo_kl と mis_kl の違い](/images/5fc9e8dc7f2ae3-fig3-ppo-kl-mis-kl.png)

ppo_kl は PPO 由来の名前で、学習エンジンの内部で完結します。同じトークン列を更新前後の重みで forward し、その 2 列の KL divergence を取ったもので、1 回の更新でポリシーがどれだけ動いたかを表します。mis_kl は 2 つのエンジンの境界に現れます。同じトークン列を推論エンジンと学習エンジンでそれぞれ forward し、その 2 列の KL divergence を取ります。重み同期の直後で両エンジンの重みは同じはずですが、計算経路が微妙に違うためギャップが生じます。同じ重み、同じトークン、同じ時点で、エンジンだけが違う、この差が mis_kl です。

この不一致による不安定化は既知の現象で、対策として、確率の比が勾配へ過大に効くのを防ぐ truncated importance sampling、以下 TIS が知られています。理論面では arXiv の [Beyond Precision (2602.01826)](https://arxiv.org/html/2602.01826v1) が、系列が長いほど誤差が累積しうることを示し、学習率スケジューリングを対策として提案しました。KV キャッシュを少ないビット数で表す量子化が出力分布をどう乱すかは、[KIVI (2402.02750)](https://arxiv.org/abs/2402.02750) が背景を与えます。

# miles での mis_kl の測り方

推論エンジンの SGLang が生成中にトークンごとの log-probability を記録し、そのトークン列とともに Ray 経由で学習プロセスへ送ります。学習エンジンの Megatron が同じトークンを再度 forward し、両者の差から k3 推定量、つまり KL を安定に見積もる推定式で mis_kl を求め、毎ステップ TensorBoard へ記録します。

![miles における mis_kl の計測経路](/images/5fc9e8dc7f2ae3-fig4-mis-kl-pipeline.png)

設定は 2 つだけです。学習側で計測を有効にし、SGLang 側で KV キャッシュの精度を指定します。ここを 8 ビットの浮動小数点である fp8 にすると、16 ビットの bf16 より数値が粗くなり、mis_kl が増幅されてはっきり観測できました。

# 実測: KV 精度と学習率の 2x2

KV キャッシュの精度と学習率を交差させて測りました。増幅と崩壊を分けて見るのがポイントです。

![KV 精度と学習率の 2x2 実験](/images/5fc9e8dc7f2ae3-fig5-2x2-kv-lr.png)

bf16 では学習率によらず mis_kl は 0.0006 前後で安定します。fp8 にすると mis_kl は明確に上がりますが、学習率が低い場合は勾配の大きさである grad_norm が落ち着いたままで崩壊しません。fp8 かつ学習率が高い場合にだけ、mis_kl も grad_norm も一気に跳ね上がります。この実験の範囲では、増幅そのものは学習率に無関係で、それが崩壊に至るかどうかは、オプティマイザが重みをどれだけ速く動かすかに依存しました。

# 何が効いて何が効かないか

増幅の主因を切り分けました。今回の範囲では、増幅を引き起こすのは KV キャッシュの量子化であり、他の推論最適化である CUDA グラフや triton のアテンションバックエンドは効きませんでした。効果は 3 点の範囲で、数値の細かさを決める仮数部のビット数に対して単調でした。fp8 の 2 形式では e4m3 で約 12 倍、e5m2 で約 45 倍です。

![何が増幅し何が影響しないかの切り分け](/images/5fc9e8dc7f2ae3-fig6-attribution.png)

何が効かないかも示しました。少なくとも H100 と H200 ではハードウェア依存はなく、少なくとも今回比較した 2 系統ではフレームワーク依存もなく、3 つの乱数シードで同じ方向を確認しました。少なくともこの範囲では、特定構成のクセではなく構造的な要因が示唆されます。一方で今回試せていないものもあります。B300 のような別世代のハードウェア、rollout エンジンに vLLM を使える verl、MoE やより大規模なモデル、そして重みの量子化は今後の課題です。

# TIS が暴走を食い止める

崩壊時と対策時の mis_kl を、30 ステップ分そのまま並べます。

![mis_kl の暴走と TIS による平坦化](/images/5fc9e8dc7f2ae3-fig7-collapse-vs-tis.png)

対策なしの赤い曲線は、0.032 から始まり、ステップ 29 でおよそ千倍の 31.8 まで暴走します。log 軸でほぼ直線、つまり指数的な増大です。ミスマッチが勾配をバイアスし、偏った更新がポリシーをずらし、それが次のステップのミスマッチをさらに広げる、というステップ間の正のフィードバックが働いていると考えられます。この暴走はステップをまたぐ現象であり、系列長に関する理論上の上界とは別の層の話です。青い曲線は TIS を入れた場合で、2 つのエンジンが同じトークンに付けた確率の比、つまり重要度比に 2.0 の上限をかけます。その結果 mis_kl の暴走が抑えられ、ピークでも 0.15 程度、最終的に 0.07 付近に留まります。上限がフィードバックループを断ち切ったように見えます。miles はもともと TIS を持っているので、設定ファイルで上限値などを指定すれば有効になります。

# まとめ

RL ポストトレーニングでは、生成する推論エンジンと更新する学習エンジンの間に数値ミスマッチがあり、mis_kl は構造的で、条件がそろうと積み上がって学習を静かに崩壊させます。今回この増幅の主因が KV キャッシュの量子化であり、仮数部のビット数に対して単調であることを実測で示しました。この範囲では、増幅そのものは学習率に無関係で、崩壊するのは学習率も高いときだけでした。対策としては TIS が暴走する重要度比をキャップします。なお今回振ったのは KV キャッシュの精度だけで重みの精度は未検証、計測も 30 ステップと小規模モデルの範囲です。低精度化の副作用は学習の安定性まで波及しうる、というのが本記事の教訓です。
