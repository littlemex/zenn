# はじめに

RL ポストトレーニング、つまり学習済みモデルを強化学習でさらに調整する工程では、通信の速さやネットワーク構成に目が行きがちです。しかし少なくとも今回のケースで学習を静かに壊しかけたのは、ネットワークの外側にある別の要因でした。生成を担う推論エンジンと、重みを更新する学習エンジンが、同じ重みを持っていても同じトークンにわずかに違う数値を出すことがあります。同じ重みなら同じ確率を出すはず、という前提が崩れるこのズレを、本記事では後述するフレームワーク slime に倣い mis_kl と呼びます。条件がそろうと mis_kl は積み上がり、学習を崩壊させます。

以下では GRPO(Group Relative Policy Optimization)を例に、mis_kl がどこで生まれ、何が増幅し、どう抑えるのかを実測とともに整理します。図が説明の中心なので本文は短くします。実測は miles で行いました。miles は後述する slime のフォークで、GRPO のテストケースを [awsome-distributed-ai の PR #1225](https://github.com/awslabs/awsome-distributed-ai/pull/1225) として追加中です。執筆時点では未マージです。

# GRPO の基本ループ

まず土台の GRPO を確認します。学習対象のモデルをポリシーと呼び、GPU 上でプロンプトから行動を生成します。生成された行動は CPU 上の環境で評価され、1 回の試行ごとに 1 つの報酬が返ります。

![GRPO の基本ループ](/images/5fc9e8dc7f2ae3-fig1-grpo-loop.png)

GRPO の特徴は、PPO などが必要とする価値推定用の補助モデル、いわゆる critic を使わない点です。同じプロンプトから複数の試行を走らせ、各報酬をグループの平均と比べ、平均より良ければ強化し悪ければ抑制して、重みを更新します。タスクがツール利用でもコーディングでも数学でも、GPU が生成し CPU が評価する構造は同じです。

# slime の分離構成と境界

この概念図を、実際のフレームワーク slime に当てはめます。slime は生成側に推論サーバの SGLang、学習側に学習フレームワークの Megatron、全体統括に分散実行基盤の Ray を組み合わせます。

![slime の disaggregated なロールアウトと学習](/images/5fc9e8dc7f2ae3-fig2-slime-disaggregated.png)

この図は生成(ロールアウト)と学習を別々の GPU プールで動かす分離(disaggregated)構成です。ポイントは 2 つあります。生成中に過去トークンの計算結果を保持する KV キャッシュはロールアウト側から出ないこと、そして学習側がロールアウト側へ状態を返す経路は重み同期だけであることです。生成されたトークン列(トラジェクトリ)と重み同期という 2 本の矢印が両エンジンの唯一の情報交換で、mis_kl はこの境界に現れます。

# ネットワークだけの問題ではない

スケールで動かすと、コストの内訳は直感と少し違います。下の実測は miles の 4B モデルを H200 2 枚で回したもので、1 ステップは 119.2 秒でした。

![ネットワークの外側にあるコストと境界](/images/5fc9e8dc7f2ae3-fig3-beyond-network.png)

生成が 63 パーセント(74.8 秒)を占め、ネットワーク経由の重み同期はわずか 0.5 パーセント(0.57 秒)です。少なくともこの構成では、ネットワークは支配的なコストではありませんでした。学習側は起動時に並列度を決める固定トポロジー、ロールアウト側は GPU と CPU を独立に増減できる弾性プールで、スケールの仕方が違います。そして図の上部にある境界での数値ミスマッチが、崩壊の入り口になります。

# mis_kl とは何か

崩壊の正体に入る前に、いくつかの用語を定義します。KL divergence は 2 つの確率分布がどれだけ違うかを測る尺度です。log_probs は、モデルにトークン列を通して各トークンの確率を計算する順伝播、つまり forward の際に、各トークンへ付けられる対数確率が並んだ列です。

![ppo_kl と mis_kl の違い](/images/5fc9e8dc7f2ae3-fig4-ppo-kl-mis-kl.png)

ppo_kl は PPO 由来の名前で、学習エンジンの内部で完結します。同じトークン列を更新前後の重みで forward し、その 2 列の KL divergence を取ったもので、1 回の更新でポリシーがどれだけ動いたかを表します。mis_kl は 2 つのエンジンの境界に現れます。同じトークン列をロールアウトエンジンと学習エンジンでそれぞれ forward し、その 2 列の KL divergence を取ります。重み同期の直後で両エンジンの重みは同じはずですが、計算経路が微妙に違うためギャップが生じます。同じ重み、同じトークン、同じ時点で、エンジンだけが違う、この差が mis_kl です。

# 先行研究と本記事の位置づけ

mis_kl による不安定化は既知の現象です。slime の開発チームは分離型の GRPO を実行した際にポリシーの静かな崩壊を観測し、原因を SGLang と Megatron の数値的な不一致に突き止めました。対策として、確率の比が勾配へ過大に効くのを防ぐ truncated importance sampling、以下 TIS を実装しています。arXiv の [Beyond Precision (2602.01826)](https://arxiv.org/html/2602.01826v1) はこの不一致を理論として定式化し、系列が長いほど誤差が累積しうることを示して、学習率スケジューリングを対策として提案しました。KV キャッシュを少ないビット数で表す量子化が出力分布をどう乱すかは、[KIVI (2402.02750)](https://arxiv.org/abs/2402.02750) が背景を与えます。

本記事が加えるのは因果の帰属です。今回切り分けた範囲では、増幅を引き起こすのは KV キャッシュの量子化であり、他の推論最適化である CUDA グラフや triton のアテンションバックエンドは効きませんでした。効果は 3 点の範囲で、数値の細かさを決める仮数部のビット数に対して単調でした。fp8 の 2 形式では e4m3 で約 12 倍、e5m2 で約 45 倍です。何が効かないかも示しました。少なくとも H100 と H200 ではハードウェア依存はなく、少なくとも miles と slime ではフレームワーク依存もなく、3 つの乱数シードで同じ方向を確認しました。少なくともこの範囲では、特定構成のクセではなく構造的な要因が示唆されます。

# miles での mis_kl の測り方

ロールアウトエンジンの SGLang が生成中にトークンごとの log-probability を記録し、そのトークン列とともに Ray 経由で学習プロセスへ送ります。学習エンジンの Megatron が同じトークンを再度 forward し、両者の差から k3 推定量、つまり KL を安定に見積もる推定式で mis_kl を求め、毎ステップ TensorBoard へ記録します。

![miles における mis_kl の計測経路](/images/5fc9e8dc7f2ae3-fig5-mis-kl-pipeline.png)

設定は 2 つだけです。学習側で計測を有効にし、SGLang 側で KV キャッシュの精度を指定します。ここを 8 ビットの浮動小数点である fp8 にすると、16 ビットの bf16 より数値が粗くなり、mis_kl が増幅されてはっきり観測できました。

# 実測: KV 精度と学習率の 2x2

KV キャッシュの精度と学習率を交差させて測りました。増幅と崩壊を分けて見るのがポイントです。

![KV 精度と学習率の 2x2 実験](/images/5fc9e8dc7f2ae3-fig6-2x2-kv-lr.png)

bf16 では学習率によらず mis_kl は 0.0006 前後で安定します。fp8 にすると mis_kl は明確に上がりますが、学習率が低い場合は勾配の大きさである grad_norm が落ち着いたままで崩壊しません。fp8 かつ学習率が高い場合にだけ、mis_kl も grad_norm も一気に跳ね上がります。この実験の範囲では、増幅そのものは学習率に無関係で、それが崩壊に至るかどうかは、オプティマイザが重みをどれだけ速く動かすかに依存しました。

# TIS が暴走を食い止める

崩壊時と対策時の mis_kl を、30 ステップ分そのまま並べます。

![mis_kl の暴走と TIS による平坦化](/images/5fc9e8dc7f2ae3-fig7-collapse-vs-tis.png)

対策なしの赤い曲線は、0.032 から始まり、ステップ 29 でおよそ千倍の 31.8 まで暴走します。log 軸でほぼ直線、つまり指数的な増大です。ミスマッチが勾配をバイアスし、偏った更新がポリシーをずらし、それが次のステップのミスマッチをさらに広げる、というステップ間の正のフィードバックが働いていると考えられます。この暴走はステップをまたぐ現象であり、系列長に関する理論上の上界とは別の層の話です。青い曲線は TIS を入れた場合で、2 つのエンジンが同じトークンに付けた確率の比、つまり重要度比に 2.0 の上限をかけると、mis_kl はピークでも 0.15 程度、最終的に 0.07 付近に留まります。上限がフィードバックループを断ち切ったように見えます。miles はもともと TIS を持っているので、設定ファイルで上限値などを指定すれば有効になります。

# まとめ

RL ポストトレーニングは、弾性的なロールアウトプールと固定の学習トポロジーという性質の違う 2 つを融合するため、インフラを立てること自体が難しい構成です。その上で training と inference のミスマッチがあり、mis_kl は構造的で、条件がそろうと積み上がって学習を静かに壊します。今回この増幅の主因が KV キャッシュの量子化であり、仮数部のビット数に対して単調であることを実測で示しました。この範囲では、増幅そのものは学習率に無関係で、崩壊するのは学習率も高いときだけでした。対策としては TIS が暴走する重要度比をキャップします。なお今回振ったのは KV キャッシュの精度だけで重みの精度は未検証、計測も 30 ステップと小規模モデルの範囲です。低精度化の副作用は学習の安定性まで波及しうる、というのが本記事の教訓です。
